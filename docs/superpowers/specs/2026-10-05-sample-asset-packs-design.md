# 샘플 8개 에셋 팩 설계 (B 단계)

날짜: 2026-10-05
상태: 대화에서 팩 구성, 샘플 쪽 프롬프트 셋, 만드는 방법 승인(2026-10-05). 시범 실행은 하지 않는다(사용자 결정).
앞 단계: `2026-10-05-tutorial-prompts-home-and-cost-design.md`(A 단계, 이름·시간과 비용·구독 표시). 그 설계의 2절 B 행과 10절 메모를 이 문서가 대신한다.

## 1. 목표와 성공 기준

샘플 8개(고루, 울림, 하루공부, AFTERGLOW, 핏슬롯, 제철상자, PACECREW, Uptrail)마다 에셋 팩을 둔다. 독자는 팩으로 두 가지를 한다.

- **똑같이 만들기**: AI 그림을 그리지 않고 사이트의 샘플과 같은 화면을 만든다. 이름만 바꿔도 된다.
- **나만의 서비스 만들기**: 팩을 바탕으로 이름, 색, 페이지, 주제를 바꾼다. 맞지 않는 그림만 같은 화풍으로 다시 그린다.

성공 기준:
- 팩 하나만 보고 에이전트가 모든 페이지를 만들 수 있다. 팩 밖에서 찾을 것이 없다.
- 이름만 바꿀 때 그림을 다시 그리지 않는다. 그림에는 글자, 숫자, 로고가 없다.
- 커스텀할 때 무엇을 바꾸면 무엇을 다시 하는지 팩 안의 표로 알 수 있다.
- 샘플 쪽 시간과 비용, 구독 표시, 사이트 값이 "에셋 팩으로" 값으로 바뀐다.
- A 단계와 함께 한 번에 공개한다.

## 2. 그림 사정 (2026-10-05 확인)

- 8개 합계 169장이다: 고루 5, 울림 41, 하루공부 3, AFTERGLOW 22, 핏슬롯 18, 제철상자 32, PACECREW 46, Uptrail 2.
- 7개 샘플의 147장은 그린 프롬프트가 그림 옆 `.webp.json`에 남아 있고, 모두 "글자, 숫자, 로고 없이"를 넣어 그렸다. 스타일 기준 그림(`refs`)도 기록돼 있다.
- AFTERGLOW 22장은 그림 옆 기록이 없다. 팩을 만들 때 그림을 보고 프롬프트를 새로 적고(`"recorded": false`로 표시), 글자가 든 그림이 있으면 그 장만 다시 그린다. (2026-10-06 팩 라운드에서 `.impeccable/plates/`에 22장의 생성 기록이 남은 것을 찾아 기록 프롬프트를 그대로 썼다. 글자 든 그림은 없어 다시 그린 그림도 없다.)
- 우리가 AI로 그린 그림과 우리 사이트 스크린샷이라 배포할 수 있다. Refero 원본이나 다른 서비스 화면은 넣지 않는다.

## 3. 팩 위치와 구성

위치는 `tutorials/samples/pack/<샘플>/`이다. 사이트 동기화(`sync-tutorials.mjs`)는 `<튜토리얼>/pack/…`을 쪽으로 만들지 않고 GitHub 링크용 목록에만 남기므로, 이 위치는 지금 규칙에 그대로 맞는다(`samples/pack/goru/screens.md`).

저장소에는 글과 JSON만 둔다. 그림과 스크린샷은 팩 릴리스 zip으로 올린다.

| 파일 | 내용 | 똑같이 | 커스텀 |
|---|---|---|---|
| `README.md` | 에이전트용 쓰는 법: 두 방식의 순서, 팩은 고치지 않기, 이름 바꾸기 규칙, zip 받기와 sha256 확인, 그림 놓을 자리 | 따른다 | 따른다 |
| `site.json` | 서비스 이름, 첫 화면 문구, 말투, 샘플 주소 | 그대로(이름만 바꿀 수 있음) | 바꾼다 |
| `screens.md` | 사이트맵, 공통 머리줄과 푸터, 페이지별 배치·상태·동작, 계산 규칙(예: 고루의 최소 송금). 샘플의 브리프(`docs/briefs/`)와 실제 화면에서 옮긴다 | 정본 | 페이지를 빼거나 더하는 기준 |
| `DESIGN.md` | 샘플이 마지막에 쓴 디자인 문서(색, 서체, 간격, 컴포넌트)를 실제 코드의 토큰(`index.css` 등)과 맞춘 것. 울림은 옛 Sequel 판, 제철상자는 본문이 잘림, PACECREW는 원문 빨강이 남아 있어(2026-10-02 조사) 코드 값으로 고친다 | 그대로 | 색이나 서체만 바꿀 수 있음 |
| `data/*.json` | 화면에 나오는 예시 데이터. 샘플 코드(`data.ts` 등)에서 JSON으로 옮긴다 | 그대로 | 주제에 맞게 바꾼다 |
| `images.json` | 릴리스 태그, 주소, sha256, 크기, zip 안 파일 목록(Nextflix 팩과 같은 꼴) | 받는다 | 받는다 |
| `prompts.json` | 그림마다 `file`, 쓰는 곳(`where`), `prompt`, 스타일 기준 그림(`ref`), 대표 색이 들어갔는지(`brandColor`), 기록에서 왔는지(`recorded`) | 읽지 않는다 | 다시 그릴 그림만 고쳐 쓴다 |
| `CUSTOMIZE.md` | 바꾸는 것별로 다시 할 일을 적은 표(4절) | 읽지 않는다 | 범위를 정한다 |
| `SOURCES.md` | 스타일 출처(Refero 주소), 그림 모델과 날짜, 스크린샷 날짜와 판 | | |

zip(`<샘플>-images.zip`) 안:
- `images/…`: 샘플 앱에서 쓰던 경로 그대로(예: `images/home/hero-plate.webp`)
- `style-ref/…`: 다시 그릴 때 쓰는 스타일 기준 그림
- `shots/<페이지>-1440.webp`, `shots/<페이지>-390.webp`: 페이지마다 전체 길이 스크린샷. 창과 상태 화면(예: 지출 추가 창)도 `screens.md`에 적은 이름으로 찍는다

## 4. `CUSTOMIZE.md` 표 (모든 팩 공통 틀)

| 바꾸는 것 | 다시 할 일 | 그대로 쓰는 것 |
|---|---|---|
| 이름만 | 화면 글자와 문서의 이름 | 그림, 화면, 디자인, 데이터 |
| 첫 화면 문구, 말투 | 문구 | 나머지 전부 |
| 대표 색 | `DESIGN.md` 색 값, `prompts.json`에서 `brandColor: true`인 그림만 색을 바꿔 다시 그림 | 나머지 그림, 화면, 데이터 |
| 서체 | `DESIGN.md` 서체 | 나머지 전부 |
| 페이지 빼기 | 사이트맵, 메뉴, 그 페이지로 가는 링크 | 남은 페이지 전부 |
| 페이지 더하기 | 그 페이지 화면(`DESIGN.md`와 가까운 페이지 배치를 따름), 필요한 그림만 새로 | 기존 페이지 |
| 주제(예: 생활비 정산 → 동아리 회비 정산) | 이름, 문구, 데이터, 주제가 보이는 그림(같은 화풍으로) | 화면 구성, 디자인 |

샘플마다 표 아래에 그 샘플의 그림 목록을 쓰는 곳별로 두고, 대표 색이 들어간 그림을 표시한다. 그림을 그릴 수 없는 환경(이미지 API 키도 ChatGPT 로그인 Codex도 없음)이면 원래 그림을 그대로 쓰고 보고에 적는다.

## 5. 샘플 쪽 구성 (`tutorials/samples/<샘플>.md` 8개)

프롬프트를 셋으로 정리한다. 순서:

1. 소개, 첫 화면 그림, 링크, 요약 표(그대로)
2. **샘플과 똑같이 만들기** (새로)
3. **에셋 팩으로 나만의 서비스 만들기** (새로, "비슷하게 만들고 싶을 때"를 대신한다)
4. **이 컨셉으로 처음부터 만들기** (지금 "이 컨셉으로 만들어 보기"의 이름만 바꾼다. 팩 없이)
5. 시간과 비용(6절)
6. 실제로 거친 과정, 실제 서비스로 만들 때(그대로)

"비슷하게 만들고 싶을 때"는 지운다. 그 안의 Refero 주소, 서체, 홈 강조점은 팩의 `DESIGN.md`와 `screens.md`에 이미 있다. `refine.md`의 고루 예는 팩 없이 처음부터 정해 보내는 예로 남긴다.

### 5.1 똑같이 만들기 프롬프트 (고루 예)

```prompt
https://github.com/roadkwonai/bts-starter-kit 을 이 폴더에 받고, 그 안의 AGENTS.md대로 화면만 만들 프로젝트를 bts-starter-kit 옆에 [goru] 폴더로 만들어줘.
DB는 쓰지 않아. 없는 준비물은 설치해줘.
옆 폴더 bts-starter-kit의 tutorials/samples/pack/goru 에셋 팩대로 고루 샘플과 똑같은 서비스를 만들 거야. 이름은 [고루].
팩의 README.md 순서대로 하고, 팩은 고치지 마. 이름을 바꿨으면 팩의 이름 대신 내가 정한 이름을 써.
디자인, 화면 구성, 그림은 팩에 있는 것을 써. 스타일 추천, 시안, 새 그림은 만들지 마.
모든 페이지를 팩의 스크린샷과 같게 만들고, 다 만들면 HTML 파일로 내보내줘.
```

### 5.2 나만의 서비스 프롬프트 (고루 예)

```prompt
https://github.com/roadkwonai/bts-starter-kit 을 이 폴더에 받고, 그 안의 AGENTS.md대로 화면만 만들 프로젝트를 bts-starter-kit 옆에 [my-service] 폴더로 만들어줘.
DB는 쓰지 않아. 없는 준비물은 설치해줘.
옆 폴더 bts-starter-kit의 tutorials/samples/pack/goru 에셋 팩을 바탕으로 나만의 서비스를 만들 거야. 이름은 [우리 동아리 회비].
바꿀 것: [주제는 동아리 회비 정산, 대표 색은 짙은 파랑]
팩의 README.md와 CUSTOMIZE.md를 보고, 바꾸는 것에 맞춰 다시 할 일만 해줘. 다시 그릴 그림은 팩의 prompts.json을 고쳐 같은 화풍으로 그려줘.
팩은 고치지 말고, 바꾸지 않는 것은 팩대로 해. 다 만들면 HTML 파일로 내보내줘.
```

`[ ]` 칸 아래에 바꿀 것의 예를 몇 줄 둔다(이름만, 색만, 페이지 빼기, 주제 바꾸기). 프롬프트 블록 안에는 숫자 값을 넣지 않는다.

### 5.3 프롬프트가 바꾸는 흐름

- 두 프롬프트 모두 "작업 폴더에서 시작했을 때"(AGENTS.md) 흐름을 탄다. 첫 요청이 새 프로젝트의 `docs/first-request.md`에 남고, 새 폴더에서 연 세션이 이어서 만든다. 팩 경로는 새 폴더에서 본 상대 경로(`옆 폴더 bts-starter-kit의 …`)로 쓴다.
- 템플릿(`bts-ui`)의 디자인 흐름(스타일 추천, 시안, AI 그림)은 프롬프트와 팩 `README.md`가 막는다. 템플릿은 바꾸지 않는다.

## 6. 시간과 비용

A 단계 설계 5절 블록 모양과 5.2절 토큰 표시를 따른다. 단가는 A 단계 6.2절, 요약값은 6.3절 "자료 팩으로" 열, 구독 표시는 7절 "B 단계부터" 열을 쓴다(이름은 "에셋 팩으로"로 읽는다).

- 요약(늘 보임): "똑같이 만들기"의 최소 시간과 토큰, 구독 표시 한 줄, 안내 한 줄.
- 단계별 예상(접힘): 열을 "에셋 팩으로 똑같이"와 "처음부터(내 컨셉으로)" 둘로 한다. 같은 행에 두 값을 둔다. 팩 쪽 "화면 구성"은 "팩의 스크린샷", "그림"은 "팩에서 받기"다.
- 표 아래 한 줄로 커스텀을 더하는 법을 적는다: "나만의 서비스로 바꾸면 다시 그리는 그림 장당 약 30초, 약 1.7만 토큰이 더 들고, 주제를 바꾸면 기획 5분이 더 들어요." 숫자는 A 단계 6.2절 단가(그림 장당 0.3달러, 기획 차이 1.5달러)에서 5.2절 비율로 바꾼다.
- "만든 사람이 실제로 쓴 값"은 그대로 둔다.
- 팩을 만드는 데 든 값은 세지 않는다(Nextflix처럼 "원래 서비스 리서치, 에셋 팩 만들기: 세지 않음").

## 7. 다른 교재 글

- `tutorials/samples/README.md`: "샘플로 만들어 보기"에 세 방식을 한 줄씩. "샘플 쪽에는 …"의 "비슷하게 만들고 싶을 때의 자세한 요청"을 "똑같이 만들기와 에셋 팩으로 나만의 서비스 만들기 프롬프트"로. 시간과 비용 절의 값은 6절 기준으로.
- `tutorials/reference/glossary.md`: "에셋 팩" 설명을 샘플 팩까지 담게 고친다. 예: "Asset Pack. 만들 서비스의 화면 구성, 디자인, 예시 데이터, 그림을 묶어 둔 폴더. 에이전트는 이것만 보고 만들어요".
- `tutorials/reference/costs-and-keys.md`: 이미지 요금 안내에 "에셋 팩으로 똑같이 만들면 그림을 그리지 않아요" 한 줄.
- 루트 `README.md`: 튜토리얼 절에 샘플 에셋 팩 한 줄. `AGENTS.md`의 팩 릴리스 규칙은 이미 `<slug>`로 일반화돼 있어 그대로다.
- 교재 설계(`2026-10-01-bts-starter-kit-tutorials-design.md`)의 샘플 쪽 구성에 5절 순서를 적는다.

## 9. 팩을 만드는 방법

1. **공통 지시문과 검사 스크립트를 먼저 만든다.** 지시문은 `bts-samples/prompts/pack-<샘플>.txt`, 검사는 `bts-samples/tools/check-pack.mjs`(저장소에 넣지 않는다). 검사 항목:
   - 3절 파일이 모두 있다. `site.json`, `images.json`, `prompts.json`, `data/*.json`이 JSON으로 읽힌다.
   - `prompts.json`의 그림 수가 2절 수와 같고 `images.json` 파일 목록과 일치한다.
   - `screens.md` 사이트맵의 페이지마다 `shots/<페이지>-1440.webp`와 `-390.webp`가 zip에 있다.
   - zip의 sha256과 크기가 `images.json`과 같다.
   - 글과 JSON에 비밀 값, 로컬 절대 경로, Refero 원본 그림이 없다.
2. **샘플마다 에이전트 라운드를 하나씩 돌린다**(`tools/run.sh`, 샘플 작업공간에서). 라운드는 자기 브리프, `DESIGN.md`, 데이터 코드, 그림 기록, 공개된 샘플 정적 HTML에서 팩과 zip을 `bts-samples/packs/<샘플>/`에 만들고 검사를 통과시킨다. 스크린샷은 공개판과 같은 정적 HTML을 로컬에서 띄워 찍는다.
3. **고루를 먼저 만들고 내가 검토해 지시문을 고친 뒤** 나머지 7개를 돌린다. 동시에 돌리는 수는 한도를 보며 정한다.
4. 팩 글을 `tutorials/samples/pack/<샘플>/`로 옮기고, 샘플 쪽과 다른 교재 글(5~7절)을 고친다.
5. 새 교재 글은 korean-skills(humanizer → style-guide → grammar-checker)로 검수한다. 팩 글도 사람이 읽으므로 같이 검수한다.
6. 사이트 라운드(8절).

## 10. 검증

- 팩 8개가 `check-pack.mjs`를 통과한다.
- 교재 링크·프롬프트 검사와 사이트 `tutorials:check`가 통과한다. 팩 링크(`samples/pack/…`)가 GitHub 주소로 이어진다.
- 숫자: 샘플 쪽, 사이트 홈, 카드, 상세의 값이 A 단계 6.3절·7절 "에셋 팩으로" 열과 같다.
- 사이트: 빌드, 내보내기, 링크·버튼 전수 검사, axe, 폭 검사, 콘솔 오류. 증거는 `tasks/evidence/<라운드>`.
- 시범 실행(처음 보는 에이전트가 팩으로 실제로 만들어 보기)은 하지 않는다. 그래서 팩 `README.md`의 순서와 프롬프트 문장이 유일한 안전장치다. 공개 뒤 독자 보고나 다음 기회에 실제로 돌려 보고 고친다.

## 11. 공개 순서 (사용자 확인 뒤에만)

1. `main`에 커밋한다(팩 글, 교재, 설계).
2. `node scripts/release.mjs`로 다음 버전(커밋 접두어가 정한다)을 만들고 노트를 korean-skills로 검수한 뒤 `--publish`로 push한다.
3. 팩 릴리스 8개를 올린다: `gh release create pack-<샘플>-1 <샘플>-images.zip --target main --latest=false --title "<샘플> 에셋 팩 그림 1" --notes "<무엇이 들었나>"`. 올린 뒤 받은 zip의 sha256이 `images.json`과 같은지 확인한다.
4. 사이트 작업공간에 커밋하고 `tools/publish-root.sh`로 gh-pages에 올려 push한다. 공개 주소에서 홈, 샘플 상세, 샘플 쪽, 팩 링크, `og.png`를 확인한다.
