# 프리셋 디자인 설정과 미리보기 팔레트

## 요청과 성공 기준

프리셋을 만들기 전에 제목·본문 서체와 색상 조합을 비교하고, 고른 설정으로 제작 프롬프트를 복사한다. 앞으로 프로킷 사이트에 싣는 모든 프리셋은 시스템·라이트·다크 모드와 한국어·영어를 기본 제공한다. 화면만 프리셋도 번역문을 한곳에서 고치는 구조를 사용한다.

폰트·색상 선택 팔레트와 설정 견본은 프리셋 제작·프로킷 사이트 미리보기 전용이다. 실전 서비스는 프롬프트에서 정한 폰트·색상만 디자인 토큰에 고정한다. 일반 서비스에 선택 UI·견본·프로킷 미리보기 수신기를 추가하지 않는다. 이는 사용자의 같은 세션 범위 정정으로 확정한 기준이다.

프로킷 사이트의 기존 제작창과 미리보기창을 확장한다. 프리셋 원래 디자인을 유지하는 선택을 제공하고, 프로킷 사이트 자체의 디자인은 바꾸지 않는다. 이미 공개한 프리셋을 모두 번역하거나 팩을 재발행하는 작업은 아래 전환 계획으로 관리한다.

## 현재 구조와 재사용

- 프리셋 메타데이터는 `pro-kit-web/apps/web/src/data/samples.json`이다. 기존 `fonts`, `colors`, `style`을 원래 디자인 표시와 프롬프트에 재사용한다.
- 제작창은 `components/work/sample-tutorial.tsx`, 복사는 `BlockCopy`와 `CopyButton`을 재사용한다. 교재 원문은 pro-kit의 `docs/blocks/`가 정본이므로 사이트 사본을 직접 수정하지 않는다.
- 미리보기는 `components/preview/preview-dialog.tsx`의 실제 iframe을 유지한다. 우측 설정 패널은 데스크톱·모바일 보기와 함께 사용하며, 그림 비교에서는 원본 그림이라는 설명을 표시한다.
- 현재 프리셋에는 공통 번역 사전이 없다. `fitslot`, `studyday`, `olgot`은 라이트 모드 강제 설정도 있어 사이트 UI만으로 전환을 보장할 수 없다.
- 서체 후보는 기존 DESIGN.md의 Pretendard·Wanted Sans·SUIT·Noto 계열·Outfit과 사용자 첨부 자료에서 추린다. 공식 배포처와 라이선스를 확인한 후보만 선택기에 등록한다.

## 선택값과 정본

`PresetDesignOptions`는 `bodyFont`, `headingFont`, `palette`, `theme`, `locale`을 갖는다. 폰트와 팔레트의 `original`은 해당 프리셋 정본을 따른다. `theme`은 `system | light | dark`, `locale`은 `ko | en`이며 초기값은 `system`, `ko`다.

폰트 목록은 이름, 한글 지원, 권장 용도, CSS family, 공식 출처, 라이선스, 자체 호스팅 파일을 가진다. 영문 전용 서체에는 Pretendard 같은 한글 폴백을 함께 지정한다. 무료 다운로드 여부와 웹 배포 허용을 구분한다. 긴 본문에 적합한 서체와 제목용 서체를 화면에서 구분한다.

색상 조합은 원래 디자인과 검증한 조합으로 제공한다. 각 조합은 light/dark의 배경·표면·글자·보조 글자·대표 색·대표 색 위 글자·테두리를 가진다. 성공·경고·오류·차트 의미 색은 별도로 유지한다. 임의 색상 입력과 자동 반전은 이번 범위에 넣지 않는다.

선택기 안의 작은 설정 견본에서 선택한 서체·색상·모드·언어를 비교한다. 견본은 프리셋 원본과 구분해 표시하고, 미지원 프리셋을 바꿨다고 안내하지 않는다. 시스템 모드 견본도 운영체제 설정을 따르며 폰트가 실패하면 원래 서체로 표시한다고 알린다. 실제 비교용 폰트는 파일과 라이선스를 확보한 서체부터 제공하고 조사한 나머지는 카탈로그 문서에 후보로 기록한다.

## 제작 프롬프트

제작창에서 기존 팩 프롬프트를 읽고 설정 부분만 조합한다. 원본 팩 파일과 받기 명령은 그대로 유지한다. 폰트·색상을 바꾸면 원본 스크린샷과 같게 만들라는 지시보다 선택값이 우선한다는 점을 명시한다.

프롬프트에는 제목/본문 서체와 한글 폴백, 팔레트의 양쪽 모드 토큰, 초기 모드·언어, 번역 누락 검사와 정적 HTML 보존을 담는다. 일반 서비스에는 고른 폰트·색상을 고정하고 선택 팔레트·설정 견본·프로킷 미리보기 연결을 넣지 말라고 명시한다. 공식 프리셋 자체를 제작하는 규칙에서만 미리보기 연결을 요구한다. 선택값을 바꾼 뒤 보이는 프롬프트와 복사된 문장이 같아야 한다.

## 미리보기 연결 계약

프로킷은 iframe 내부를 직접 조작하지 않는다. `postMessage`의 `prokit:preview:hello`, `prokit:preview:ready`, `prokit:preview:apply`, `prokit:preview:applied`를 사용한다. 버전은 `1`이다. 메시지는 프리셋 slug와 요청 식별자, 옵션을 가진다.

부모는 실제 iframe의 `contentWindow`와 그 URL의 정확한 origin, slug, 버전을 확인한다. 프리셋은 `window.parent`, 허용한 프로킷 origin 목록, 버전, slug와 모든 옵션을 확인한다. `*` targetOrigin과 수신 문자열의 CSS·HTML 실행을 사용하지 않는다. 허용 목록 밖 메시지는 무시한다.

수신기의 `prepareApply(options)`는 폰트·번역 자료를 비동기로 준비하되 DOM을 바꾸지 않는다. 준비된 동기 적용 함수는 최신 요청과 활성 연결을 확인한 뒤에만 실행한다. 실제 적용과 응답을 연속 실행해 느린 이전 요청이 새 설정을 덮어쓰지 않게 한다.

`ready`는 지원하는 `font`, `palette`, `theme`, `locale`을 알린다. `applied`는 요청 식별자와 실제 적용 옵션, 미지원 목록을 반환한다. 부모는 현재 iframe·origin·slug·버전·요청 식별자와 지원 필드의 옵션값을 모두 대조한 뒤에만 적용 확인을 표시한다. 지원하지 않는 기능은 실제 화면에 적용했다고 표시하지 않는다. 선택값은 제작 프롬프트에 계속 사용할 수 있으며, 현재 프리셋은 지원 여부를 확인하기 전까지 원본으로 보인다.

폰트와 색상 변경은 프리셋 내부의 의미 토큰에 연결한다. 프리셋별 화면·레이아웃·앱 로직은 공통화하지 않는다. 페이지 이동 뒤 다시 연결하고, 데스크톱/모바일 보기를 바꿔도 선택값을 유지한다. iframe 설정은 프로킷 사이트의 테마·언어를 바꾸지 않는다. 부모의 예상 origin은 기존 `sampleUrl()`에서 계산하며 리디렉션으로 origin이 달라지면 적용하지 않는다.

패널은 본문 안에서 데스크톱 우측 열, 모바일 상단 접이식 영역으로 배치한다. `LiveFrame`은 본문이 제공하는 실제 남는 높이와 너비를 측정하고 ResizeObserver로 패널·뷰포트 변경을 반영한다. 패널 안에서는 이전/다음 페이지 방향키 단축키를 실행하지 않는다.

사용자의 후속 요구에 따라 미리보기 높이는 자동을 기본으로 하며 수동 조절도 제공한다. 가로 배율을 유지한 채 남는 세로 공간을 실제 iframe viewport 높이에 사용해 아래 내용을 더 보여준다. 외곽 창의 최대 높이는 제한으로만 사용하고, 회색 빈 영역을 늘리지 않는다. 높이 변경은 iframe을 다시 불러오지 않으며 연결 상태를 초기화하지 않는다. 그림 비교에서는 높이 조절을 사용하지 않는다.

## 신규 프리셋 제작 계약

- DESIGN.md에 양쪽 모드 토큰, 제목/본문/숫자 서체, 한글 폴백, 라이선스, 원본 스타일 출처를 적는다. 기본 모드는 시스템이며 사이트 자체에 모드·언어 선택기를 둔다.
- 서비스 프로젝트는 설치된 국제화 체계가 있으면 재사용한다. 새 체계가 필요하면 라우팅·서버 렌더링·정적 내보내기 요구를 비교해 정한다. 화면만 프로젝트는 `messages/ko`와 `messages/en`의 같은 키를 읽는 작은 사전으로 충분하다. 문구 치환이나 외부 번역 API를 런타임에 사용하지 않는다.
- 제목·본문·탐색·버튼·폼·오류·빈 상태·접근성 이름을 번역한다. 사용자 입력·고유명·콘텐츠 원문은 번역 대상과 구분한다. 날짜·숫자·금액은 Intl로 표시하되 언어 전환으로 환율·통화·시간대를 바꾸지 않는다.
- 언어를 바꿔도 입력, 페이지, 선택 상태를 유지하고 `html.lang`을 갱신한다. 저장이 막힌 브라우저에서도 동작한다. 시스템 테마 변경을 반영하고 초기 깜박임·수화 오류를 검사한다.
- 정적 HTML에도 모드·언어·폰트·색상 전환과 미리보기 수신 기능이 남아야 한다. 프로킷 전용 설정 패널은 부모 사이트에만 있고 독립 프리셋에 프로킷 패널을 넣지 않는다.

## 인수 조건과 테스트 시나리오

1. 정상: 제목·본문 서체, 팔레트, 세 모드, 시작 언어를 고르면 보이는 프롬프트와 복사값에 같은 설정이 들어간다.
2. 기본/초기화: 원래 폰트·색상으로 돌아가고 기본 기능 지시는 남는다. 제작창과 미리보기를 열고 닫아도 다른 프리셋 이름이 섞이지 않는다.
3. 미지원/오류: 응답 없는 기존 iframe, 일부만 지원하는 iframe, 폰트 실패에서 원본과 실제 지원 상태를 구분한다. 거짓 적용 완료를 표시하지 않는다.
4. 경계/보안: 다른 source·origin·slug·버전과 잘못된 옵션/응답 요청은 거부한다. 페이지 쿼리·basePath를 유지한다.
5. 접근성: 모바일에서 가로 넘침 없이 조작하고 키보드만으로 열기·선택·복사·초기화·닫기가 된다. 선택기 화살표가 이전/다음 페이지를 움직이지 않는다.
6. 제작물: 모든 사이트맵 페이지의 ko/en 키 일치, 여섯 모드/언어 조합, 오류·빈 상태, 입력 보존, 정적 HTML에서 전환을 확인한 뒤 지원 기능을 선언한다.

## 전환 순서

1. 사이트 선택·프롬프트 UI와 지원 여부를 확인하는 미리보기 패널, 신규 제작 규칙을 구현한다.
2. 테마 기반이 있는 `slidelab`에서 번역 사전·양쪽 토큰·미리보기 연결을 구현하고 전체 페이지를 검증한다. slidelab 등록은 현재 별도 작업과 충돌하지 않게 한다.
3. 나머지 프리셋은 하드코딩 색상·문구를 조사하고 한 프리셋씩 전환한다. 지원 기능과 검증 결과를 먼저 갱신한다.
4. 변경된 팩 원본·CUSTOMIZE.md·DESIGN.md·번역 자료·폰트 라이선스를 함께 묶고, 팩 재발행·sha256 갱신·Pages/Vercel 배포를 실행한다. 원격 변경은 요청한 세션의 릴리스 절차를 따른다.

## 만들지 않는 것

- 기존 프리셋 전체의 자동 번역·CSS 강제 덮어쓰기: 앱별 의미와 대비를 보장할 수 없어 개별 전환한다.
- 폰트·팔레트 관리 서버, 계정별 저장, 번역 API, 새 상태관리 의존성: 정적 카탈로그와 기존 클라이언트 상태로 충분하다.
- 임의 색상 생성과 이미지·로고 재색칠: 의미 색과 원본 자산을 유지한다. 필요하면 후속 브리프로 정한다.
- 폰트를 전부 첫 화면에 로드하기: 선택한 미리보기 폰트만 로드한다.
