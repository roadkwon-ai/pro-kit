# 프로킷 소개 페이지, 문서(docs), GitHub 스타 설계

날짜: 2026-10-07. 사용자 승인: 1절(스타 버튼·토스트와 접근 방식 A), 2절(docs 목차와 README 관계), 3절(소개·docs 페이지 UI).

## 목적

지금 프로킷 사이트(`https://prokit-web.vercel.app/`, 작업공간 `../pro-kit-samples/ws/portfolio`)의 홈은 프리셋 갤러리다. 프리셋만 보고는 프로킷이 무엇이고 어떻게 일하는지 알기 어렵다. 다음 세 가지를 더한다.

1. GitHub 스타: 헤더 오른쪽 위 스타 수 버튼, 스크롤하면 오른쪽 아래에 마스코트가 잠깐 나와 스타를 부탁하는 토스트.
2. 프로킷 소개 페이지 `/about`: bkit.ai, speckit.org처럼 프로킷의 기술과 흐름을 한 페이지에서 자세히 소개한다. 홈에서 이 페이지로 안내한다.
3. 문서 `/docs`: MoAI-ADK 문서(adk.mo.ai.kr/ko)처럼 기술을 쪽 단위로 설명한다. 마크다운 원본을 pro-kit 저장소 `handbook/`에 먼저 쓰고, 그 내용으로 사이트 페이지를 만든다.

성공 기준
- 처음 온 사람이 홈 → 소개 → 문서 순서로 "무엇이고, 어떻게 일하고, 자세히는 어떻게 동작하나"를 따라갈 수 있다.
- 소개와 문서의 사실은 모두 README, handbook, 템플릿 문서에 근거가 있다. 후기나 없는 수치는 만들지 않는다.
- 비개발자도 각 문서 쪽의 첫 문단("한눈에")까지는 읽을 수 있고, 개발자는 같은 쪽에서 파일·명령·규칙까지 찾는다.

## 1. GitHub 스타 버튼과 스타 토스트

스타 버튼
- 헤더의 "GitHub" 링크를 `GitHub 마크 + ★ <스타 수>` 버튼으로 바꾼다(스타만 있으면 어디로 가는 버튼인지 알기 어렵다. 사용자 지적 2026-10-07). 모바일 메뉴 시트에도 같은 버튼을 둔다. 새 탭으로 저장소를 연다.
- 숫자: 빌드할 때 GitHub API(`GET /repos/roadkwon-ai/pro-kit`의 `stargazers_count`)로 받아 페이지에 넣는다. 브라우저에서는 하루에 한 번만 다시 받는다. 받은 수와 시각을 `localStorage`에 두고, 24시간 안에는 그 값을 쓴다(실패해도 시각을 남겨 24시간 동안 다시 부르지 않는다. 사용자 지적 2026-10-07). 받기가 실패하면(한도, 오프라인) 빌드 때 값을 그대로 보인다. 빌드 때도 실패하면 숫자 없이 `GitHub 마크 + GitHub`.
- 표기: 1,000 미만은 그대로, 이상은 `1.2k`. 접근 이름은 "GitHub에서 스타 주기, 현재 스타 N개".

스타 토스트
- 나오는 때: 홈은 페이지 높이의 약 60%까지 스크롤했을 때, 프리셋 상세(`/work/…`)와 튜토리얼 마지막 쪽은 본문 끝에 닿았을 때. 한 방문(세션)에 한 번.
- 모양: 오른쪽 아래에서 마스코트(hello 포즈, 약 96px)가 아래에서 올라오고 말풍선이 열린다. 문구(후보 5개 중 고름) + "★ 스타 주기"(GitHub로) + 닫기(×).
- 사라짐: 약 8초 뒤 내려가며 사라진다. 마우스를 올리거나 포커스가 있으면 멈춘다. 닫기나 스타 주기를 누르면 30일 동안 다시 나오지 않는다(`localStorage`, 읽기·쓰기 실패해도 동작).
- 접근성: `role="status"`로 알리고 포커스를 옮기지 않는다. 움직임 줄이기면 미끄러짐 없이 나타나고 사라진다. 390 너비에서는 아래 가운데에 작게, 다른 고정 버튼을 가리지 않는다.
- 문구 후보(구현 라운드에서 하나로 정하거나 돌아가며 보인다): "프로킷이 마음에 들었다면 GitHub ★로 응원해 주세요", "만든 결과가 마음에 드셨나요? ★ 하나가 큰 힘이 돼요", "프로킷이 도움이 됐다면 스타로 알려 주세요", "★ 하나면 프로킷이 더 많은 사람에게 닿아요", "응원의 ★를 눌러 주시면 다음 프리셋을 더 빨리 만들게요".

## 2. 문서 원본 `handbook/` (pro-kit 저장소)

위치와 이름
- 원본 `pro-kit/handbook/*.md`. `docs/`는 개발 기록(adr, 설계 기록, 측정 보고서)이라 섞지 않는다.
- 사이트 주소 `/docs`, 메뉴 이름 "문서". 튜토리얼 허브의 "가이드"(비용과 키, 배포하기, 용어, 문제 해결, Windows)와 겹치지 않게 한다.

쪽의 틀(두 층)
```
# 제목
> 한눈에: 쉬운 말 2~3문장. 무엇이고 왜 필요한지
## 개념·흐름   (도식, 표)
## 자세히      (파일, 명령, 규칙)
## 관련 문서
```
- 말투는 튜토리얼과 같은 해요체. "자세히" 절은 코드 식별자와 명령을 그대로 쓴다.
- 도식은 Mermaid로 둔다(GitHub에서도 보인다).

목차(7묶음 30쪽 + 문서 홈). 문서 홈 `handbook/README.md`의 표가 순서의 정본이다.

| 묶음(폴더) | 쪽 | 재료 |
|---|---|---|
| 문서 홈 `README.md` | 핵심 3가지(하네스, 전용 스킬, 디자인부터 배포까지), 묶음 표 | 새로 씀 |
| 1. 시작하기 `start/` | 프로킷이란, 준비물, 빠른 시작: 화면만 만들기, 빠른 시작: 서비스 만들기, 만든 뒤 개발하기 | README 소개, 누구나 전문 개발자처럼, 빠른 시작, 요청하면 이렇게 진행됩니다, 만든 뒤 |
| 2. 핵심 개념 `concepts/` | 하네스 엔지니어링, dev-cycle 라운드, 케이스 A~H와 대조표, 증거와 audit·사용자 확인, 구현 에이전트와 리뷰 에이전트 | 에이전트 하네스, 그냥 AI에게 맡길 때와 다른 점, 요청 하나가 흘러가는 모습, dev-cycle 라운드, 템플릿 `docs/dev-workflow.md` |
| 3. 템플릿 `templates/` | 템플릿 고르기(neon·supabase), 템플릿이 더하는 것, 앱 구조, 설치기와 옵션, 기존 프로젝트에 갱신 반영 | Better-T-Stack이란, 템플릿이 더하는 것, 템플릿 고르기, 아키텍처 앱 구조, 설치기 옵션, AGENTS.md 갱신 절차, 템플릿 README |
| 4. 스킬과 에이전트 `skills/` | prokit 스킬 8개, 공식 스킬과 연결, 선택 스킬 묶음, 설치와 업데이트 구조 | prokit 스킬, 공식 스킬(호출률·활용도), 선택 스킬 묶음, 스킬 설치 구조 |
| 5. 디자인 `design/` | UI/UX 흐름(스타일 추천 1~3위, 브리프), DESIGN.md, 화면만 프로젝트와 HTML 내보내기 | UI/UX 디자인 절, prokit-ui 화면만 프로젝트 절과 references |
| 6. 배포와 릴리스 `deploy/` | Vercel 배포와 되돌리기, GitHub Pages 배포, 버전과 릴리스, 비밀값 지키기 | 배포, 릴리스, prokit-deploy |
| 7. 레퍼런스 `reference/` | 명령 모음, 설치된 프로젝트의 폴더 구조, 검증 결과, 자주 묻는 질문 | 디렉터리 구조, 템플릿 VERIFICATION.md, 템플릿 README 명령 |

중복 규칙
- 비용과 키, Windows, 문제 해결, 용어 풀이는 튜토리얼 "가이드" 쪽으로 링크하고 다시 쓰지 않는다.
- 튜토리얼은 따라 하며 만들기, 문서는 어떻게 동작하나를 맡는다.

README와의 관계
- 1차: handbook을 새로 쓰고 README는 그대로 둔다.
- 2차(문서 페이지가 올라간 뒤): README를 짧은 개요와 handbook 링크로 줄이고, 자세한 설명의 정본을 handbook으로 옮긴다. AGENTS.md의 "템플릿을 바꾸면 README도 맞춘다" 규칙에 handbook을 더한다.

쓰기와 검수
- 쪽마다 사실을 재료 절과 대조하고, 템플릿 파일에서 확인되지 않는 내용은 쓰지 않는다.
- korean-skills(humanizer → style-guide → grammar-checker)로 검수하고, 별도 리뷰 에이전트가 사실 대조와 링크를 본다.

## 3. 사이트 페이지 설계

메뉴와 연결
- 헤더: `프리셋 ▾ · 튜토리얼 · 문서 · 프로킷 소개` + 오른쪽 `GitHub 마크 ★ 스타 수`. 모바일 메뉴 시트도 같은 순서.
- 홈에서 안내: 첫 화면 수치 줄 옆 "프로킷 자세히 보기 →"(`/about`), 워크플로우 절 아래 "dev-cycle과 하네스 자세히 → 문서", 마지막 CTA 절 보조 버튼 "프로킷 소개 보기".

`/about` 프로킷 소개
- 지금 브랜드(DESIGN.md의 paper/ink, Wanted Sans 제목, Pretendard 본문, 마스코트 포즈, 민트 체크·노란 반짝임 포인트)를 따른다. ink 반전 절은 하네스 절 하나.
- 데스크톱에서 헤더 아래 얇은 절 이동 메뉴가 붙어 다닌다: 작동 방식, dev-cycle, 하네스, 스킬, 템플릿.
- 절 순서:
  1. 히어로: 눈썹, 큰 제목, 설명, 시작 프롬프트 한 줄과 복사(탭: 화면만 만들기 | 서비스 개발하기), 버튼 "튜토리얼로 시작하기"·"문서 보기", 수치 줄(GitHub 스타, prokit 스킬 8, 템플릿 2, 프리셋 8), 마스코트.
  2. 이런 걱정, 프로킷이: 걱정(취소선) → 답 카드 6쌍. 답은 README "그냥 AI에게 맡길 때와 다른 점"과 prokit 스킬 표의 "지키게 하는 것"에서만 가져온다.
  3. 시작은 프롬프트 한 줄: 번호 3단계(작업 폴더에서 에이전트 열기, 프롬프트 보내기, 알려 준 한 줄로 새 폴더에서 열기)와 복사되는 코드 블록.
  4. 프로킷은 이렇게 일해요: 홈의 탭 워크플로우 컴포넌트를 그대로 쓴다.
  5. dev-cycle 들여다보기: 01 케이스 판정, 02 대조표, 03 증거와 audit, 04 확인과 마무리. 고른 단계의 터미널 모양 출력 예시를 옆에 보인다(실제 라운드 기록에서 가져옴). 사용자가 눌러 바꾸고 자동 재생은 없다.
  6. 하네스(어두운 절): 가운데 prokit-dev-cycle, 둘레에 규칙 문서, 계층 스킬, 공식 스킬, 구현 에이전트, 리뷰 에이전트, audit. 노드를 고르면 설명이 바뀐다. 같은 내용을 목록으로도 제공한다.
  7. 전용 스킬 8개: 4×2 카드(맡는 일, 지키게 하는 것).
  8. 템플릿 두 가지: neon | supabase 비교.
  9. 디자인부터 배포까지: 스타일 추천, DESIGN.md, HTML 내보내기·배포.
  10. 지원 에이전트: Claude Code | Codex.
  11. 만들어진 것: 프리셋 4장 미리 보기, 검증 수치, 전체 보기 링크.
  12. 릴리스 노트: 최근 `v*` 3개. pro-kit `release/` 노트를 sync해서 읽는다(빌드 때 API를 부르지 않는다).
  13. 마지막 CTA: "프롬프트 한 줄이면 돼요" + 튜토리얼, 문서, ★.
- 움직임은 화면에 들어올 때 살짝 나타나는 정도. reduced-motion이면 없음.

`/docs` 문서 홈
- 눈썹 "PROKIT DOCS", 제목, 설명, 버튼 "시작하기"·"핵심 개념", 마스코트.
- 핵심 3가지 카드, "문서 둘러보기" 묶음 카드(묶음 이름, 한 줄 설명, 쪽 수), 아래에 튜토리얼 안내 띠.

`/docs/<묶음>/<쪽>` 문서 쪽
- 튜토리얼 문서 틀(`components/tutorials/doc-shell.tsx`)을 다시 쓴다. 왼쪽 묶음 사이드바(지금 묶음만 펼침), 이동 경로, 눈썹(묶음 이름), 제목, "한눈에" 상자(fog 바탕, 작은 마스코트), 본문, 이전·다음, "GitHub에서 고치기"(handbook 원본 파일 링크).
- 1280 이상에서 오른쪽 "이 쪽에서" 목차(h2·h3, 스크롤 따라 표시).
- 묶음 첫 쪽은 하위 쪽 카드 목록.
- 모바일은 사이드바를 시트로 열고 오른쪽 목차는 숨긴다.
- Mermaid: 도식이 있는 쪽에서만 mermaid를 지연해서 불러와 브랜드 색으로 그린다. 불러오기 전이나 실패하면 원문을 코드 블록으로 보인다.
- 검색(⌘K)은 1차에서 뺀다. 문서가 40쪽을 넘으면 더한다.

데이터와 검사
- `pnpm handbook:sync`: pro-kit `handbook/`을 `apps/web/content/handbook/`으로 복사(원본은 읽기만, `HANDBOOK_SRC`로 경로 변경 가능). 그림은 `public/images/handbook/`.
- `lib/handbook.ts`: 문서 홈 표로 묶음과 쪽 순서를 정한다. 표에 없는 쪽, 없는 "한눈에", 깨진 내부 링크는 오류.
- `handbook:check`: 위 규칙과 쪽 수를 단언한다. 기존 site-check, widths, axe, clean에 새 경로를 더한다.

## 만드는 순서

1. R27(포트폴리오 dev-cycle 라운드): 스타 버튼과 스타 토스트.
2. handbook 마크다운 30쪽: pro-kit 세션에서 쓴다. 검수와 리뷰를 거쳐 pro-kit에 커밋한다.
3. R28: 문서 페이지(`/docs`, sync, 사이드바, 오른쪽 목차, Mermaid).
4. R29: 소개 페이지(`/about`)와 홈·헤더 연결, release 노트 sync.
5. 2차: README 줄이기와 AGENTS.md 규칙 갱신.

각 라운드는 R26을 닫은 뒤 연다. 사이트 배포(gh-pages)는 라운드마다 사용자 확인 뒤 한다.
