## 1. 목표와 성공 기준

비개발자와 AI 개발 초보자가 bts-starter-kit과 자료 팩만으로 넷플릭스 같은 영상 구독 서비스를 만든다. 원래 서비스를 조사하지 않고, 이름 한 줄만 바꿔 자기 서비스로 만들 수 있다.

- 샘플 사이트를 자료 팩만으로 만들 수 있다(팩 검증).
- 샘플의 모든 링크와 버튼이 동작한다. 404나 "준비 중"이 없다.
- 교재 프롬프트에 색, 크기 같은 값이 없고 자료 팩을 가리킨다.
- 넷플릭스 로고, 브랜드 빨강 `#E50914`, Netflix Sans, 작품 이미지와 문구가 저장소, 팩, 샘플 어디에도 없다.
- 프롬프트가 bts-starter-kit 절차(`AGENTS.md`, `bts-ui`, `bts-dev-cycle`)와 어긋나지 않는다. 끝까지 실행해 확인하지는 않는다(상위 설계 1절).

## 4. 교재 구성 (`tutorials/01-nextflix/`)

### 4.1 첫 쪽 (`README.md`)
무엇을 만드나(샘플 화면), 원래 서비스, 샘플 링크, 장 목록, 시간과 비용, 안내 문구("넷플릭스와 관계없는 연습용 서비스예요. 데이터는 모두 예시예요."), 만든 기록(상위 설계 9절).

맨 위에 "가장 쉬운 방법"을 둔다. 14번 교재 첫 쪽(설계 2026-10-02 2.1절)과 같은 방식이다. 작업 폴더에서 연 에이전트에 프롬프트 하나를 붙여 넣으면 bts-starter-kit 받기, neon 프로젝트 만들기, 자료 팩으로 모든 화면 만들기(1~4장)까지 간다. 기능 장(5장부터)은 그 프로젝트 폴더에서 장별로 이어 간다. 프롬프트의 바꿀 곳은 `[nextflix]`(폴더), `[Nextflix]`(서비스 이름)처럼 괄호로 표시한다.

시간과 비용은 교재를 끝까지 실행하지 않으므로 샘플을 만든 기록(4장까지)만 적는다.

### 5.3 받은 뒤 고칠 것 (`design-notes.md`)
- **기준 화면**: 원문은 로그인 전 랜딩(바탕 `#000`, 버튼 반경 4~8px)이다. 로그인 후 둘러보기 화면으로 고친다. 페이지 바탕 `#141414`, 스크롤한 뒤 헤더 `#000`, 창 정보 영역 `#181818`. 버튼은 알약(주 버튼은 흰 바탕에 검정 글자, 보조 버튼은 회색 반투명에 흰 글자). 반경은 빌보드 24, 카드 12, 창 6. 좌우 여백 48(1024·768은 36, 500 이하는 24), 카드 사이 8. 이미지 비율은 카드 16:9, 포스터 5:7. 랜딩과 로그인도 같은 값으로 맞춰 한 서비스에 두 세대 디자인을 섞지 않는다.
- **브랜드 대체**: 강조색 `#D6203B`(흰 글자 대비 5.09:1, 호버 `#B61B32`, 눌림 `#8F1528`). 서체 Pretendard(SIL OFL. 본문 400, 버튼·소제목 500, 제목 700, 900은 큰 제목만). 로고는 서비스 이름 글자. 아이콘은 lucide. 토큰 이름과 설명에 남은 "Netflix"도 바꾼다.
- **원문 정리**: Google 명세 frontmatter를 본문 표 값으로 만든다. `Similar Brands`, `Quick Start` 절은 지운다. `%` 반경은 옮기지 않는다(`bts-ui` 저장 단계).
- **확인**: 팩을 만들 때 원문을 받아 고친 결과가 `pnpm dlx @google/design.md` lint를 통과하는지 한 번 보고, 날짜와 결과를 `design-notes.md`에 적는다.

### 6.1 `features.md` 규칙
- **프로필(5장)**: 계정당 최대 5개, 이름과 아바타, 메인 프로필은 지울 수 없다, 지우면 그 프로필의 찜·진행·평가가 함께 사라진다. 고른 프로필은 쿠키로 기억하고 요청마다 내 프로필인지 DB로 확인한다. 5개 제한은 DB 제약으로 보장한다.
- **작품(6장)**: 재생 단위는 모두 회차다(영화는 회차 1개). 장르·분위기 태그로 줄을 만든다. 관람 등급은 전체, 7, 12, 15, 19. 4장은 예시 순서, 10장은 최근 7일 재생 기록으로 시리즈·영화를 따로 집계하며 기록이 없으면 예시 순서를 쓴다.
- **검색(7장)**: 제목, 배우, 장르. 입력할 때마다 주소의 `q`가 바뀐다. 결과가 없으면 안내와 추천 검색어. Postgres `pg_trgm` 색인을 쓴다(DB 문자 설정이 `C`면 한글이 잡히지 않는다. Neon 기본값과 로컬 postgres:18은 된다).
- **찜(8장)**: 프로필별 담기·빼기 토글, 최대 2,000개, 최근에 담은 순. 찜에는 프로필 id와 작품 id만 저장한다.
- **평가(9장)**: 3단계(맘에 안 들어요, 좋아요, 최고예요). hover 카드와 상세 창의 버튼 하나를 누르면 세 단계가 펼쳐진다. 같은 단계를 다시 누르면 취소한다(넷플릭스의 취소 방법은 확인하지 못해 우리가 정한 규칙). 좋아요와 최고예요는 "좋아요 표시한 작품" 줄에 모인다.
- **재생과 이어 보기(10장)**: 재생기는 `@videojs/react` 10(판 고정). 위치는 10초마다, 멈출 때, 옮길 때, 끝날 때, 페이지를 나갈 때 저장하고 늦게 온 오래된 저장은 무시한다. 남은 시간이 5% 이하이면(크레딧 시작 시각이 있으면 그 시각부터) 끝난 것으로 보고 시리즈는 다음 회차를 이어 보기에 둔다. 끝남은 서버가 판단한다. "줄에서 제거"가 있다.

### 6.2 `data/` 예시 데이터
| 파일 | 내용 |
|---|---|
| `site.json` | 서비스 이름(`Nextflix`, 이름을 바꾸는 한 값), 안내 문구, 요금제 3개(확인 날짜와 함께), 예시 프로필 4개(메인 포함), 아바타 8개, 알림 예시 |
| `titles.json` | 가상 작품 50개(시리즈 28, 영화 20, 라이브 2). 줄거리, 연도, 관람 등급, 내용 정보, 출연·제작(가상 이름), 장르 2~3개와 분위기 1~2개, 그림 파일 이름, 시즌 1~2개와 회차 3~6개(모두 약 160개). 회차는 모두 `videos.json`의 영상 하나를 가리킨다 |
| `rows.json` | 홈 기본 줄 15개와 클립·라이브 줄(이어 보기, 찜, TOP 10, 지금 뜨는, 새로 올라온, 장르·분위기 10줄)와 시리즈·영화·요즘 대세 줄 구성. 한 줄에 같은 작품을 두 번 넣지 않고, 첫 화면 위 세 줄은 겹치지 않게 한다 |
| `videos.json` | Blender 공개 영화 10편. 재생 주소(PeerTube API `files[].fileUrl` 값과 그 API 주소), 길이, 라이선스, 표기 문구. 음성 언어·자막 목록을 포함하고 영상 파일은 저장소에 넣지 않는다 |
| `games.json`, `clips.json`, `help.json`, `ai-search.json` | 게임 3개, 클립 12개, 도움말 15편, AI 검색 규칙표 |
| `subtitles/*.vtt` | Sintel·Tears of Steel의 공개 자막과 영어 원본에서 번역한 한국어 자막 |

작품명과 배우명은 모두 지어낸 것이고, 실제 작품·인물과 겹치지 않는지 검색으로 확인한다. 한국 서비스처럼 한국 드라마, 로맨스, 스릴러를 앞에 둔다.

### 6.3 이미지 묶음
- `nextflix-images.zip`을 GitHub Release `pack-nextflix-1`에 올린다(상위 설계 3-1절). 샘플과 팩이 같은 그림을 쓴다.
- 138장(webp): 기존 112장과 게임 4장, 라이브 6장, 대표 작품 8편의 대체 카드 16장. 카드는 800×450·90KB 이하, 포스터는 5:7·110KB 이하, 빌보드는 220KB 이하, 아바타는 256×256을 지킨다. 실제 묶음 크기는 `images.json`에 기록한다.
- 작품 제목 로고는 그림 대신 글자로 쓴다. 랜딩의 포스터 콜라주는 포스터를 다시 쓴다. 회차 썸네일은 카드 그림을 다시 쓴다.
- OpenAI 이미지로 만든다. 키는 셸 환경변수 `OPENAI_API_KEY`로만 쓰고 출력이나 파일에 남기지 않는다(상위 설계 8절).

### 6.4 팩에 넣지 않는 것
Refero 원문, 넷플릭스 스크린샷·로고·문구, 실제 작품명과 작품 그림. 이런 참고 자료는 `../bts-samples/research/nextflix/`에만 둔다.

## 7. 샘플 사이트

- 작업공간 `../bts-samples/tutorials/nextflix`(`bts-samples/base` 복사본)에서 자료 팩만 보고 만든다. 리서치 폴더는 읽지 않는다. 팩만으로 안 되는 곳이 나오면 팩을 고친다.
- 4장의 결과와 같다. 사이트맵의 모든 쪽을 예시 데이터로 만들고 기능은 넣지 않는다. 로그인과 가입은 값을 보내지 않고, 찜·평가 버튼은 화면 안에서만 바뀐다.
- 정적 내보내기 제약: Next.js intercepting routes는 내보내기에서 빌드가 실패하므로 상세 창은 쿼리와 클라이언트 컴포넌트(`useSearchParams`와 `Suspense`)로 만든다. `/title/<slug>`, `/watch/<slug>`, `/games/<slug>`, `/help/<slug>`는 `generateStaticParams`로 낸다. 공개 예정 작품과 시작 전 라이브에는 재생 경로를 만들지 않는다. 영상은 Blender 주소에서 바로 재생한다.
- 확인: 링크·버튼 전수 검사, 폭 검사, axe, critique·audit(`../bts-samples/tools/`의 도구), 리서치 06의 3·4절 값과 대조.
- 공개: gh-pages `nextflix/`(`basePath: "/bts-starter-kit/nextflix"`)와 포트폴리오 갤러리의 튜토리얼 샘플.

## 8. 작업 순서

1. 이 문서 승인 → 실행 계획(writing-plans)
2. 자료 팩: `data/` → 이미지 생성과 zip → 배치도 → `screens.md`, `features.md`, `design-notes.md`(원문을 받아 고친 결과 lint) → `SOURCES.md`, `images.json`
3. 교재 첫 쪽과 12장
4. 샘플(팩만으로), 팩 수정
5. 교재 마무리: 샘플 스크린샷(1440, 390), 도식 1~2개
6. 독립 검토(사실·절차), korean-skills 세 스킬
7. 사이트 반영: 허브 카드, 첫 쪽, 장 쪽(`pnpm tutorials:sync`), 갤러리, gh-pages. 팩 릴리스 `pack-nextflix-1`, 루트 `AGENTS.md` "버전과 릴리스"와 README "릴리스"에 팩 릴리스 방법을 더한다. 커밋, push, 릴리스는 요청을 받고 한다

## 9. 확인하지 못한 것과 위험

- 직접 보지 못한 화면: 프로필 고르기, 재생, 어린이 프로필, 시즌 선택 드롭다운. `screens.md`에 [추정]으로 표시하고 프롬프트에 단정해 쓰지 않는다.
- Refero 원문은 다시 추출되거나 내려갈 수 있다. id와 추출일, 대안 주소를 적어 둔다(5.2절).
- 영상 주소는 PeerTube가 다시 인코딩하면 바뀔 수 있다. `videos.json`에 API 주소를 함께 두고 10장 "막히면"에서 다시 받게 한다.
- 이미지 생성의 비용과 시간은 아직 재지 않았다. 독자는 그림을 팩에서 받기만 하므로 독자 비용이 아니다. 팩을 만들 때 재서 리서치 `README.md`에 적는다.
