## 1. 목표와 성공 기준

모아 보기 사이트와 교재가 "무엇을 만들 수 있고, 얼마나 걸리고, 내 요금제로 되는지"를 한눈에 보여 준다.

- 홈 대제목이 "튜토리얼 프롬프트"이고, 그 아래 "컨셉으로 화면 만들기"와 "유명 서비스 클론하기" 두 소제목으로 묶인다.
- 프로젝트마다 최소 시간과 비용, Claude Pro·ChatGPT Plus 가능 여부가 보인다. 펼치면 단계별 예상과 만든 사람이 실제로 쓴 값이 나온다.
- 모든 숫자에 "최소값이고 2~3배까지 늘 수 있다"는 안내가 붙는다.
- 클론 쪽에는 토큰을 많이 쓴다는 경고가 있다.
- bts-starter-kit과 프롬프트를 응용해 다른 서비스도 만들 수 있다는 안내가 한 줄 있다.
- 사이트의 틀과 디자인(색, 서체, 카드 모양, 필터)은 바꾸지 않는다.

"컨셉으로 화면 만들기"는 지금 교재 이름과 같다. 홈 소제목과 교재 이름을 맞춰 독자가 같은 곳으로 이어진다는 것을 알게 한다.

### 3.1 서비스 이름 "프로킷" (2026-10-05 변경, 사용자 결정)

- 사이트 이름은 "프로킷"(영문 ProKit)이다. 같은 이름의 Flutter UI 키트가 있어 화면에서는 한글을 앞에 둔다.
- 부제: "누구나 프롬프트만으로 전문 개발자 수준의 서비스를 만들 수 있어요."
- 홈 h1은 "프로킷"이고 부제를 바로 아래에 크게 둔다. "튜토리얼 프롬프트"는 작은 머리말로 남는다. 위 표의 h1 행보다 이 절이 우선한다.
- 사이트 제목: `프로킷 · 누구나 프롬프트만으로 전문 개발자 수준의 서비스를`, `%s · 프로킷`.
- bts-starter-kit은 이 서비스가 쓰는 도구로 남긴다. 주소 `/bts-starter-kit/`는 바꾸지 않는다.
- 교재와 루트 README의 "튜토리얼 프롬프트 사이트"는 "프로킷 사이트"로 바꾼다.
- 튜토리얼에 딸린 "자료 팩"은 "에셋 팩"(Asset Pack)으로 부른다(사용자 결정 2026-10-05). 폴더 `pack/`와 릴리스 태그 `pack-<slug>-<판>`은 그대로다.

## 4. 홈 구성

위에서 아래 순서다. 글만 바꾸고 틀은 그대로 둔다.

1. **대제목과 소개**
   - h1 "튜토리얼 프롬프트"
   - 소개: "bts-starter-kit과 프롬프트로 만든 서비스예요. 프롬프트와 자료 팩을 그대로 쓰면 같은 서비스를, 내 아이디어를 넣으면 나만의 서비스를 만들어요."
   - 응용 안내 한 줄: "여기 없는 서비스도 bts-starter-kit과 프롬프트를 응용해 만들 수 있어요." 끝에 튜토리얼 허브 링크
2. **컨셉으로 화면 만들기** (h2)
   - 설명: "컨셉 한두 문장으로 모든 페이지의 화면을 만들어 HTML로 내보내요. DB와 로그인 없이 예시 데이터로 화면만 만들어요."
   - 요약 줄: 샘플 범위의 최소 시간과 비용, 구독 표시, "시간과 비용 읽는 법" 링크. A 단계 값은 "내 컨셉으로" 값이다(6.3절): "샘플 하나에 최소 약 1시간 30분~3시간 10분, API 환산 약 35~80달러 · Claude Pro·ChatGPT Plus로 가능"
   - 태그 필터와 카드 8장(그대로). 카드 아랫줄 오른쪽의 "N페이지" 뒤에 최소 시간과 비용을 붙인다. 예: "7페이지 · 약 1시간 30분 · 약 35달러"
   - 가상 이미지 안내 문장(그대로)
3. **유명 서비스 클론하기** (h2)
   - 설명: "유명 서비스를 본뜬 서비스를 자료 팩으로 만들어요. 화면부터 로그인, DB, 검색, 배포까지 실제로 동작하는 서비스를 끝까지 만들어요."
   - 경고 상자(사이트의 기존 주의 상자 모양): "토큰을 많이 써요. 화면까지(1~4장) 최소 약 2시간 25분, API 환산 약 80달러, 끝까지(1~12장) 최소 약 5시간 15분, 약 140달러예요. AI와 진행 상황에 따라 2~3배까지 늘 수 있어요. Claude Pro·ChatGPT Plus로는 5시간 한도에 약 4번 걸려 2~3일에 나눠 만들어요." 끝에 "시간과 비용 읽는 법" 링크
   - 카드(지금 모양 그대로). 부제 "튜토리얼 · {교재 이름}" 뒤에 "12장 · 화면까지 약 2시간 25분"
   - 클론 교재가 늘면 같은 2열로 이어 붙인다
4. **만든 과정, 검증 결과, 맺음**: 그대로. 샘플 8개 이야기다

샘플 상세(`/work/<샘플>`)의 사실 목록에 두 줄을 더한다: "시간과 비용(최소)"과 "구독". 값은 6.3절과 7절 표다.

## 5. 시간과 비용 블록 (모든 튜토리얼 공통)

교재 첫 쪽(샘플은 샘플 쪽)의 "시간과 비용" 절은 이 모양으로 쓴다. 교재 설계 5절에도 같은 규칙을 넣어 앞으로 만들 클론 교재가 따른다.

1. **요약 (늘 보임)**: 이 프롬프트와 자료 팩으로 순조롭게 한 번에 끝날 때의 최소 시간과 비용(API 요금 환산), 그 아래 구독 표시 한 줄(7절), 그 아래 안내 한 줄:
   > 순조롭게 한 번에 끝날 때의 최소값이에요. AI와 진행 상황에 따라 2~3배까지 늘 수 있어요. [자세히](../reference/costs-and-keys.md#시간과-비용-읽는-법)
2. **▸ 단계별 예상 (접힘, `<details>`)**: 단계마다 시간과 비용. 샘플은 "자료 팩으로"와 "내 컨셉으로(팩 없이)" 두 열이다. A 단계에는 팩이 없으므로 "내 컨셉으로" 열만 두고, B 단계에서 "자료 팩으로" 열을 더한다. 클론 교재는 장별이다. 실측과 예상을 칸마다 밝힌다.
3. **▸ 만든 사람이 실제로 쓴 값 (접힘)**: 샘플을 만들 때 실제로 든 시간과 비용. 리서치, 리디자인, 고침 라운드, 범위 넓히기가 들어 있어 독자 값보다 크다는 점을 한 줄로 밝힌다. 세지 않은 것은 "세지 않음"으로 적는다.

비용은 모두 API 요금 환산이다. 정액 요금제는 돈이 더 들지 않고 사용량 한도 안에서 쓴다는 것, 이미지 API 요금(시안, AI 그림)은 따로라는 것을 `costs-and-keys.md`에 적는다.

### 5.1 `costs-and-keys.md`에 더할 절

**"시간과 비용 읽는 법"**: 다음을 적는다.
- 튜토리얼의 값은 프롬프트와 자료 팩으로 순조롭게 한 번에 끝날 때의 최소값이다. 이럴 때 더 든다.
  - **쓰는 AI와 모델**: 공급사(Claude Code, Codex)와 모델마다 토큰 단가와 일하는 방식이 달라 최소값의 1~2배까지 차이 난다.
  - **다시 요청하고 다듬기**: 고쳐 달라고 할 때마다 더 든다. 샘플을 만들 때는 리디자인과 다듬기를 거쳐 최소값의 1.1~3배, 대개 2배쯤 들었다.
  - **오류와 끊김**: 중간에 끊겨 이어 가면 다시 읽고 확인하느라 20%쯤 더 든다(Nextflix 4장 실측).
  - **정액 요금제**: 돈은 더 들지 않지만 한도에 걸리면 기다려서 끝나는 시각이 늦어진다.
- 넉넉히 잡으려면 최소값의 2~3배를 생각한다.
- 비용은 API 요금 환산이고 이미지 API 요금은 따로다.
- 단가의 근거(6.1절)를 짧게 적는다.

**"5시간 한도에 걸리면"**: 다음을 적는다.
- 구독 요금제는 처음 쓰기 시작한 때부터 5시간 동안 쓸 수 있는 양이 정해져 있다.
- 걸렸을 때 순서:
  1. 멈추면 에이전트가 풀리는 시각을 알려 준다. 만든 파일과 진행한 내용은 남는다.
  2. 그 시각까지 기다린다. 길면 4시간 넘게 기다리고, 컴퓨터는 꺼도 된다.
  3. 같은 프로젝트 폴더에서 에이전트를 열고 `하던 작업 이어서 해줘`를 보낸다.
  4. 기다리기 싫으면 사용 크레딧을 켠다. Claude Code는 `/usage-credits`로 켜고 API 요금으로 청구된다. Codex는 크레딧을 산다.
- "5시간 한도에 약 N번 걸려요"는 이 일을 N번 겪는다는 뜻이다. 일하는 시간은 같고 끝나는 시각만 늦어진다.
- 주간 한도도 있다. 샘플 몇 개는 한 주에 충분하지만 Nextflix를 끝까지 만들면 닿을 수 있다. 자주 만들면 Claude Max나 ChatGPT Pro가 편하다.
- 남은 양은 Claude Code의 `/usage`나 Codex의 사용량 화면으로 확인한다.
- 횟수는 한도가 공개되지 않아 실측 비용으로 어림한 값이다(2026-10-05 기준, 7절). Codex는 가벼운 모델로 바꾸면 5시간 한도가 약 3배 늘어난다.

교재의 "막히면" 가운데 "사용량 한도에 걸려 멈췄어요" 항목은 이 절로 링크한다.

### 5.2 토큰 표시 (2026-10-05 변경, 사용자 결정)

독자는 대부분 유료 요금제(구독)로 써서 달러가 와닿지 않는다. 겉에 보이는 값은 토큰으로 쓴다. 6절 단가표와 7절 계산은 달러로 두고, 표시할 때만 바꾼다.

- 메인 값은 **캐시 다시 읽기를 뺀 토큰**(입력, 캐시 쓰기, 출력)이다. 캐시 다시 읽기까지 센 **캐시 포함** 토큰은 괄호에 쓴다. 예: "약 1시간 30분, 약 190만 토큰(캐시 포함 약 9,600만)".
- 비율은 샘플 Opus 기록(약 994달러어치)에서 잰 값이다: 1달러 = 5.5만 토큰, 캐시 포함 275만 토큰. 표시 토큰 = 표시 달러(6.3·6.5절의 반올림 값) × 비율.
- 반올림은 유효숫자 두 자리, 단위는 만과 억이다(5.5만, 190만, 1,700만, 2.2억).
- 접힌 "단계별 예상"과 "만든 사람이 실제로 쓴 값"에는 토큰, 캐시 포함, API 요금 환산(달러)을 함께 쓴다. 단계별 표의 행 달러는 1달러 단위로 쓰고 마지막에 합계 행(배포 빼고)을 둔다.
- 사이트 홈 요약 줄, 카드 아랫줄, 클론 경고, 샘플 상세의 사실 목록도 토큰으로 쓴다. 홈 요약 줄의 구독 표시는 "가능 (5시간 한도에 약 1~2번 걸려요)"와 "5시간 한도란?" 링크다.
- 5시간 한도 한 번은 약 170만 토큰(약 30달러)으로 어림한다.

## 6. 단가표와 숫자 (정본)

교재와 사이트의 숫자는 이 절에서 옮긴다. 단가를 고치면 이 절의 표를 다시 계산하고 교재와 사이트를 함께 고친다. 시간은 5분 단위, 비용은 5달러 단위로 반올림한다(10달러 미만은 1달러 단위).

## 7. 구독 표시

공식 한도는 토큰이나 금액으로 공개되지 않는다. 그래서 실측 비용으로 어림한다.

- 가정: Claude Pro 5시간 창 하나는 API 환산 약 20~40달러, 계산에는 가운데인 30달러를 쓴다.
  - 2025년 사용 보고에서 약 18달러였다.
  - 2026-05-06에 5시간 한도가 2배가 됐다.
  - 2026-09-22 Opus 5.5 출시 때 다시 올랐다.
- ChatGPT Plus(Codex)도 같은 수준으로 본다. 공식 안내의 5시간 메시지 수는 GPT-6 Astra 5~45, GPT-6 Sol 15~150이다.
- 필요한 5시간 창 수 = 최소 비용(반올림해 보여 주는 값) ÷ 30달러를 올림한 값. 한도에 걸리는 횟수 = 창 수 - 1.
- 표시: 창 1개면 "가능 (5시간 한도 안)", 2개 이상이면 "가능 (5시간 한도에 약 N번 걸려요)".
  - 창이 4개를 넘으면 "2~3일에 나눠 만들어요"를 붙인다.
  - 표시 끝에는 [5시간 한도란?](../reference/costs-and-keys.md#5시간-한도에-걸리면) 링크를 단다.
- Claude와 Codex는 칸을 따로 둔다. 지금 값은 같다. 실측이 생기면 칸별로 고친다.

## 10. B 단계 메모 (샘플 자료 팩, 따로 설계)

설계는 `2026-10-05-sample-asset-packs-design.md`로 옮겼다(2026-10-05). 아래는 그 전의 메모다.

- 샘플마다 팩을 둔다.
  - `pack/`: 디자인 노트(카탈로그 주소와 받은 뒤 고칠 것), 화면 구성(`screens.md`), 예시 데이터, 그림 목록(`images.json`)
  - 그림 묶음은 팩 릴리스 `pack-<샘플>-1`로 올린다. 그림은 우리가 AI로 그린 것이라 배포할 수 있다. 8개 합계 169장이다.
- 샘플 쪽에 "샘플과 똑같이 만들기" 프롬프트를 더한다. 지금의 "이 컨셉으로 만들어 보기"는 그대로 둔다.
- 팩이 생기면 그 샘플의 요약값, 카드, 상세, 구독 표시를 "자료 팩으로" 값(6.3절, 7절)으로 바꾸고, 단계별 예상에 "자료 팩으로" 열을 더한다.
- 정할 것: 화면 구성의 근거로 우리 샘플 스크린샷을 팩에 넣을지, 배치도를 그릴지. 시범 팩 하나를 실행해 확인할지(사용자는 전체 실행은 하지 않기로 했다).

## 11. 공개 순서

1. `main`에 커밋한다(`docs:` 또는 `feat:`). 아직 커밋하지 않은 시안 선택 교재 수정(2026-10-05, 5개 파일)도 같은 릴리스에 넣는다.
2. `node scripts/release.mjs`로 릴리스하고, 노트는 korean-skills로 검수한다.
3. 사이트 작업공간에서 라운드를 돌린다(8절 사이트 표, 9절 검증). 작업공간에 커밋한다.
4. `tools/publish-root.sh`로 gh-pages에 올리고 push한다. 공개 주소에서 홈, 샘플 상세, 튜토리얼 쪽을 확인한다.

- 숫자를 재려고 샘플이나 Nextflix를 새로 실행하기
- 요금제 한도를 공식 숫자처럼 적기. 늘 "어림"과 날짜를 함께 적는다
- 샘플 팩 만들기(B 단계)
