# 스킬·에이전트 실행 효율 추가 개선

2026-10-10 승인된 범위는 두 템플릿의 스킬·에이전트 지시와 관련 평가·문서다. 올곧·Claudle은 기존 작업 기록만 참고하며 제품 수정, H 적용, 빌드·재배포를 하지 않는다. 새 스킬·프레임워크·감시 서비스와 CLI·권한 인터페이스도 추가하지 않는다.

## 기존 개선과 이번 변경

기준선은 [앞선 병렬 실행·검사 재사용 개선](../2026-10-10-parallel-verification/README.md)을 포함한 현재 작업 트리다. 과거 개선 이전 버전과 비교하지 않는다. 기준 파일은 저장소 밖에서 사본과 SHA-256으로 고정했다.

이번에는 실행 효율 정본에 작업 범위 구분과 작은 관련 작업 묶기를 보완했다. 구현자는 배정된 회귀검사를 맡고, 전역 검사 명령을 수행자마다 자동 반복하지 않도록 지시를 맞췄다. 리뷰어는 변경 계층·실제 소비자·공유 설정에 맞는 문맥을 읽는다.

하네스 변경도 화면·API·DB·인증·권한·환경 변수 공급·data trust 계약에 영향이 있거나 불명확하면 관련 계층을 확인한다. 필수 보안 문맥과 신뢰 경계, 전문 리뷰 보완과 최종 검수는 유지한다. 명시된 대상 프로젝트의 하네스 수정에 필요한 H 라운드까지 금지하는 규칙은 아니다.

기존 평가의 중복 전문 리뷰 강제와 대행 해석을 현재 위임 계약에 맞췄다. 분석 범위, 한정 리뷰, 독립 배정, 재검사 선택의 네 평가 입력을 추가했다. 평가 입력 개수는 행동 평가 실행 횟수나 품질 점수가 아니다.

## 비교 방법

현재판과 개선판은 네 읽기 전용 과제를 각각 한 번씩 순차로 수행한다. 각 실행은 같은 네이티브 에이전트 유형과 상속된 모델 설정, 같은 요청·fixture·허용 도구를 사용한다. 평가 요청에는 정답과 기존 결론을 넣지 않는다.

과제에 넣은 완료 기록과 검사 로그는 테스트용 합성 자료다. 그 안의 118분 기록은 올곧·Claudle의 실제 제작 시간이 아니다. 실제 계측값은 이번 수행자의 파일 읽기 감사 기록과 배정·회수 시각뿐이다.

계측용 `reader.py`는 고정 입력만 읽고 파일별 해시·바이트 수·호출 식별자를 기록한다. 실제 파일 읽기와 reader 호출을 세며 네이티브 전체 도구 호출 수나 모델 입력 토큰 수로 표현하지 않는다. reader가 남기는 감사 기록만 허용된 계측 쓰기다. 실제 검사·빌드·제품 작업 명령은 실행하지 않는다.

응답에 제안한 명령은 실제 실행과 구분한다. 경과시간은 배정부터 결과 회수까지의 관측값이며 에이전트 준비·대기·회수 비용을 포함한다. 파일 준비 시간은 별도로 기록하고 토큰·비용은 실제 자료가 없어 산출하지 않는다.

## 검증과 관측 결과

기술 변경과 행동 품질은 독립 검수에서 승인됐다. 이번 비교로 추가 속도 향상은 입증하지 못했다. 확인된 성과는 작업 범위, 검사 소유권, 리뷰 문맥과 증거 차단 계약을 명확히 한 것이다.

| 검증 | 결과 |
|---|---|
| 스킬 형식 | 변경 참조를 쓰는 dev-cycle·verify의 quick validation, 두 템플릿 합계 4/4 통과 |
| 관련 템플릿 검사 | 템플릿마다 평가 구조 1개·공유 파일 2개·문서 20개·에이전트 동기화 5개, 28/28 통과 |
| 추가 보완의 영향 검사 | 리뷰어 프로필만 바뀌어 템플릿마다 공유 파일 2개·동기화 5개를 다시 확인, 7/7 통과 |
| 문서 검사 | 변경된 문서의 링크·값·중복 글·시간 표기·마크다운 관련 선택 검사 6/6 통과 |
| 행동 비교 | 네 과제를 현재판·초기 후보에서 각각 한 번 실행했다. 초기 후보의 한정 리뷰 실패를 보존하고, 그 과제만 새 수행자로 한 번 재평가했다. 최종 후보의 네 과제 모두 품질 조건 승인 |
| 권한·증거 | 미검증 통합을 승인하지 않고 unknown·flaky·실패 기록을 유지했다. 제품 작업이나 제안한 검사·빌드를 실행하지 않았다 |

초기 한정 리뷰는 통합을 차단했지만 공통 필수 문서인 `AGENTS.md`와 `delegation.md`를 읽지 않았다. 그 읽기량 감소는 성과로 인정하지 않았다. 공통 필수 읽기를 별도 항목으로 분리하고 H 추가 문맥과 구분한 뒤, 최상위 판정과 통합 판정을 모두 `blocked`로 맞추도록 보완했다.

최종 후보는 초기 후보와 리뷰어 프로필 두 파일만 다르다. 다른 세 과제에서 읽은 입력은 같아 통과한 행동을 재사용했다. 초기 실패 `results/c2.json`과 첫 후보 manifest를 덮어쓰지 않았다.

### 실제 읽기 관측

아래는 성공한 reader 호출, 파일 읽기 횟수, 읽은 파일의 바이트 수다. 한 호출에서 여러 파일을 읽을 수 있다. 전체 네이티브 도구 호출이나 모델 토큰 수가 아니다.

| 과제 | 현재판 호출 / 파일 / 바이트 | 최종 후보 호출 / 파일 / 바이트 |
|---|---:|---:|
| 기록 분석 | 1 / 4 / 23,993 | 1 / 4 / 24,546 |
| 한정 리뷰 | 3 / 9 / 50,161 | 2 / 10 / 62,331 |
| 독립 배정 | 1 / 5 / 26,766 | 1 / 5 / 27,495 |
| 재검사 선택 | 1 / 8 / 34,626 | 1 / 8 / 35,463 |

한정 리뷰의 후보 값은 실패 뒤 프로필을 보완한 재평가 결과다. 호출은 줄었지만 필수 문맥을 복구하면서 파일 수와 바이트는 늘었다. 다른 과제의 호출 수는 같았고, 배정 과제의 전역 명령 제안도 두 판 모두 타입·린트·빌드가 각각 한 번이었다. 재검사 과제에서 소비자 검사를 별도 목록에 적은 형식 차이를 검사 감소로 세지 않았다.

따라서 기술과 품질은 수용하지만, 추가적인 실행량·시간 감소의 수용 근거는 부족하다. 이 결과에 개선률이나 비용 절감률을 붙이지 않는다.

### 시간과 실행 조건

준비 구간은 baseline manifest 생성부터 첫 후보 고정까지 513.4초였다. 이 중 일부는 첫 현재판 평가와 겹치므로 준비 시간과 평가 시간을 더해 전체 작업 시간을 계산하지 않는다. 평가의 배정부터 결과 회수까지 관측값은 최초 여덟 실행에서 61~141초, 실패 과제 재평가에서 196초였다. Main의 회수 지연이 포함돼 실제 과제 수행 시간이나 속도 비교로 사용하지 않는다.

각 실행은 `agent_type=default`, `fork_turns=none`과 동일한 상속 설정을 사용했고 모델·추론 옵션을 별도로 바꾸지 않았다. 실제 모델 식별자와 토큰·비용은 별도 노출 자료가 없어 확인하지 못했다. 준비 후 최초 여덟 실행과 실패 과제 한 번만 수행했고, 각 실행의 성공한 읽기 호출은 설정 상한 안이었다.

원시 근거는 `baseline-manifest.json`, `candidate-manifest.json`, `candidate-v2-manifest.json`, `requests.json`, `fixture-manifest.json`, `audit/`, `results/`, `read-metrics.json`, `experiment-metadata.json`, `logs/`다. 응답 JSON은 Main이 네이티브 최종 응답을 회수해 저장한 것이며 전체 네이티브 도구 transcript로 표현하지 않는다.

## 한계와 재사용

작은 행동 비교는 스킬·에이전트의 판단과 실행 준비를 평가한다. 실제 기능 개발, 빌드 시간, 전체 작업 시간이나 안정성 통계를 증명하지 않는다. 앞선 QA 배치 시간 감소를 이번 지시문 개선의 효과로 합산하지 않는다.

입력이 바뀌지 않은 기존 통과 검사는 재사용하고 이번 변경의 영향 검사만 실행한다. 전체 평가의 반복 비교와 완성 프로젝트 이행은 하지 않는다. 원시 입력·해시·읽기 감사 기록·검사 로그·평가 응답은 `/Users/freelife/youtube/pro-kit-samples/checks/skill-agent-efficiency-20261010/`에 보관한다. 사본과 계측 스크립트는 설치본이나 저장소에 넣지 않는다.

이번 변경은 커밋·push·배포하지 않았다. 홈페이지의 문서 사본 동기화도 실행하지 않았다. handbook 원본과 두 템플릿의 검증 기록만 맞췄다.
