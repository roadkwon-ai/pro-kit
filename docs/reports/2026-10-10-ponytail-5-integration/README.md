# Ponytail 5.1 통합과 Codex 선택 설치 검증

2026-10-10에 Ponytail 원본과 프로킷 설치·라우팅을 대조했다. 확인 원본은 [5.1.0, `9b58c1ffb790c075ca32e70a89cf1d80588f4abf`](https://github.com/DietrichGebert/ponytail/tree/9b58c1ffb790c075ca32e70a89cf1d80588f4abf)이다. 이 판은 확인 기록이며 설치 버전을 고정하지 않는다.

## 구성과 역할

프로젝트 설치 목록에 Ponytail 보조 스킬을 더하고, Codex 네이티브 플러그인은 전역 설치 옵션에서만 받도록 했다. 기본 실행과 확인 모드는 사용자 Codex 설정을 쓰지 않는다. 이미 설치된 플러그인의 출처와 비활성화 선택을 보존한다.

Prokit은 공식 스킬 수행자를 선택하고 작업 범위·증거·재지시를 관리하는 역할을 유지한다. 작업 시작 전 사본과 비교해 전문 리뷰어 정의, 위임 계약, 병렬 처리·재검증 정책을 보존했음을 확인했다. 최종 리뷰어의 책임과 게이트도 유지한다. 최종 판정의 `reused`와 전문 리뷰·QA 증거 재사용을 구분한 추가 검토에서도 기존 승인을 유지했다. 마지막 대조에서 별도로 추가된 `reused` JSON 필드와 설명을 관찰했고, 이번 Ponytail 변경이 아니므로 되돌리지 않았다. 기존 대조표·위임 실행·자원 guard의 사용자 변경도 보존했다. 전문 리뷰 coverage를 재사용하고 부족한 계약만 보완하며 최종 `prokit-reviewer` 게이트를 유지한다. audit·debt는 요청할 때만 수행한다.

## 설치와 훅 시험

실제 Better-T-Stack 3.44.3 프로젝트에 Neon 템플릿을 `--skip-skills`로 설치했다. 이어 시험용 매니페스트를 Ponytail 항목으로 한정하고, 자식 프로세스의 Codex·Claude 설정 경로를 격리해 스킬과 플러그인을 실제 설치했다. 다른 전역 도구의 설치와 DB 시작은 제외했다.

| 확인 대상 | 관찰 |
|---|---|
| 실행 환경 | Node v24.21.0, pnpm 12.10.1, Codex CLI 0.162.0 |
| 실제 설치판 | Ponytail 5.1.0, 위 원본 커밋 |
| 기본 실행·확인 | Codex 설정 파일 해시가 바뀌지 않음. `--check --with-global`도 설치하지 않음 |
| 전역 설치 옵션 | 공식 원본 marketplace와 플러그인 설치, JSON 목록으로 설치·활성 상태 확인 |
| 재실행·업데이트 확인 | 설치 설정 재작성 없음, 프로젝트 스킬의 원본 비교 성공 |
| 시작·서브에이전트 훅 | 직접 호출한 JSON에 지침과 코드 지도, 서브에이전트 문맥이 나옴 |
| 모드·리뷰 | ultra 전환 뒤 슬래시·네임스페이스 review 호출로 지속 모드가 바뀌지 않음 |
| off | 모드 파일을 지우고 서브에이전트 훅이 지침을 넣지 않음 |
| Claude 시작 훅 | 격리 경로에 프로젝트 모드와 보조 파일 생성 |
| 정리 | 시험용 Claude project 플러그인, Codex 플러그인과 marketplace 제거 완료 |
| 사용자 설정 | 실제 사용자 Codex·Claude 설정의 시험 전후 해시 일치 |

실제 설치와 직접 호출, 정리까지 기록한 명령은 20개이며 모두 exit 0이다. 설치 스크립트 SHA-256은 `7a30bb58685835477069684e7e60e69879b9c9ba872f92767ceb33666f4e8f7f`다. 실제 설치한 plugin manifest는 `6efc6b6c8e6e33625f9a27574f27a4d453179bcf534b09c430b00814ecbc98f3`, hook manifest는 `2848d305d8e97f0deb5a5d4e771aef21f27780075737cc08c0c1bdfb6a6061f2`다. 설치 파일의 존재와 직접 훅 실행을 실제 호스트의 신뢰 완료·자동 실행 증거로 대체하지 않았다.

## 검수와 회귀

설치 회귀를 먼저 실패시킨 뒤 구현했다. 독립 Ponytail 리뷰에서 확인 모드와 전역 옵션을 함께 쓸 때의 쓰기, 설치된 플러그인의 출처 확인 누락을 발견해 회귀 검사와 함께 고쳤다. Supabase 문서 테스트의 DB별 차이도 복구했다. 전역 변경 안내와 marketplace snapshot·설치판 갱신의 차이를 정정했다. 수정 뒤 독립 리뷰는 스펙 준수와 품질 검토를 모두 승인했고 남은 지적이 없었다.

skill-creator 구조 검증과 humanizer → style-guide → grammar-checker 순서의 문서 검수를 적용했다. 문체와 짧은 가운뎃점 나열은 프로킷 예외를 유지했다. 기대 조건이 함께 있는 저장소를 읽은 첫 행동 평가는 독립성에 한계가 있었다. 두 번째는 기대 조건·테스트 파일을 뺀 격리 작업공간에서 새 평가자가 사용자 요청만 받아 수행했다. off 존중, 보안 수정 판단과 최종 리뷰 경로, 두 주석 표기의 수집·재검토 조건 누락·gain의 원본 벤치마크 구분을 확인했다. 모든 위임 평가의 실행이나 통계적인 성공률 측정으로 해석하지 않는다.

전체 템플릿 검사는 마지막에 순서대로 실행했다. 앞선 병렬 실행에서의 실패는 아래 한계와 별도 원본 로그에 남겼고 최종 결과로 덮지 않았다.

## 한계와 이행

- Codex의 실제 `/hooks` 신뢰 화면과 호스트의 자동 훅 배포는 시험하지 않았다. 신뢰 기록을 자동으로 쓰거나 우회하지 않았다.
- 실설치는 Neon 확인용 프로젝트에서 했다. Supabase는 같은 설치 스크립트·회귀 검사와 별도 템플릿 검사를 사용하며 로컬 Supabase DB를 띄우지 않았다.
- 첫 설치 시험은 격리 Codex 폴더가 없어 실패했다. 원본 로그를 보존하고 시험 환경을 바로잡았다.
- 첫 병렬 전체 검사에서 reviewer child 정리 검사가 한 번 실패했고 독립 진단 한 번은 통과했다. 원인을 확정하지 않았으며 최초 실패를 통과로 바꾸지 않았다.
- 기존 프로젝트는 해당 프로젝트 세션의 H 라운드로 템플릿 차이를 반영한다. 기존 네이티브 플러그인 갱신은 원본 훅·코드 검토와 사용자 요청을 따르며 비활성화를 유지한다.
- 설치 구성 변경이므로 minor를 추천한다. 이번 작업은 릴리스·push·배포를 하지 않는다.
