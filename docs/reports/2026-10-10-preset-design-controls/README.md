# 프리셋 디자인 설정과 제작 기본 기능

> 아래 2026-10-10 기록은 당시 구현 범위다. 이후 전체 번역과 도구 확장의 현재 결과는 마지막 2026-10-11 절에서 확인한다.

## 범위

사용자의 범위 정정을 반영했다. 폰트·색상 선택 UI·설정 견본·미리보기 수신기는 공식 프리셋 제작과 프로킷 미리보기 전용이다. 실전 서비스 생성 프롬프트는 선택값을 디자인 토큰에 고정하고 이 전용 기능을 넣지 말라고 명시한다.

프로킷 사이트의 제작 프롬프트 설정과 미리보기 팔레트, 앞으로 제작하는 프리셋의 기본 모드·언어 계약을 다룬다. 기존 공개 프리셋 전체 번역과 팩 재발행·원격 배포는 포함하지 않는다.

정본은 [설계](../../superpowers/specs/2026-10-10-preset-design-controls-design.md), [구현 계획](../../superpowers/plans/2026-10-10-preset-design-controls.md), [폰트 조사](../../superpowers/specs/2026-10-10-preset-font-catalog.md)다.

## 제작 규칙

두 템플릿의 prokit-ui에 프리셋 기본 기능과 `references/preset-settings.md`를 추가했다. 시스템·라이트·다크, 한국어·영어, 같은 키의 번역 사전, Intl 표시, 상태 유지, 정적 HTML 검증을 요구한다. 폰트·색상은 원래 디자인과 선택 적용을 구분한다.

공통 프롬프트는 `docs/blocks/preset-default-features.md`가 원본이다. 팩 그대로 만들기·리믹스·화면만 만들기 프롬프트에 같은 지시가 들어간다. 한 줄로 쓴 시작 프롬프트 사본과 공통 글 목록도 맞췄다.

## 설계와 문서 리뷰

독립 계획 리뷰의 원문 팩 안내 보존, 패널 크기 측정, 방향키 충돌 방지, 실제 적용 옵션 대조 지적을 반영했다. 한글 검수는 humanizer·style-guide·grammar-checker 순서로 수행하고 문체와 짧은 가운뎃점 나열을 보존했다. 기존 프리셋이 새 기본 기능을 이미 갖췄다는 오해를 줄이는 문구도 고쳤다.

## 스킬 행동 평가

`evals/prokit-ui/evals.json`에 시나리오 3을 추가했다. 독립 native 에이전트가 수정한 SKILL.md와 참조를 읽고 Inter 제목·SUIT 본문·원래 색상·화면만 HTML 요청의 제작 계획을 작성했다.

계획 응답에서 참조 읽기, 세 모드·두 언어, 사전 키/Intl/상태 유지, 영문 폰트의 한글 폴백, HTML/메시지 검증, 기존 지원 미확인 유지의 요구를 확인했다. 이는 문서를 읽고 계획하는 행동 평가다. 생성된 프리셋 앱이나 공개 프리셋의 실제 전환을 검증한 결과로 합치지 않는다.

사용자 정정 뒤에는 시나리오 4를 추가했다. 실전 SaaS의 고정 Pretendard·짙은 파랑 요청에서 선택 팔레트·견본·미리보기 수신기·전체 카탈로그를 제외하고, 모드·언어는 제품 요구를 따른다는 계획을 확인했다. 실제 서비스 구현을 평가한 결과는 아니다.

두 템플릿을 동시에 검사했을 때 공용 임시 폴더 개수를 세는 기존 자원 테스트 한 항목이 경합했다. 해당 항목 단독 검사와 두 템플릿 순차 전체 검사는 모두 통과했다. 자원 코드나 그 테스트는 이번 작업에서 고치지 않았다.

실제 비교 서체는 기존 Pretendard와 새 자체 호스팅 서체 SUIT·SUITE·Wanted Sans·Gmarket Sans·MaruBuri·LINE Seed KR다. 원래 디자인 선택도 제공한다. 팔레트는 원래 색상과 Ocean·Forest·Plum·Sand·Slate이며 선택한 팔레트의 라이트·다크를 비교한다. 폰트 조사 후보 전부를 미리보기 자산으로 내려받지는 않았다.

브라우저에서는 제작창의 표시 문장과 CopyButton에 전달되는 값의 일치, 고정 폰트·색상 지시, 일반 서비스에 수신기를 요구하지 않는 문장, 팩 링크 보존을 확인했다. 원래 팔레트에서 서체만 바꿔도 견본이 표시된다. 1440·390·320 폭에서 가로 넘침, 선택기의 방향키와 페이지 이동 충돌, 그림 비교 원본 안내, 다음 페이지 이동을 확인했다.

격리된 로컬 검증용 iframe에서 SUIT 본문·MaruBuri 제목·Ocean 다크·영어의 실제 적용과 확인 응답을 검사했다. iframe 안의 `html.lang`, 배경색, 실제 글꼴과 제목을 읽어 대조했다. 페이지·기기 보기 전환 직후 이전 적용 성공 표시도 지워진다. 이 fixture 검사를 기존 공개 프리셋 지원으로 합치지 않는다.

Next.js `get_compilation_issues`는 빈 목록, `get_errors`는 config/session 오류가 없는 결과를 반환했다. 깨끗한 agent-browser의 오류 목록도 비었다. React DevTools 트리는 재시도 뒤에도 `No React renderer attached`로 확인하지 못했다. DOM 상호작용·Next 메타데이터·타입 검사·독립 코드 리뷰는 별도로 통과했다.

남은 범위는 기존 공개 프리셋 개별 전환, 팩 재발행·정적 배포, Safari·실제 모바일 기기와 일부 기존 링크/슬라이더/닫기 버튼의 터치 영역이다. 문구로 미지원 상태를 판정하는 부분도 후속 정리 항목이다. 사이트 dev-cycle의 실제 사용자 확인 행은 비워 두며 커밋·원격 push·배포는 하지 않았다.

## 사용자 확인 중 미리보기 높이 보완

세로로 긴 화면의 제보에서 고정 `h-[92svh]`와 고정 iframe 높이 때문에 실제 프레임 아래에 약 1,000px 빈 공간이 생기는 문제를 재현했다. 창의 고정 높이를 제거하고 여유 공간을 실제 iframe viewport 높이로 쓰도록 바꿨다. 자동 높이가 기본이며, 아래 손잡이를 드래그하거나 방향키로 수동 높이를 조절한다. 가로 배율은 유지하고 화면 상한을 넘기지 않는다.

높이 변경은 같은 iframe을 유지하며 페이지를 다시 불러오거나 설정 연결 상태를 초기화하지 않는다. 손잡이는 pointer capture/up/cancel/lost, 키보드 방향키/Home/End를 지원한다. 실제 손잡이 높이와 여백도 화면 예산에 넣는다. 그림 비교에서는 높이 조절을 사용하지 않는다.

지정한 ego-browser만 사용해 큰 화면의 채우기, 실제 드래그 줄이기·늘이기, 자동→수동, 같은 iframe 노드 유지, 모바일 가로 넘침 없음, slider 방향키의 페이지 이동 방지를 확인했다. 높이 계산·드래그 경계 테스트를 더해 사이트 계약 테스트는 17개가 통과했다. 최종 타입·린트·빌드 결과도 별도 높이 수정 검사에서 통과했다.

자동 높이는 실제 페이지 viewport를 바꾸므로 `vh`처럼 화면 높이에 반응하는 프리셋의 배치도 바뀐다. 페이지 전체를 스크롤 없이 항상 보여준다는 보장은 하지 않는다. 테스트 도중 큰 에뮬레이션 화면의 포인터 입력과 HMR 이전 상태 문제를 구분했고, HMR에도 새 높이 상태 필드가 반영되도록 수정했다.

## 공식 미리보기 실제 적용과 선택 견본 개선

사용자가 승인한 후속 계획에 따라 펼치기·접기 문구와 화살표, 후보별 실제 서체 견본, 원래 색상과 대체 팔레트의 라디오 카드를 같은 설정 컴포넌트에 반영했다. 선택된 팔레트는 체크와 키보드 포커스 윤곽으로 표시한다. 모바일 요약은 설정 패널 안에서 고정되고, 320px의 서체 메뉴도 가용 폭 안에 들어간다.

공통 수신기와 11개 프리셋의 의미 토큰·서체 역할 연결표는 pro-kit-web에 둔다. 기존 정적 HTML 535개에는 공유 모듈을 한 번씩 붙였고, 붙인 태그를 뺀 원문은 실행 전 sha256과 모두 같다. 원본 앱과 팩은 바꾸지 않았다. 공유 코드·서체는 정적 배포 루트의 `_preset-preview/`에 한 번만 두며, 일반 서비스 내보내기는 이 처리를 부르지 않는다. 공식 게시 도구는 같은 후처리를 호출하고 비공식 사이트에서는 주입 단계만 건너뛴다.

메시지와 실제 적용값은 서체·색상·모드·언어별로 검증한다. 기존 프리셋의 언어 미지원은 서체·색상 적용을 막지 않고 원래 색상의 모드는 유지한다. 공개 운영 별칭과 기본 개발 포트도 출처 허용 목록에 명시했다. iframe은 마운트마다 캐시 구분 값을 만들지만 설정·높이 변경에는 같은 노드와 주소를 유지한다. 공유 ESM 전체와 HTML은 같은 내용 해시로 캐시를 구분한다.

Ego에서 11개 첫 화면과 9개 로그인·신청·상세·앱 화면의 실제 서체 로딩·팔레트 적용·가로 넘침 없음을 확인했다. 320px·390px 메뉴, 모드·언어·초기화, 제작 프롬프트의 표시·복사 문자열 일치, 키보드·페이지 이동과 높이 조절도 확인했다. 독립 페이지로 연 프리셋은 연결 속성·스타일이 없고 원래 색상으로 보인다. 사진 위 글자와 정적 색상 클래스가 섞인 Nextflix는 명시한 요소만 추가로 연결해 입력·배지·사진 문구의 대비를 보존했다.

최종 공통 테스트 35개가 통과했다. 타입·린트·빌드와 Next 진단은 통과했고, 독립 코드 리뷰는 approve다. 독립 UI 재확인은 Design Health 36/40, audit 19/20, 접근성 4/4이며 P0·P1은 없다. 검사와 화면 증거는 pro-kit-web의 `tasks/evidence/preset-preview-20261010/`에 있다.

원격 배포·팩 재발행·기존 프리셋 전체 번역·Safari·실제 모바일 기기 검사는 하지 않았다. 첫 서체 메뉴에서 후보 파일 약 3.87MB를 지연 로드하고 캐시하며, 견본용 subset은 후속 성능 작업으로 남겼다. 실제 사용자 확인 행은 비워 두고 커밋·push·배포는 하지 않는다.

## 2026-10-11 후속 구현과 제작 프롬프트 검사

사용자가 승인한 확장 계획에 따라 무료 서체 20종과 원래 서체, 팔레트 14종과 원래 색상을 제공한다. KoPubWorld·넥슨은 제외했다. 후보 메뉴에는 실제 서체로 만든 PNG 견본을 표시하고, 선택한 본문·제목 서체의 파일만 불러온다. 원본 파일과 라이선스·저작권 고지를 보존한다.

제작 프롬프트의 요청 본문은 편집 상태를 유지한다. 자동 디자인 설정은 기본 접힘, 완성 프롬프트는 기본 펼침이며 세 영역 모두 높이를 조절하고 내부에서 스크롤한다. 복사·ChatGPT·Claude는 같은 완성 문자열을 사용하며 자동 제출하지 않는다. 높이 손잡이 안내와 넓게 보기, 오른쪽 패널의 왼쪽 경계 드래그·키보드 조절을 제공한다. 크기 변경은 같은 iframe과 페이지·입력을 유지한다.

기존 원본 앱 11개에는 같은 공통 React 번역·모드 연결을 적용했다. 테마는 현재 모드 아이콘 메뉴, 언어는 국기와 이름으로 고른다. 미리보기 안의 전환은 부모 설정과 동기화하며 설정 견본도 영어로 바뀐다. 실제 서비스에는 고른 서체·색상을 고정하고 프로킷 제작용 선택 UI·수신기를 넣지 않는다.

색상·모드를 연속 변경할 때 이전 비동기 요청이 새 화면을 덮어쓰던 경합과, 늦은 서체 로딩이 새 선택을 되돌리던 경합을 공통 코드에서 해결했다. 정적 서버 컴포넌트의 단일 자식을 배열로 바꾸던 번역 문제도 고쳐 상세 화면 전환의 React 오류와 상태 초기화를 막았다. 숫자 단위는 숫자에만 붙이고 고유명·사용자 입력·콘텐츠 원문은 보존한다.

추가 프롬프트 감사에서 자동 설정 재삽입의 중복과 사용자 인용문 삭제를 발견했다. 고정 시작·끝 표시가 있는 자동 블록만 최신 값으로 교체하고 사용자 본문은 그대로 둔다. 선택값을 `docs/preset-design.json`과 `DESIGN.md`에 기록하며, 실제 파일·굵기·라이선스와 양쪽 모드 토큰을 구현 기준으로 삼도록 요구한다.

완료 검사에는 `document.fonts`와 `getComputedStyle`의 실제 적용값 대조, 본문·버튼 4.5:1 및 큰 글자·아이콘·조작부 3:1 대비, 모드·언어와 페이지·입력 유지, 내보낸 HTML과 검증 증거를 명시했다. 두 템플릿의 `prokit-ui/references/preset-settings.md`에도 같은 기준을 넣었다. 프롬프트는 제작·검증 계약이며 AI의 실행을 강제하는 자동 검사기가 아니다. `pnpm export:html` 성공은 선택 디자인의 적용 증거를 대신하지 않는다.

원격 배포·팩 재발행·커밋·push, Safari·실제 모바일 기기 검사는 하지 않는다. 과거 절의 전체 번역 미지원·후보 서체 전체 로딩·원본 앱 제외 설명은 이번 확장으로 대체한다. 사용자 확인 행은 자동으로 채우거나 라운드를 닫지 않는다.

현재 검증 증거는 pro-kit-web의 `tasks/evidence/preset-expansion-20261011/`에 있다. 사이트 회귀 66개, 공통 번역·수신·닫기 도구 회귀 13개, 두 템플릿 각각 274개와 문서·공유 파일 63개가 통과했다. 사이트 타입·전체 Biome, 원본 앱 11개의 타입·변경 파일 Biome와 공식 내보내기도 통과했다.

Ego에서 11개 앱 513개 경로의 영어 라이트 적용과 한국어 다크 복원을 검사해 실패·런타임 오류 0건을 확인했다. 시스템 테마는 11개 첫 화면에서 라이트·다크 에뮬레이션 변경에 반응했다. 원본 브랜드와 사용자 입력은 보존하며, Uptrail 요일 트리거와 기본 닫기 문구는 마지막 개별 재검사로 확인했다.

Olgot의 제목·강조 버튼·빠른 메뉴 532표본은 14팔레트의 두 모드에서 최저 5.15:1 대비를 보였다. 모든 페이지의 모든 색 대비를 검사한 수치로 합치지 않는다. 실제 서체 20종과 견본 PNG 20개, 표시·복사·두 AI 주소의 최종 문자열 일치, 입력·iframe·모달 유지와 모바일 390px·설정 버튼 44px도 확인했다.

사이트 빌드는 넓은 터미널 출력에서 정적 페이지 117개를 생성했다. 일반 파이프 출력의 Next.js UTF-8 경고 처리 오류와 원본 앱 전체 Biome의 범위 밖 접근성·생성 상태·포맷 진단은 별도 한계로 남겼다. 새 서비스를 생성 프롬프트로 처음부터 만드는 반복 평가는 하지 않았으므로 AI의 지시 준수를 자동으로 보장한다고 표현하지 않는다.
