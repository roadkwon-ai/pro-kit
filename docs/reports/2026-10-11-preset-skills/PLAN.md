# 프리셋 반영 시스템과 전문 스킬 설계

## 목표와 범위

프리셋 제작 기록을 누락 없이 설명하고, 공통 카탈로그·설정·미리보기·팩·문서의 등록 계약을 검사한다. 이 시스템을 먼저 보완한 뒤 별도 로컬 Git 저장소 `../pro-kit-preset-skills`에 전문 스킬을 제작하고 프로젝트 범위에 설치한다.

기존 제품·템플릿과 다른 작업의 변경은 보존한다. 배포 보류를 유지하고 커밋·push·원격 저장소 생성·팩 발행·배포는 실행하지 않는다. 주기적인 정본 확인은 게시 시작과 시스템 변경 때의 내용 해시 비교로 구현한다. 사용자가 예약 실행을 요청하지 않았으므로 자동 실행 서비스는 추가하지 않는다.

## 확인한 결함과 최소 보완

| 결함 | 보완 | 소유권과 검사 |
|---|---|---|
| 제작 관측 기록은 있지만 전체 시간·점수·토큰과 함께만 표시됨 | 일부 관측 세션과 전체 제작·재현 시간을 구분해 공통 값으로 표시 | Main: 원시 관측 정본·doc-values. 수행자: 공통 카드·상세 표시와 영향 검사 |
| 여러 저장소의 등록 상태를 따로 검사함 | 읽기 전용 계약 CLI로 slug·게시 상태·문서·스크린샷·팩 정본을 대조 | 수행자: web CLI와 samples 게시 연결, 작은 실패 fixture |
| 게시 작업의 정본과 스킬이 낡았는지 알기 어려움 | 실제 코드·정본 파일의 해시와 스킬의 검증 기준선을 비교 | 계약 CLI 결과를 새 갱신 스킬이 사용 |

## 순서와 완료 조건

사용자 추가 지시에 따라 두 템플릿에서 프로킷 웹 게시 관리 지침을 분리한다. 제품 디자인·이미지 생성·언어·테마·정적 HTML 검증은 유지하고, 운영 미리보기 프로토콜·카탈로그·팩 게시 계약은 새 관리 스킬의 참조로 옮긴다. 템플릿에 관리 스킬을 설치하지 않는다.

1. 기존 상태와 실제 시간 구간을 고정한다. 병렬 구간·내부 검사 시간을 중복 합산하지 않는다.
2. 위 두 시스템 보완을 구현하고 관련 검사만 실행한다. 전체 프리셋 제작·과거 QA 비교는 반복하지 않는다.
3. `skill-creator`로 `prokit-preset-publish`와 `prokit-preset-maintain`을 제작한다. 문서 작성은 `prokit-docs`·`prokit-writing`, 제품 제작은 해당 프로젝트 `prokit-ui`, 배포는 허가된 기존 배포 스킬에 위임한다.
4. 형식·참조·스크립트 검사와 독립 행동 검수를 한다. 통과한 시나리오는 반복하지 않고 실패 또는 수정 영향 범위만 재검사한다.
5. 로컬 설치 후 동일 내용을 확인하고 handbook·프로킷 웹 문서 사본과 보고서를 맞춘다. 사용자가 확인하지 않은 `[confirm]`은 채우지 않는다.

완료는 변경된 검사 통과, 독립 검수 승인, 미검증 범위 명시로 판정한다. 단일 제작 기록이나 형식 검사 통과를 전체 제작 속도 개선율로 표현하지 않는다.
