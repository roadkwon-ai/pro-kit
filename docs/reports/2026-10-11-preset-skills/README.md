# 프리셋 반영 시스템과 관리 스킬 검증

## 제작 시간이 숨겨진 원인

제작 이력이 없는 것은 아니다. 웹은 공개 여부와 디자인 점수가 있어야 팩 시간·토큰도 있는 것으로 가정했고, 전체 시간 자료가 없던 슬라이드랩의 일부 관측 기록까지 미측정으로 숨겼다. 공개 여부·점수·예상치·실제 관측의 조건을 분리했다.

슬라이드랩 최초 제작·수정의 <!-- v:preset.slidelab.observed.count -->3<!-- /v -->개 세션에서 <!-- v:preset.slidelab.observed.time -->1시간 59분<!-- /v -->을 관측했다. <!-- v:preset.slidelab.observed.note -->대기·검사·증거 정리를 포함한 세션 관측값이에요. 초기 설치와 레퍼런스 재제작·게시 준비는 포함하지 않았어요.<!-- /v --> 내부 검사 시간과 병렬 작업을 다시 더하지 않았다. 실패·중단 기록의 시간도 보존하며 성공 검사로 승격하지 않았다.

원시 근거는 `pro-kit-samples/checks/slidelab-20261010/`의 `project-session-run.json`, `project-session-resume-run.json`, `project-session-defect-fix-run.json`이다. 원시 SHA-256·시작/끝·wallMs·종료 코드를 공통 값 정본의 `presets.slidelab.observed`에 기록했다. 전체 제작 시간·레퍼런스 품질 재제작·게시 준비·토큰·비용은 이 세 구간으로 확정할 수 없다.

## 먼저 보완한 시스템

| 결함 | 보완 결과 |
|---|---|
| 시간·점수·공개 상태를 함께 판단 | 일부 관측을 독립적으로 표시하고 팩 예상·토큰·구독은 필요한 실제 키가 있을 때만 표시 |
| 여러 저장소의 등록 상태를 따로 확인 | `presets:check`가 카탈로그·미리보기·팩·문서의 전역 등록을 대조하고 선택한 프리셋을 상세 검사 |
| 팩의 크기와 자료가 따로 변경 가능 | 명시한 ZIP의 실제 SHA-256과 bytes를 등록값에 대조 |
| 공통 코드 변경과 스킬 갱신이 연결되지 않음 | 실제 정본 내용 해시와 관리 스킬 기준선의 차이를 파일별로 표시 |
| 준비가 누락돼도 게시 도구가 진행됨 | 기존 publish 도구의 내보내기 전에 등록 계약 검사를 연결하고, 실패하면 기존 출력을 보존 |
| 사용자 프로젝트 스킬에 관리 규칙이 포함됨 | 두 템플릿에서 iframe·부모 설정·카탈로그·팩 게시를 분리하고 제품 제작 계약을 유지 |

기존 카드·상세·설정 UI·서체 로더·미리보기·보호된 내보내기를 재사용했다. 여러 책임의 데이터를 하나의 범용 엔진으로 합치거나 새 프레임워크를 추가하지 않았다. 프로킷 웹 게시 계약은 사용자 프로젝트의 템플릿 manifest에 넣지 않았다.

슬라이드랩은 사용자 지시대로 퍼스널브랜딩으로 분류했고, 기존 학원 프리셋은 유지했다. 로컬 화면·필터와 모바일에서 확인했다.

준비본 공개 방지도 보완했다. 개발에는 보이되 production 카드·경로·교재·목차에서는 제외한다. public 원시 파일과 목록 링크, Pages의 준비본 폴더는 공개 사전검사로 차단하며 삭제하지 않는다. 실제 앱 build 명령도 사전검사에서 멈추고 원래 빌드를 실행하지 않았다.

## 별도 스킬 저장소

원본은 저장소 밖의 로컬 Git 저장소 `../pro-kit-preset-skills`다. `skill-creator`로 다음 스킬을 만들며, 사용하는 프로킷 관리 프로젝트에만 설치한다.

| 스킬 | 책임 |
|---|---|
| `prokit-preset-publish` | 공식 프리셋 제작의 전문 위임, 공통 카탈로그·설정·팩·문서 반영, 로컬 검수와 허가된 게시 관리 |
| `prokit-preset-maintain` | 게시 전·공통 시스템 변경 후 정본 비교, 영향 검사·독립 리뷰, 스킬 기준선과 설치본 갱신 |

제품 구현은 해당 프로젝트 스킬, 문서 구조·값은 `prokit-docs`, 글은 `prokit-writing`, 배포는 기존 배포 전문 스킬에 맡긴다. 유지보수 해시와 JSON 결과를 실행 권한이나 최종 인수 콜백으로 쓰지 않는다. 자동으로 현재 기준선을 수용하거나 원격 작업을 예약하는 서비스는 추가하지 않았다.

## 검증과 한계

시스템 계약의 결정적 검사, 명시한 로컬 Slidelab 정적 결과·ZIP 검사, 시간 합집합·실패/unknown 처리, 두 템플릿 경계 회귀 검사와 공통 파일 일치 검사가 통과했다. 변경된 표시의 타입·형식과 실제 개발 화면을 확인했다. 웹 문서 사본은 새 페이지와 공통 값을 동기화했다.

독립 행동 검수의 원본 스냅샷은 필수 18/18, 현재 지침 변경 영향 두 시나리오는 7/7을 충족했다. 최종 독립 리뷰는 APPROVE, 미해결 지적 0건이다. 승인한 정본 파일 32개의 기준선을 갱신했고 pro-kit·pro-kit-web에 설치한 두 스킬의 네 사본 모두 원본과 바이트가 같다. 자세한 결과는 별도 스킬 저장소의 `VERIFICATION.md`에 기록했다. 실제 행동 과제의 판단과 제안한 작업은 실제 빌드·배포 실행과 구분한다. 통과한 과거 QA·전체 시나리오·성능 비교는 반복하지 않았다.

추가 웹 빌드 전 기존 guard가 빌드 캐시 논리 합계 `51,757,782,862`바이트에서 `block`을 반환했다. 새 빌드는 실행하지 않았고 캐시·환경·폴더도 삭제하지 않았다. 이 측정값은 정리하면 확보되는 공간이 아니다. 실기기·Safari·전체 설정 조합과 다른 호스트의 스킬 실행은 이번 검증 범위가 아니다.

새 등록 검사와 해시 비교는 반복되는 등록 누락을 탐지하지만 향후 오류를 완전히 막는다는 보장은 아니다. 전체 제작·게시 시간 단축률은 이번 작업에서 비교 측정하지 않았다. 로컬 저장소와 반영본만 준비했다. 사용자 확인·커밋·push·원격 저장소 발행·팩 릴리스·배포는 실행하지 않는다.

원시 기록·검사 출력은 `pro-kit-samples/checks/preset-skills-20261011/`에 보존한다. 사용 안내는 [프리셋 등록과 검수](../../../handbook/design/preset-publication.md), 적용 범위는 [계획](PLAN.md)에서 확인한다.
