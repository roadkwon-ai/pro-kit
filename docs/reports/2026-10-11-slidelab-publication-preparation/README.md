# 슬라이드랩 게시 준비와 재발 방지 검수

2026-10-11 작업 기록이다. 사용자의 마지막 지시인 **배포 중지**에 따라 로컬 카탈로그·디자인 설정·팩·검증까지만 진행했다. 이 작업에서 커밋·push·팩 릴리스·Pages·Vercel 배포는 하지 않았다.

## 기존 수정과 이번에 발견한 빈틈

레퍼런스 조사·생성 이미지·넓은 화면 정렬·프로필 겹침·모션·접근성·현재판 CLI 인수는 [이전 검증 기록](../2026-10-10-slidelab-reference-fidelity/README.md)에 있다. 그 인수는 레퍼런스 충실도 범위였다. 공식 프리셋 게시에 필요한 설정까지 완료했다는 근거로 사용하지 않았다.

| 발견한 문제 | 보완 | 현재 증거 |
|---|---|---|
| 공식 프리셋의 모드·언어·미리보기 연결 누락 | 기존 공통 React 번역과 모드 연결을 재사용하고 실제 앱에 연결 | 사전 300키, 두 언어·세 모드, 시스템 변화·저장 차단·입력·열린 창·초점 유지 확인 |
| 설정 표시·성공 응답과 실제 글꼴이 다름 | 없는 Pretendard 변수의 fallback과 실제 폰트 파일을 공통 정본에서 연결 | SUIT·MaruBuri·Pretendard의 실제 글꼴과 로딩 상태를 iframe에서 확인 |
| 새 프리셋마다 게시·보존 목록에 이름을 중복 추가 | `presetPreviewProfiles`를 정본으로 `--slugs`를 제공 | 두 수동 목록을 제거하고 공식 프로필 12개를 같은 목록으로 조회 |
| 오래된 게시 도구가 프로젝트 전체를 복사 | 프로젝트 또는 정본 템플릿의 보호된 exporter·resource guard를 재사용 | 전용 helper와 기존 프로젝트 대안, 실패 시 이전 출력 보존 fixture 통과 |
| 카탈로그가 모든 프리셋에 점수·시간·공개 팩이 있다고 가정 | 공통 카드·상세·교재를 쓰는 곳에서 미평가·미측정·미게시를 명시 | 새 프리셋의 없는 값을 0이나 과거 점수로 채우지 않음. 공개 프리셋 누락 검사는 유지 |
| 공개 메타데이터에 로컬 절대 경로와 개수 불일치 | 원시 증거를 보존하고 공개 경로를 정리, 총량·신규·재사용을 구분 | 생성물 총 13개, 신규 11개, 재사용 2개. 정적 JSON·팩에서 로컬 사용자 경로 없음 |
| 문서 검사가 public 전체를 추적 | 문서·튜토리얼·관련 이미지 폴더와 루트의 고정 파일만 조회 | 넓은 경로 경고 3개에서 0개. 표준 `pnpm build`로 119개 정적 페이지 생성 |
| 실패 사례를 다음 실행 조건으로 옮긴 확인이 없음 | 프로젝트 lessons, 템플릿 종료 조건, 행동 평가를 연결 | 아래 재발 방지 구조 확인 |

이미지와 레퍼런스를 다시 만들지는 않았다. 기존 생성물과 수용한 화면을 보존했다. 폰트·팔레트 선택 UI는 프로킷의 공통 컴포넌트를 사용하며 프리셋별 화면을 범용 엔진으로 합치지 않았다.

## 학습을 실행에 연결하는 구조

프로젝트 시작 시 `tasks/lessons.md`를 읽는 기존 규칙에 더해, 재발 원인이 발견된 라운드의 종료 단계에서 lessons·정본 규칙/평가·백로그 중 어디에 반영했는지 확인한다. 슬라이드랩과 프로킷 웹의 lessons에도 이번 원인과 조건을 남겼다. 두 템플릿에는 같은 규칙을 유지한다.

- UI 행동 평가 5번: 실제 레퍼런스 관측, 넓은 화면 좌표, 실제 휠의 sticky 경계, 생성 이미지 연결, 기능 검사와 시각 검수 분리.
- dev-cycle 행동 평가 38번: 현재 audit 누락 시 차단, 유효한 검사 재사용, 새 최종 판정과 검사 재사용의 구분, 결과 JSON 수동 조작 금지.
- 프리셋 게시 계약: 앱·카탈로그·팩의 개수·지원 기능을 대조하고 공개 메타데이터를 내보내기 전에 점검한다.
- 인증 계약: 다시 로그인하라고 묻기 전에 신뢰한 `.envrc`·`.env`의 키 존재·우선순위·세션과 값 차이를 비밀값 출력 없이 확인한다. 실제로 파일 토큰과 세션 토큰이 달랐다. 배포 중지 뒤에는 새 인증 시도를 하지 않았다.

두 행동 과제의 단회 독립 읽기 검수는 필수 조건을 모두 충족했다. 이는 계획 판단을 검수한 결과이며 실제 브라우저·CLI 실행이나 전체 평가 반복 결과로 합치지 않는다. 모델의 가중치를 바꾸거나 미래 실수를 완전히 막는 장치는 아니다. 기록·수용 조건·평가·독립 검수를 연결한 구조다.

## 실제 검사와 재사용

| 범위 | 결과 |
|---|---|
| 변경된 템플릿 스킬 | skill-creator 형식 검사, JSON·공통 파일 일치, 템플릿별 관련 테스트 19개씩 통과 |
| 공통 미리보기·게시 경로 | 관련 검사 16개와 게시 shell fixture 통과. 이후 폰트 입력이 바뀐 영향 검사 40개 통과 |
| 슬라이드랩 정적 검사 | 타입·사전 검사 통과. 첫 import 정렬 오류만 고쳐 lint 통과 |
| 모드·언어 | 여섯 조합, 시스템 변경, 선택 저장·저장 차단, 입력·시간·열린 창·초점 유지 확인 |
| 접근성·반응형 | 정지된 화면에서 두 언어×두 모드의 axe 위반 0. 너비 6종 검사 누락·flaky·넘침 0 |
| 현재 클릭 검사 | 한 페이지, 클릭 40회, 열린 창 24회, 메뉴 2회. 콘솔·요청·반응 없는 버튼·404 없음 |
| 프로킷 웹 | 초기 nullable 타입·미게시 팩 검사 실패를 해당 항목만 수정. 현재 타입·문서 검사 및 표준 빌드 통과 |
| 정적 산출물·팩 | 공개 JSON 경로 정리와 source·CRC·해시·로컬 zip 받기 확인. 원격 다운로드·발행은 하지 않음 |

슬라이드랩의 이번 일반 빌드는 10.64초, 최초 정적 내보내기는 21.03초였다. 이후 320px 로고 줄바꿈은 CSS 한 줄로 수정하고 필요한 내보내기만 갱신했다. 메타데이터 변경 때도 화면·타입·기능 검사를 재사용하고 산출물과 팩만 갱신했다.

첫 움직이는 화면의 axe 관측은 정지 조건과 CSS 전환 준비가 일치하지 않았다. 원시 기록을 보존하고 관측 조건을 맞춘 실패 경로만 확인했다. 브라우저의 닫힌 메뉴·숨긴 radio 입력을 직접 누른 진단 실패도 제품 결함과 구분했다. 메뉴 준비 상태와 실제 선택 label, 기존 부모 메시지 계약으로 확인했다.

빌드의 최초 Turbo 오류는 Next.js 경고의 UTF-8 코드 프레임 처리에서 발생했다. 경고 원인이던 파일 탐색 범위를 좁혔고 기본 명령이 통과했다. 10,224개라는 값은 최초 경고가 알린 넓은 패턴의 매칭 수다. 전체 작업 시간·토큰·비용의 감소율은 측정하지 않았으며 캐시가 따뜻한 빌드 시간을 일반화하지 않는다.

통과한 기존 24개 시나리오 반복 평가, QA worker 성능 비교, 기존 프리셋 전체 검사·H 이행은 다시 실행하지 않았다. 실패 또는 새 수정의 소비자 범위만 다시 확인했다.
