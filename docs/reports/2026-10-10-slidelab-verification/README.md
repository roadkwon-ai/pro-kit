- 최종 코드 검수에서 기본 `/dashboard`가 필요한 공급자 없이 렌더될 수 있는 조건부 high 회귀를 발견했다. 원 수행자가 단일 화면 프리셋에 불필요한 생성 경로와 관련 UI 다섯 개를 제거했다. 인증 라이브러리·API·DB·패키지는 보존하고 영향 검사만 재실행했다.
- 설치기의 제외 설정에 `.prokit/`과 생성 증거가 빠져 린트가 관리 JSON을 검사했다. 두 템플릿의 기존 설정 병합 함수에 Git 제외 `.prokit/`, Biome 제외 `!**/.prokit`·`!tasks/evidence`를 추가했다. 관리 상태의 민감 진단은 공개 증거에서 제거했다. 원본 해시와 제거 범위는 별도 기록했다.

기존 버튼 일괄 검사는 열린 모달 상태가 다음 클릭에 영향을 주므로 링크 검사와 상태별 검사를 나눴다. 링크 탐색 결과만으로 버튼 검증까지 통과했다고 보고하지 않는다. 네이티브 모달에서 브라우저 주소창으로 이동한 Tab 동작은 페이지의 초점 누출과 구분했다. 브라우저 실행 환경 변수와 건너뛰기 링크 선택자 오류, 최초 재시도 기록도 보존했다. 수정된 검사 입력의 통과와 변경 없는 실패 후 재시도 성공을 같은 최초 성공으로 바꾸지 않았다. QA 병렬 비교의 새 flaky 0은 해당 고정 비교에 한정한다.

## 시간·자원과 측정 한계

검사 명령의 단조 시계 경과시간, QA sidecar의 `wallMs`, 에이전트 실행 기록을 구분한다. 실행 준비, 위임·대기·회수와 사용자 대기를 실제 검사 시간으로 바꾸지 않는다. 병렬 작업 시간을 더해 전체 시간을 계산하지 않는다.

이메일·모션 수정 뒤 고정한 정적 산출물의 같은 경로를 390·1440 너비로 검사했다. QA `clean`을 worker 1과 2로 각각 한 번 실행했으며, 결과 JSON은 정확히 같았다. 각 실행은 예정·실행 2개, 실패·누락·flaky 0개였다.

| 실제 관측 | 직렬 worker 1 | 병렬 worker 2 |
|---|---:|---:|
| QA sidecar 경과시간 | 17,135.23ms | 11,231.24ms |
| 명령 전체 경과시간 | 17,342.16ms | 11,435.75ms |

QA 묶음은 약 34.46% 짧아졌다. 확인용 BTS 설치·린트와 이 비교의 실행 구간은 겹치지 않았다. 검사 범위와 탐지 결과가 같고 수용 기준을 넘었으므로 해당 프로젝트의 QA worker 2를 수용한다. 전체 프리셋 제작 시간이나 다른 호스트의 단축률은 아니다.

첫 정상 빌드는 10.78초, 첫 정적 내보내기는 19.86초에 통과했다. 뒤늦게 발견한 이메일 검증과 모션 수정으로 입력이 바뀌어 영향받은 빌드 7.49초·내보내기 19.66초를 다시 실행했다. 이는 같은 통과 입력을 반복한 것이 아니다. 마지막 생성 경로 제거 뒤에는 영향 타입 검사의 오래된 경로 참조를 공식 `next typegen`으로 갱신했고, 실패한 타입 검사와 변경에 영향받은 빌드를 다시 확인했다. 이때 빌드는 8.18초였다. 삭제 파일 일부가 내보내기 복사 입력에 들어 있어 영향 내보내기도 별도 실행해 21.24초에 통과했다. 다만 코드 전문 검토를 무거운 검사 앞에 배정했다면 재작업을 줄일 여지가 있었으며, 그 절감 시간을 실측했다고 주장하지 않는다.

초기 원위치 BTS 생성은 약 5.6초였다. 앞선 경로 오류와 임시 staging 복구를 별도 기록했다. 최초 템플릿 설치의 최종 runner 종료 코드·단일 경과시간은 회수하지 못했다. 설치 뒤 상태 검사 통과를 그 명령의 종료 코드로 대신하지 않는다.

자원 guard는 해당 프로젝트와 등록한 관리 경로만 측정했다. 초기 설치 패키지의 논리 용량은 747,678,689바이트였다. 하드링크·공유 store 때문에 이를 삭제 시 확보되는 공간으로 표현하지 않는다. 마무리 빠른 측정은 프로젝트와 명시 등록한 확인 폴더를 함께 보아 관리 합계 1,895,760,716바이트, 캐시 346,728,496바이트, 설치 환경 1,499,760,468바이트, 실제 여유 공간 300,220,149,760바이트로 `ok`였다. 이 합계에는 별도 BTS 확인 환경이 포함되므로 최초 프로젝트 설치량과 같은 범위의 증가 비교로 쓰지 않는다. 과거 정리 사례나 등록하지 않은 프로젝트의 용량을 합산하지 않았다.

제품 제작 전용 세션은 외부 관측 시계로 약 92.5분 실행됐다. 이는 모델 계산 시간이나 구현 시간만을 뜻하지 않으며 기획·위임·검사·증거 정리를 포함한다. 통과한 작업을 보존한 뒤 코디네이터가 세션을 중단하고, 같은 세션에서 팩과 최종 검수만 이어갔다. 원 실행의 종료 코드 1은 이 중단 결과다. 뒤이은 정리 구간은 약 10.1분 관측됐고, 최종 리뷰에서 발견한 실제 경로 회귀를 수정하기 위해 중단·재지시했다. 결함 수정·영향 검사·재검수·보고 구간은 추가로 약 16.85분 관측됐고 정상 종료했다. 각 구간은 준비를 포함한 전체 제작 시간이나 순수 실행 시간으로 쓰지 않는다.

실행 기록의 완전성도 구분한다. CLI JSON 스트림은 뒤쪽 native 명령 일부를 누락해 완전한 도구 호출 기록이 아니다. 실제 명령 결과 파일과 호스트의 수행자 완료 기록을 보완 근거로 사용했다. 측정 파일이 QA JSON을 덮어쓴 한 건은 기존 sidecar 결과로 복구했고, 이후 명령 메타데이터를 별도 파일로 분리해 재실행을 피했다.

다음 실제 작업에서는 지금의 소유권 배정과 선택적 검사를 유지하면서 코드 검토를 첫 빌드 전에 회수하고, 단계 시작·종료와 메타데이터 출력 경로를 처음부터 고정하는 편이 낫다. 별도 규칙·프레임워크를 더할 근거는 없었다.

생성 경로 제거 뒤 내보내기의 컴파일된 CSS·번들은 바뀌었다. 기존 랜딩 소스 해시만으로 최신 결과물 전체가 같은 입력이라고 주장하지 않고, 최신 정적 결과물의 오류와 접근성을 390·1440 너비에서 다시 검사했다. 두 검사 모두 예정·실행 각 두 건, 실패·누락·flaky와 접근성 위반이 없었다. 기존 직렬·병렬 시간 비교를 반복한 검사는 아니다.

최신 ZIP은 35개 파일, 860,127바이트이며 SHA-256은 `35a8e6a51eed56b016a5f7bb8b00aa5327dfad4a30492451c19d5321a934b9df`다. 팩과 바이트 단위로 일치하고 소스 13개·자체 SVG 7개·스크린샷 2개의 대조를 통과했다. 생성 경로 수정 전 ZIP의 검증 기록도 덮어쓰지 않고 보존했다.

프로킷 설치기 변경은 독립 검수에서 승인됐다. 제품의 마지막 독립 재검수는 실제 소비자 제거와 현재 소스·증거 해시, 영향 타입·빌드·내보내기를 대조해 기술 품질을 수용했다. 대조표의 이전 high 보류 기록도 해결 근거로 갱신했다. 지원되지 않는 trusted callback 게이트와 사용자 확인은 계속 분리한다. 현재 CLI에는 실제 `verifyReceipt`·`verifyAuthority` 연결이 없어 자동 최종 권한 게이트는 blocked이며, JSON이나 합성 콜백으로 우회하지 않았다.

실기기·스크린리더, Core Web Vitals, DESIGN 전용 명세 CLI, 최초 설치의 단일 종료·시간과 일부 전역 의존성 변경은 미검증이다. 공개 카탈로그·팩 릴리스·push·배포와 제품 기능 커밋은 하지 않았다. 초기 설치 기준선 커밋만 남겼으며 사용자 확인 전 audit 성공·close를 주장하지 않는다.
