# 슬라이드랩 레퍼런스 충실도 보완과 검증

2026-10-10에 [pptpro.kr](https://pptpro.kr/)를 ego-browser로 다시 조사해 슬라이드랩의 10개 섹션을 보완했다. 원본의 인물·고객사·실적·후기·사진·MP4는 가져오지 않고 자체 문구·가상 예시와 새 생성 자산을 사용했다. 이 기록의 시각 점수는 독립 리뷰어의 주관 평가이며 속도 개선율이나 객관적인 동일도 수치가 아니다.

## 발견한 문제와 수정

| 문제 | 실제 수정 | 확인한 근거 |
|---|---|---|
| 원본의 큰 글자·폰트·색·각진 구조가 다른 스타일로 바뀜 | Outfit·Noto Sans KR, 120px/900 제목, #0A0F0A·#C8FF00, 1320px 컨테이너와 원본 섹션 간격 적용 | 실제 `computed style`과 원본·결과 캡처 |
| 넓은 화면에서도 Hero가 왼쪽 48px에 고정 | 최대폭 1320px·자동 좌우 여백 적용 | 1440/1920/2560px의 제목 x 좌표가 원본과 같은 52.5/292.5/612.5px |
| sticky 프로필이 워크북 앞에 겹침 | 프로필·소개만 별도 grid에 묶고 워크북을 다음 sibling으로 분리 | 수정 전 휠 8개 지점 중 6개 겹침, 수정 후 9개 지점에서는 겹침 없음 |
| 사진·프로필·정보 밀도가 부족 | 생성 이미지 11개, 현장 갤러리 6장, 프로필·워크북, 브랜드 예시 18개, 후기 6개 | 실제 자산 파일·출처 해시·화면 연결 |
| 판매 템플릿이 정적 SVG 3개뿐 | 서로 다른 CSS 모션 슬라이드 10종, 50초 갤러리·90초 후기 흐름·큰 미리보기 | 시간 진행·정지와 미리보기를 실제로 실행 |
| 가로 SVG를 세로 쇼츠에 잘라 사용 | 전용 세로 생성 이미지 4개를 720×1279 WebP로 연결 | 잘린 글자 제거, 세로 카드·기존 설명용 SVG 보존 |
| 내부 디자인 기록이 옛 스타일을 가리킴 | DESIGN.md와 .impeccable/design.json을 현재 시각 기준으로 동기화 | JSON 파싱·필드 검사, 코드 검사 반복 없음 |

생성 자산은 가상 강사 1개, 기업·팀·캠퍼스·온라인·기획 장면 5개, 워크북 1개, 세로 콘텐츠 4개다. 기존 편집 데스크와 입체 슬라이드 이미지도 재사용했다. 새 WebP 11개는 합계 1,035,990바이트다. 이는 파일 용량이며 페이지 속도나 확보 가능한 디스크 공간을 뜻하지 않는다. 프로필·사진은 AI 생성 예시임을 화면에 표시하고 실제 경력이나 행사로 표현하지 않았다. 원본 템플릿의 동영상 대신 기존 Next.js·CSS로 실제 움직이는 슬라이드를 제작했으며 새 프레임워크·패키지를 설치하지 않았다.

## 실제 검증과 재사용

- 정상 빌드 9.50초, 첫 정적 내보내기 20.66초에 통과했다. 정상 빌드 뒤 개발 서버 HTTP 200을 확인했다.
- 10개 너비의 넘침 검사와 데스크톱·모바일 콘솔·요청 검사는 통과했다.
- 최초 axe에서 명암 대비 9개 지점이 실패했다. 관련 네 선택자의 색상만 조정했고, 최신 정적 내보내기 22.33초와 실패한 axe 두 항목만 다시 실행해 위반 0건으로 확인했다. 통과한 타입·넘침·콘솔·기능 검사는 수정 영향이 없음을 확인해 재사용했다.
- 개발 화면과 정적 결과물에서 템플릿 10종·노트 4개·모바일 메뉴·ESC·포커스 복귀·시간과 과정 전달·문의 오류·완료·재입력을 실제 실행했다. 모션 시간 진행·정지·reduced motion도 확인했다.
- 최신 산출물의 HTML 자원 참조 25개가 HTTP 200이며 정적 파일 185개의 해시를 고정했다. 실제 빌드·검사 시간과 제안한 작업을 구분했고, 병렬 시간을 더해 전체 경과시간으로 보고하지 않았다.
- 첫 lint에서는 오류 11개·경고 39개와 수정 기록을 보존했다. 원 수행자가 오류와 경고를 0건으로 고쳤고, 변경 영향이 있는 파일만 검사했다.
- 캡처 도구가 가로 갤러리의 화면 밖 lazy 이미지를 기다린 오류와 Node HTTP 진단 오류는 제품 결함과 구분했다. 가시 영역 준비 조건과 Python 표준 라이브러리 HEAD 검사로 해당 단계만 보완했다. 통과한 빌드·QA를 다시 시작하지 않았다.
- 기존 전체 템플릿 시험, 24개 시나리오 반복 평가, QA worker 성능 비교, 올곧·Claudle의 H 이행은 하지 않았다.

독립 시각 검수는 승인됐으며 미해결 P0/P1은 0건이다. 주관 점수는 첫 판 8.3/10에서 최종 8.8/10, Media는 5.6/10에서 8.7/10으로 평가됐다. 이미 수용한 섹션은 다시 평가하지 않았다. 이 값으로 전체 개발 시간이나 8시간 작업의 단축률을 계산하지 않는다.

## 현재판 항목별 UI 평가

첫 최종 인수는 현재판 audit 항목별 증거가 빠져 `blocked`로 남았다. 이전판 점수나 주관 8.8점으로 통과 처리하지 않고, 설치된 impeccable audit 정본의 다섯 항목을 현재 소스·캡처·실제 실행 증거에 연결했다. 새 빌드나 통과한 QA는 실행하지 않았다.

| 항목 | 점수 | 근거와 평가 한계 |
|---|---|---|
| 접근성 | 3/4 | 현재 axe 위반 0, 키보드·폼 초점·모션 대안. 실기기·스크린리더와 AAA는 미검증 |
| 성능 | 3/4 | WebP·sizes·lazy·rAF·화면 밖 정지·의존성 재사용. CWV·FPS·전체 번들 프로필은 미측정 |
| 테마 | 3/4 | 현재 토큰·DESIGN·내부 기록 일치. 작품별 색상은 일부 리터럴이며 테마 전환은 범위 밖 |
| 반응형 | 3/4 | 너비·넓은 화면 좌표·실제 휠·모바일 메뉴. 물리 터치와 200% 글자 확대는 별도 미검증 |
| 구현 일관성 | 4/4 | detector 지적 0, 실제 자산·현재 소스·증거의 일치, 독립 시각 검수 승인. 전체 픽셀 동일성을 뜻하지 않음 |
| 합계 | 16/20 | 설정의 최소 16/20과 접근성 최소 3/4 충족 |

`audit-current.json`에는 현재 소스 해시, 정본 해시, 항목별 근거와 한계를 기록했다. 이 항목 평가도 실제 성능 향상률을 뜻하지 않는다.

## 스킬·에이전트 보완

두 템플릿의 prokit-ui, prokit-implementer, prokit-reviewer에 레퍼런스 충실도 계약을 연결했다. 사용자가 원본을 선택했으면 다른 스타일 선택이나 브리프 재승인을 반복하지 않는다. 실제 브라우저에서 화면 계층·서체·색·효과·이미지·모션과 수용 위치를 대응시킨다. 넓은 화면의 최대폭·중앙 정렬·좌표, 실제 휠의 인접 섹션·sticky/fixed 경계를 확인한다. 기능 QA만으로 시각 충실도를 수용하지 않는다.

기존 정본에 조건부 문장만 추가했다. 새 스킬·레퍼런스 시스템·감시 서비스를 만들지 않았다. skill-creator 형식 검증과 공유 파일 검사 2건이 통과했고, 이후 본문 두 문장 보완은 형식·링크가 같으므로 결과를 재사용하고 세 공통 파일 쌍의 바이트 일치만 새로 확인했다. 형식 통과를 성능 향상 증거로 사용하지 않는다.

첫 최종 인수는 현재판 필수 평가항목과 audit·a11y 증거를 패킷에서 먼저 대조하는 연결이 없어 `blocked`가 됐다. 이후 누락 증거만 보완하도록 연결했으며, 이는 재검수 범위를 줄이는 절차일 뿐 실제 시간 단축률을 측정한 결과는 아니다.

자동 게이트는 최종 판정과 이전 성공 검사 재사용을 혼동한 `reused` 표시를 거부했으며, 결과 JSON을 수동으로 고치지 않고 현재 artifact/hash를 새로 검토한 최종 판정으로 `reused=false`와 통과를 확인했다.

## 산출물과 한계

프로젝트는 `pro-kit-samples/ws/slidelab`, 정적 HTML은 같은 폴더의 `html/`, 현재 증거는 `tasks/evidence/reference-fidelity/`에 있다. 원본 관측·생성 PNG·프롬프트·이전 실패는 `pro-kit-samples/checks/slidelab-reference-20261010/`에 보존했다. 프리셋 팩은 `pro-kit-samples/packs/slidelab`에 있으며 zip은 해당 checks 폴더의 `slidelab-pack.zip`이다. 로컬 팩의 CRC와 파일별 내용 일치를 확인했다.

최종 관리 CLI 기술 인수 결과는 별도로 아래에 기록한다. 사용자 확인 행은 채우지 않았으며 audit/close·커밋·push·릴리스·카탈로그 등록·배포를 하지 않았다. 실제 서비스의 문의·결제·DB·AI 응답, 실기기·스크린리더·다른 CLI 호스트·완전한 픽셀 동일성은 검증 범위가 아니다.

## 최종 기술 인수 결과

실제 관리 CLI는 `ok=true`, `status=complete`, `technicalAcceptance=complete`로 통과했다. 새 최종 리뷰는 approve·maxSeverity none·findings 0이고 `reused=false`다. 두 번의 blocked 기록은 그대로 보존했다. 필수 audit 증거 누락과 재사용 표시 의미 혼동을 보완했으며, 통과한 UI·빌드·QA는 반복하지 않았다. `[confirm]`은 pending이고 라운드를 닫거나 커밋·배포하지 않았다.

최종 로컬 배포용 팩은 문서 두 파일만 안내를 갱신하고 CRC·파일 전체 일치를 별도로 확인했다. CLI가 고정한 팩과 소스·자산·화면은 같고, 달라진 것은 README.md·CUSTOMIZE.md뿐이다. 팩은 35109167바이트, SHA-256 `29cd38b6306b0481d1f81e165603406b137a4601bd4b984b7c55465c8f18cf6e`다. 이 기계적 안내 갱신을 새 전문 코드 리뷰나 새 CLI 인수 실행으로 표현하지 않는다.
