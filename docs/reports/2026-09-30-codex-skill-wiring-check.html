Codex에서도 별도 검수가 필요했다. 기대 스킬 읽기와 위임은 대체로 작동했지만, 테스트 러너 선행 행의 누락·이동과 실행 환경 제약 오해가 드러났다. 두 템플릿에 최소 보완을 적용하고 재검증했다.

실행 범위와 판정 기준

기존 Claude 평가의 자연어 요청 7개, Supabase DB 사례 1개, 전역 스킬 제외 전·후 2개, DB 재실행 1개로 총 11개 CLI 실행을 확인했다. 기대 스킬 목록은 기존 보고서의 55개 항목을 재사용하고, Supabase에는 7개를 적용했다. 호출·읽기 숫자가 기능·보안·워크플로 완료를 뜻하지 않는다.

  • 메인 JSONL의 실제 명령·출력과 Codex 원시 세션의 서브에이전트 역할·읽기 명령을 대조했다. 파일 이름만 언급하거나 skills_read에 쓰는 것으로 통과시키지 않았다.
  • 프로젝트 외부 스킬은 프로젝트 경로에서 읽었는지, 스킬의 규칙이 코드·테스트·문서에 반영됐는지 확인했다. gstack은 전역 도구여서 프로젝트판 검사에서 제외했다.
  • 사용자 확인 행은 비워 두고 닫기·커밋·push·배포를 하지 않는 평가였다. 따라서 confirm만 남은 audit exit 1은 의도한 중단이다.
  • 각 사례는 독립 복사본·DB·웹 포트를 사용했다. 패키지 설치와 공식 문서 조회는 허용하고 원격 프로젝트 연결·배포는 금지했다.

템플릿에 반영한 수정

  1. 선행 행 보존: dev-cycle --upgrade에서 수동 Vitest 도입 행을 맨 앞에 유지한다. 증거와 메모, 다른 수동 행, 마지막 confirm을 보존한다. 기존 코드에서 실패하는 회귀 테스트로 재현한 뒤 수정했고, 실제 D 평가의 대조표로도 재확인했다.
  2. 진입 단계 보강: D·E·서버/DB 버그 C의 대조표를 연 직후 러너를 확인한다. 기존 코드가 요구를 충족하거나 구현까지만 요청했어도 선행 행을 빼지 않으며, 전역 Bun 실행 파일을 프로젝트 러너로 취급하지 않는다. 설치가 막히면 실제 오류와 의존 작업의 미완료를 남긴다.
  3. Codex 경로 명확화: Skill 도구 대신 프로젝트 SKILL.md 읽기를 명시한다. 구현 대안은 네이티브 bts-implementer, OMX team은 tmux 런타임이 있을 때만 사용한다. 현 OMX가 설치하지 않는 ralph·ultrawork를 옛 전역 스킬에서 고르지 않도록 한다.
  4. 평가 기준 보강: dev-cycle eval 5는 행 존재뿐 아니라 설치·실행 증거, 선행 순서, blocked 전달을 확인한다. 회귀 검사는 두 템플릿 모두 추가했다.

사용자 config.toml과 HOME/CODEX_HOME은 바꾸지 않았다. 임시 프로필에 평가 경로만 trusted로 등록하고 무관한 MCP 서버를 비활성화했다. 복사본의 원래 절대 경로를 담은 훅을 실행하지 않도록 평가에서는 hooks를 껐다. 따라서 훅 활성 상태와 Codex App UI의 동작을 검증한 결과는 아니다.

전역 제외 평가에서는 발견된 전역 스킬 177개를 skills.config의 enabled=false로 끄고 플러그인을 비활성화했다. codex debug prompt-input 결과의 스킬 루트가 프로젝트 .codex/skills와 .agents/skills 두 곳만 남는 것을 확인했다. --ignore-user-config만으로 전역 스킬이 없어졌다고 가정하지 않았다.

기대: bts-dev-cycle, bts-db, supabase-postgres-best-practices, domain-modeling, bts-verify, agent:bts-reviewer, supabase

남은 한계

  • 기본 시나리오는 한 번씩 실행했다. 누락 확률이나 모든 작업에서의 성공률은 산출할 수 없다. 전역 제외 검증도 대표 D 사례에 한정한다.
  • 모든 설치 스킬을 모두 호출시키는 검사가 아니다. 원격 Neon 브랜치, 실제 Vercel 배포, 선택 스킬 묶음 등 요청에 없는 경로는 검증하지 않았다.
  • 성능 분석은 로그인된 대시보드의 깜빡임·운영 성능·캐시 적용 전후를 확인하지 못했다. 익명 접근과 개발 컴파일 측정, 코드 구조 가설로 범위를 제한했다.
  • 인증의 메모리 저장소·신뢰 프록시·IP 헤더 경계는 운영 전 추가 결정이 필요하다. 코드·보안 리뷰가 한계를 기록했으므로 로컬 기능 검증을 운영 안전성 보장으로 해석하지 않는다.
  • UI는 빈 목록·실제 항목과 네트워크 오류를 확인했지만 완료 항목 수는 응답 대체로 확인했다. 라이트 테마·스크린리더·극단적 큰 수까지 확인한 것은 아니다.
  • DB 테스트가 API 경로에 추가되면 보수적인 판정으로 F(+H)로 상향된다. 이번 실행은 UI 등 무관한 행을 사유 있는 N/A로 기록했다. 분류 정책은 바꾸지 않았다.
  • audit은 증거 칸과 필수 행을 검사하며 실제 스킬 실행 이력을 증명하지 않는다. 모델의 자기보고를 검증하려면 도구 로그 대조가 계속 필요하다.
  • OMX 생성 설정의 child_agents_md 등 일부 오래된 키는 Codex가 무시한다는 경고가 있었으나, bts-implementer·bts-reviewer 실제 역할 호출은 확인했다. 사용자 전역 설정은 수정하지 않았다.
  • 원시 로그·측정 스크립트·평가 프로젝트는 저장소 밖 임시 경로에 두었다. 저장소에는 이 보고서와 VERIFICATION의 요약만 남긴다.
