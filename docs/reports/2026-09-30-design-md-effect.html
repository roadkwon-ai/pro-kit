무엇을 어떻게 쟀나

  • 대상: 템플릿을 설치한 BTS 프로젝트 사본 8개(서비스 4개 × 조건 2개). 서비스마다 PRODUCT.md와 화면 브리프 2개(첫 화면, 두 번째 화면)를 미리 써 두고 두 조건에 똑같이 넣었습니다. 브리프에는 시각 스타일을 적지 않았습니다.
  • A: 첫 턴에서 bts-ui가 카탈로그 1~3위를 추천하고 멈춤 → 사용자가 고름 → 원문을 받아 DESIGN.md로 저장·lint → 첫 화면 구현. 두 번째 화면은 새 세션에서 구현.
  • B: 같은 브리프로 "<브랜드> 느낌으로, 대표 색은 <hex>"라고 요청. 카탈로그와 DESIGN.md는 쓰지 않게 했습니다. 두 번째 화면도 새 세션에서 같은 말로 요청.
  • 공통: claude -p, Opus 5.5. 두 조건 모두 템플릿의 bts-ui와 impeccable 규칙(토큰만 쓰기, craft floor)을 따릅니다. 측정용이라 dev-cycle 대조표, critique·audit·polish, 리뷰 에이전트, 커밋은 빼고 구현 → 타입·린트 → 스크린샷 확인까지만 시켰습니다.
  • 측정: 각 사본을 프로덕션 빌드(next build, next start)해 Chrome 헤드리스로 1440×900과 390×844 화면을 찍었습니다. 계산된 스타일에서 색, 반경, 글자 크기, 서체를 모아 A가 저장한 DESIGN.md 토큰과 비교했습니다(B는 같은 브랜드의 같은 파일과 비교). axe-core(WCAG 2.2 AA), impeccable detect, 코드의 원시 색 값도 셌습니다.
  • 블라인드 평가: Opus 5.5에게 두 조건의 스크린샷(첫 화면 데스크톱·모바일, 두 번째 화면 데스크톱)을 X, Y로만 보여 주고 목표 DESIGN.md와 브리프를 기준으로 5개 항목을 1~10점으로 매기게 했습니다. 좌우를 바꿔 서비스마다 두 번, 모두 8번 돌렸습니다.

찾은 결함과 고친 것

고침

추천 글이 대표 색을 원문과 다르게 적었다

Uptrail 추천에서 Vapor의 대표 색을 "거의 검정(#171717)"이라고 적었는데, 원문의 브랜드 primary는 Blue 500(#2A72E5)이었습니다. 사용자는 이 설명을 보고 대표 색을 정합니다. impeccable-map.md 2단계에 "대표 색과 서체는 후보 원문에서 확인한 값으로 적는다. colors.primary가 없으면 본문 Colors 절이 브랜드 색이라고 한 값을 적는다"를 더했습니다. 측정에서는 B에 준 색 힌트를 바로잡아 다시 돌렸습니다.

고침

새 글자 크기 토큰 이름이 cn()에서 지워진다

같이살림 A 실행이 찾았습니다. --text-body-md 같은 새 이름을 만들면 cn()(tailwind-merge 방식)이 text-body-md를 글자색으로 보고, 같은 요소의 색 클래스와 겹칠 때 지웁니다.

cn("text-body-md text-muted-foreground")  →  "text-muted-foreground"
cn("text-sm text-muted-foreground")       →  "text-sm text-muted-foreground"

impeccable-map.md 5단계(적용)에 글자 크기는 Tailwind 기본 이름의 값을 바꾸라고 적었습니다.

관찰

1위가 토스로 몰렸다

한국어 서비스 4개 중 3개(생활비 정산, 수업 예약, 학습 플래너)에서 토스가 1위였습니다. 이유(금액·숫자를 크게, 버튼 하나)는 저마다 타당했고 2·3위에는 분야가 맞는 후보(쏘카, 팀스파르타, 코드잇)가 들어왔습니다. 규칙은 바꾸지 않고 기록만 합니다.

측정 환경

사본에 초기 포맷 정리가 빠져 있었다

측정용 사본을 만들 때 설치 절차 8번의 pnpm check를 빠뜨려 작업 전부터 biome 오류가 85건 있었습니다. 실행마다 저장소 전체를 포맷하거나 그대로 두는 등 대응이 달라 비용과 시간에 잡음이 섞였습니다. 코드 지표는 공백 변경을 빼고(git diff -w) 화면 코드(apps/web/src)에서만 셌습니다. 템플릿 결함은 아닙니다.

한계

  • 서비스 4개, 조건마다 한 번씩만 돌렸습니다. 한 기기, neon 템플릿, Opus 5.5에서만 쟀습니다.
  • B는 브랜드 이름과 대표 색 hex까지 받은 강한 기준선입니다. 아무 말 없이 만드는 경우와는 비교하지 않았습니다.
  • 리뷰와 polish를 뺐습니다. 실제 라운드에서는 critique·audit·polish가 두 조건의 차이를 줄이거나 키울 수 있습니다.
  • 팔레트 일치율은 팔레트가 넓을수록 쉽게 높아집니다(Vapor 223색). 그래서 서체, 글자 크기, 반경, 블라인드 평가를 함께 봤습니다.
  • 평가자는 사람이 아니라 Claude입니다. 원문과 스크린샷을 보고 판단했고 실제 사용자 과업 시간은 재지 않았습니다.
