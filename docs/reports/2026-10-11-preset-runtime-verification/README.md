# 캐시 일시 완화와 실제 실행 검증

## 캐시 차단의 의미

기존 자원 helper의 기본 빌드 캐시 차단 기준은 40GiB다. pro-kit-web에서 별도로 실행한 측정은 캐시 합계 약 48.23GiB에서 `block`을 반환했다. 큰 비중을 차지한 `.turbo/cache`에는 압축 결과물과 manifest가 쌓여 있었다.

앞선 기록의 캐시 차단은 빌드 명령이 자동으로 자원 helper를 호출했다는 뜻이 아니다. 별도 자원 검사 결과를 보고 Main이 추가 빌드를 보류한 것이며, 실제 정식 build 명령은 미게시 public 자산 사전 검사에서 먼저 차단됐다. 자원 보호와 공개 보류 검사는 서로 다른 경계다.

## 일시 완화와 격리

사용자의 일시 완화 요청에 따라 이번 검증 프로세스에만 캐시 차단 기준 64GiB를 전달했다. 총량과 여유 공간의 기존 기준을 유지했으며 원본 `.dev-cycle.json`과 기본 정책은 바꾸지 않았다. 원본의 캐시·환경·개발 서버도 삭제하거나 종료하지 않았다.

검증용 복사본에는 기존 `.turbo`·`.next`·설치 환경과 비밀 환경 파일을 복사하지 않았다. 설치된 의존성을 링크로 재사용하고 필요한 기존 환경값은 자식 프로세스에만 전달했다. pnpm의 공유 task-state 제한과 자동 의존성 확인을 격리본에서만 조정했으며 준비 실패 기록도 보존했다.

진단용 원본 컴파일 명령을 로컬에서 실행했다. 공개 상태는 계속 `published:false`이고 정식 게시 사전 검사는 그대로다. 진단 결과물은 미게시 원시 public 자료를 포함하므로 배포용 인수 결과물로 취급하지 않는다.

## 실제로 발견하고 고친 결함

첫 실제 컴파일은 통과했지만 페이지 생성 중 `/tutorials` 구성이 실패했다. 프리셋 가시성 검사가 `samples/README.md`, `refine.md`, `real-service.md`까지 프리셋으로 해석해 소개 문서를 숨겼다.

기존 공통 분류 함수에서 등록된 프리셋에만 공개 상태를 적용하도록 고쳤다. 일반 튜토리얼 문서는 유지하고 미게시 프리셋은 개발에서만 표시한다. 기존 unknown 프리셋 등록 검사는 유지했으며 관련 회귀 검사와 형식 검사가 통과했다.

## 실행 결과

| 검사 | 실제 결과 |
|---|---|
| 수정 후 컴파일·TypeScript·페이지 생성 | 정상 종료, 118페이지, 명령 전체 약 10.2초 |
| 로컬 production 서버 | `127.0.0.1:3021`에서 실제 산출물 기동 |
| 공개 경로 | 홈·튜토리얼·소개·다듬기·실제 서비스·관리 문서·올곧 상세 7곳 HTTP 200 |
| 미게시 경로 | 슬라이드랩 상세·교재 2곳 HTTP 404, 목록 카드 비노출 |
| 관련 브라우저 검사 | 두 경로·두 너비, 4/4 실행, 오류·누락·flaky 0 |
| 문서 메뉴 | 열기·닫기와 초점 복귀, 작은 화면 넘침 없음 |
| 자원 감시 | 실행 전후 warn, 예산 초과 없음 |
| 서버 수명 | 검증 후 소유 서버 그룹 정상 정리. guard의 수동 종료 코드는 실행 실패와 구분 |

통과한 과거 전체 평가와 QA는 반복하지 않았다. 처음의 준비 실패와 실제 페이지 생성 실패를 보존하고 실패·수정 영향 범위만 다시 실행했다. 이 실행 시간은 전체 개발 속도 개선율이 아니다.

## 증거와 한계

원시 기록은 `pro-kit-samples/checks/preset-runtime-20261011/`의 준비·실패·최종 빌드, production HTTP, QA sidecar, 메뉴 상태, 자원·서버 수명에 있다. 독립 검수 결과와 현재 계약 해시는 같은 폴더에서 확인한다.

최초 페이지 생성 실패의 전체 로그 파일은 후속 변경 입력 실행에서 덮여 남아 있지 않다. 원래 도구 응답에 남은 오류 구간·종료 코드·실행 시간을 `build-compiler-failure-transcript.json`으로 전사해 보존했다. 이것은 전체 원시 stdout과 구분한다. 최종 통과 빌드와 서버·QA 로그는 실제 파일로 보존했다.

임시 완화는 프로세스 종료로 끝났다. 원본 정책 해시가 그대로이며 기본 기준으로 재측정하면 기존 캐시는 여전히 block이다. 캐시가 정리됐거나 앞으로 비대해지지 않는다고 주장하지 않는다. 원본의 개발 서버는 유지했다.

Vercel·Pages 배포, 공개 팩 발행, push와 사용자 confirm은 실행하지 않았다. 실기기·Safari·전체 사이트 상호작용은 재검증하지 않았다. 기존 스킬 분리와 게시 보류 검수 범위는 [앞선 보고서](../2026-10-11-preset-skills/README.md)에 있다.
