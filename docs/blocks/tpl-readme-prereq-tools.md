- Vercel CLI({{v:cli.vercel.installCode}})와 Vercel 계정: develop·production 배포([Vercel 배포](#vercel-배포)). 배포하지 않으면 없어도 된다.
- 브라우저 검증: [ego lite](https://lite.ego.app/)(macOS)를 먼저 쓴다. 설치한 뒤 앱에서 첫 실행 설정을 마치면 `ego-browser` 명령과 전역 `ego-browser` 스킬이 생긴다. 스크린샷을 찍는 동안 ego lite 창이 화면에 보여야 한다. ego lite를 쓸 수 없는 환경(Windows·Linux, CI, Codex 샌드박스, 창을 띄울 수 없을 때)과 React 내부 상태 확인에는 agent-browser CLI를 쓴다. 설치기가 {{v:policy.agentBrowser.da}}(`npm install -g agent-browser@latest && agent-browser install`. Homebrew로 설치했으면 `brew upgrade agent-browser`). agent-browser 스킬 본문은 CLI가 주므로(`agent-browser skills get core`) CLI 판이 곧 스킬 판이다. 태그 없이 설치하면 Node 24 미만 npm이 0.27.0을 고르므로 `@latest`를 붙인다. npm 레지스트리에 닿지 않으면 next-dev-loop 하한 0.31.1로 검사한다.
- 설치기가 프로젝트 scope에 자동으로 넣는 것: 공식 스킬, mattpocock `domain-modeling`·`grilling`·`grill-with-docs`, skill-creator(Claude 플러그인과 Codex 스킬)다. 두뇌(superpowers, agent-skills(addyosmani), pstack, gstack, OMC·OMX, mattpocock, OpenSpec, Spec Kit, Compound Engineering. 여럿을 고르면 첫 두뇌가 주 두뇌)와 과설계 방지 스킬(ponytail, caveman, karpathy)은 고른 것만 설치하고 기본은 없음(기본 AI)이다. 목록 정본은 `files/skills.manifest.json`, 고르는 기준은 `.agents/skills/prokit-dev-cycle/references/brains/README.md`, 단계별 선택은 `process-routing.md`가 정한다. ponytail을 고르고 `--with-global`일 때만 Ponytail 원본 GitHub marketplace와 Codex 네이티브 플러그인 설치를 시도한다. CLI가 없거나 이 명령을 지원하지 않으면 프로젝트 스킬로 계속하고, 실제 설치 명령이 실패하면 exit 2로 멈춘다. 기본 설치와 `pnpm skills:check`에서는 네이티브 플러그인이 없어도 선택 상태로 표시한다.
- ponytail을 고르면 Claude 플러그인이 훅 3개(SessionStart, SubagentStart, UserPromptSubmit)로 세션과 서브에이전트에 과설계를 막는 규칙을 넣는다. 상태는 `CLAUDE_CONFIG_DIR` 또는 `~/.claude` 아래에 두며, `CLAUDE_PROJECT_DIR`이 있으면 프로젝트 hash별 모드와 공유 플래그를 쓴다. 없으면 shared 상태를 쓴다. 같은 저장소의 세션은 모드를 함께 쓰므로 `stop ponytail`도 함께 적용된다. 전역 helper 파일을 쓸 수 있지만 statusline 설정은 사용자가 원할 때만 바꾼다. 고르지 않았는데 전역에 켜져 있으면 설치기가 `.claude/settings.local.json`의 `enabledPlugins`에 `"ponytail@ponytail": false`를 넣어 이 프로젝트에서만 끈다(다른 고르지 않은 두뇌 플러그인과 impeccable과 같은 일을 하는 `frontend-design` 플러그인도 같다). Codex 네이티브 플러그인의 상태는 `PLUGIN_DATA`에 있고, 훅은 trusted 프로젝트에서 `/hooks`로 허용한 뒤 새 세션부터 확인한다. 신뢰와 훅 허용은 별개다. 시작 훅의 대략적 코드 지도는 재사용 후보를 찾는 참고 자료다. 실제 코드·호출자·테스트·설정·내보내기는 직접 확인한다.
- `ponytail-review`는 일회성 읽기 전용 리뷰다. `/ponytail-review`도 세션을 영구 review 모드로 바꾸지 않는다. `ponytail-audit`·`ponytail-debt`·`ponytail-help`·`ponytail-gain`도 요청할 때만 읽는다. 이들은 매 라운드 의무 검사나 자동 장부·백로그 수정이 아니며, `gain`은 upstream benchmark이지 이 프로젝트의 절감 측정값이 아니다. 새 제한은 `shortcut:` 주석에 남기고, 기존 `ponytail:` 주석은 지우지 않고 필요할 때 debt와 함께 모은다.
- 전역에만 설치되는 도구: agent-browser CLI, Vercel CLI, {{cli}}, ego lite. 기본 실행에서도 {{v:policy.agentBrowser.da}}(실패하면 경고만 하고 계속한다). 나머지는 기본 실행이 없는 것과 설치 명령만 알려 주고, `--with-global`을 주면 ego lite를 뺀 나머지 중 없는 것만 전역 설치한다. 두뇌 gstack(upstream이 전역 설치만 지원한다. Claude·Codex 모두), OMX CLI(`oh-my-codex`), OpenSpec CLI(`@fission-ai/openspec`)는 그 두뇌를 `--brain`으로 고를 때 전역에 설치한다(gstack은 bun이 필요하고 `./setup`이 `~/.claude/settings.json`에 전역 훅을 등록한다{{tail|}}). Spec Kit은 전역 설치 없이 `uvx`로 프로젝트에 설치하므로 uv가 있어야 한다. 모두 없어도 dev-cycle은 process-routing의 기본(기본 AI) 절차로 진행된다.
