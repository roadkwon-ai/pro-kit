2. `pnpm check`로 Better-T-Stack이 만든 코드의 포맷과 정렬(import, Tailwind 클래스)을 한 번 정리하고 `pnpm exec biome check .`가 exit 0인지 확인한다. 다시 생성되는 파일(마이그레이션, `schema/auth.ts`, varlock의 `src/env.ts`)과 `pnpm export:html`이 만든 `html/`은 설치기가 `biome.json` 검사 대상에서 뺐다. 마크다운 파일(`**/*.md`)도 뺐다. Biome 2.6의 마크다운 포맷이 `tasks/todo.md`의 대조표와 `AGENTS.md` 표를 매번 바꿔 lint가 실패해서다. shadcn의 `label.tsx`·`input-group.tsx`는 upstream 코드라 두 파일에서만 a11y 규칙 3개를 껐다. 설치된 turbo가 2.11.5 이상이면 설치기가 `turbo.json`에 `"agentGuidance": false`를 넣는다. turbo가 AI 에이전트를 감지하면 루트 `AGENTS.md`에 규칙 블록을 쓰고 커밋해 두라고 지시하기 때문이다. 2.11.4 이하는 이 키를 거부하므로 넣지 않는다(나중에 turbo를 올리면 `prokit-skills-update`의 turbo 절). 설치기는 `turbo.json`의 `globalPassThroughEnv`에 프록시 변수(`HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`와 소문자판 세 개)도 넣는다. turbo의 엄격 환경 변수 모드가 이 변수를 작업에 넘기지 않아, 프록시 뒤(회사망, Codex 샌드박스)에서 빌드의 `next/font/google` 받기가 실패해서다. 이미 `globalPassThroughEnv`가 있으면 고치지 않고 빠진 변수를 직접 더하라고 알린다. 이어서 설치 결과, 포맷 정리, {{dir|}}첫 마이그레이션을 기본 브랜치(`main` 또는 `master`)에 커밋한다. 커밋하지 않고 첫 라운드를 열면 설치한 파일 전체가 라운드 diff에 섞여 `audit`이 케이스 F 상향을 요구한다. 기능 브랜치에 커밋해도 마찬가지다. 라운드 기준이 기본 브랜치와의 merge-base이기 때문이다.
