# 게슈탈트 원칙 기반 UI 개선 지침

> AI가 화면(앱·웹·문서)을 진단하고 고칠 때 따르는 규칙.
> 전제: 사용자는 글을 읽기 전에 화면을 **덩어리**로 먼저 본다. 잘 만든 화면은 설명 문구가 없어도 구조가 전달된다.
> 모든 원칙의 뿌리는 **단순성(Prägnanz)** 이다. 뇌는 보이는 것을 가장 단순하고 안정적인 형태로 해석한다.

---

## 0. 고치기 전에 확인할 것

화면마다 아래 세 가지를 먼저 정한다. 주어지지 않았으면 화면 내용에서 추론하고, 추론한 내용을 보고에 적는다.

- **목적**: 이 화면에서 사용자가 하려는 일
- **주인공**: 가장 중요한 요소 1개 (예: 주요 버튼, 핵심 정보)
- **의도한 그룹**: 같이 묶여 보여야 하는 요소들과 그 개수

---

## 1. 작업 순서

1. **덩어리 세기**: 화면을 흐리게 볼 때 덩어리가 몇 개로 보이는지 센다. 0단계에서 정한 의도 그룹 수와 비교한다.
2. **원인 찾기**: 의도와 다르게 묶여 보이면 **강한 신호부터** 의심한다.
   - 선·박스 → 색·모양 → 간격 순서로 본다.
   - 박스나 선이 간격과 반대로 묶고 있는 경우가 많다.
3. **고치기**: 의심과는 반대로 **약한 수단부터** 쓴다.
   - 간격 → 색·모양 → 박스 → 선 순서로 시도한다.
   - 간격으로 해결되면 박스를 추가하지 않는다.
4. **재점검**: 4절 점검표로 확인하고 5절 형식으로 보고한다.

### 원칙 간 힘의 세기

```
연결성 · 공동 영역  >  근접성 · 유사성
(선으로 잇기, 박스로 감싸기)   (간격, 색·모양)
```
- 강한 신호가 약한 신호를 이긴다. 간격이 가까워도 박스가 다르면 다른 그룹으로 보인다.
- 약한 수단으로 해결되지 않을 때만 강한 수단을 쓴다. 선과 박스를 남발하면 화면이 무거워진다.

### 화면 유형별로 먼저 볼 원칙

| 화면·요소 | 먼저 볼 원칙 |
|-----------|-------------|
| 프로필 수치, 폼(라벨-입력칸) | 근접성 |
| 버튼이 여러 개, 선택지·태그·아이콘 목록 | 유사성 |
| 설정 화면, 정보 묶음 | 공동 영역, 근접성 |
| 진행 단계, 배송·주문 상태, 타임라인 | 연결성 |
| 가로 스크롤 목록, 캐러셀, 피드 | 연속성 |
| 업로드 영역, 빈 슬롯, 플레이스홀더 | 폐쇄성 |
| 팝업, 바텀시트, 이미지 위 텍스트 | 전경과 배경 |
| 다중 선택, 일괄 편집 | 공동 운명 |

## 2. 원칙별 규칙

### 01 근접성 (Proximity): 가까이 붙어 있으면 한 묶음

**위반 신호**
- 모든 요소 사이 간격이 똑같아서, 라벨이 어느 숫자나 입력칸에 딸린 것인지 헷갈린다.
- 아이콘·라벨·도움말이 두 칸 사이 정중앙에 떠 있어서 어느 칸 소속인지 모호하다.
- 제목과 목록, 소제목과 항목이 같은 간격으로 붙어 있어서 구분되지 않는다.

**개선 규칙**
- 그룹 안쪽 간격은 좁게, 그룹 사이 간격은 넓게 잡는다. 최소 2배 차이를 둔다 (예: 안쪽 8px / 바깥 24px).
- 라벨·제목은 자기가 설명하는 요소 쪽에 더 가깝게 붙인다.
- 화면이 어수선하면 박스를 그리기 전에 간격부터 고친다.

**AI 지시문**: "관련 있는 건 간격을 좁히고, 그룹과 그룹 사이 간격은 2배로 넓혀줘."

### 02 유사성 (Similarity): 색·모양·크기가 비슷하면 같은 종류

**위반 신호**
- 같은 기능의 버튼이 화면마다 색이나 모양이 다르다.
- 위험한 버튼('삭제', '해지')이 '취소'와 똑같이 생겨서 실수로 누르기 쉽다.
- 성격이 다른 요소(단일 선택과 토글 설정, 라벨 칩과 일반 텍스트)가 같은 모양이다.
- 같은 목록인데 아이콘 스타일(선, 이모지, 3D)이 제각각이다.
- 같은 급의 선택지 중 하나만 다른 모양이라 덜 중요해 보인다.

**개선 규칙**
- 같은 일을 하는 요소는 색·모양·크기를 통일한다. 색뿐 아니라 **모양**도 같은 종류라는 신호다 (같은 동그라미 = 같은 종류).
- 가장 중요한 요소 **하나만** 다르게 만든다 (고립 효과). 전부 다르면 아무것도 튀지 않는다.
- 위험한 동작, '다음 단계' 버튼은 다른 요소와 확실히 다른 모양으로 만든다.
- 같은 급의 선택지는 같은 틀로 맞춘다 (예: 모두 '왼쪽 이미지 + 오른쪽 글자').
- 선택된 상태는 채움색처럼 한 가지 일관된 방식으로 표시한다.
- 목록 안의 아이콘은 한 가지 스타일로 통일한다.

**AI 지시문**: "같은 기능의 버튼은 색·모양을 통일하고, 제일 중요한 버튼 하나만 다르게 해줘."

### 03 공동 영역 (Common Region): 같은 테두리·배경 안이면 한 그룹

**위반 신호**
- 카드 안에 카드, 그 안에 또 카드가 들어 있다 (3겹 이상).
- 같은 목록인데 항목마다 박스를 따로 씌워서 서로 다른 덩어리로 보인다.
- 카드 경계가 흐리거나 겹쳐서 어디까지가 한 묶음인지 모호하다.

**개선 규칙**
- 간격만으로 묶음이 보이지 않을 때 카드나 배경을 쓴다.
- 관련 설정끼리 둥근 카드 하나로 묶는다 (iOS 설정의 그룹 리스트 방식).
- 서로 관련 없는 기능은 카드를 따로 쓴다.
- 상자는 한 겹이면 충분하다. 중첩하지 않는다.

**AI 지시문**: "관련 설정끼리 둥근 카드로 묶어줘. 카드 안에 카드는 넣지 마."

### 04 연결성 (Uniform Connectedness): 선으로 이어지면 하나 (가장 강함)

**위반 신호**
- 진행 단계가 선 없이 떨어진 점이나 막대로 표시된다.
- 단계 표시가 탭 메뉴처럼 생겨서 눌러야 하는 메뉴로 오해된다.
- 단계가 끊어진 조각으로 나뉘어 하나의 흐름으로 보이지 않는다.

**개선 규칙**
- 순서가 있는 요소는 선으로 잇는다 (스텝 인디케이터, 타임라인, 배송 단계, 노선도).
- 지난 구간은 진하게, 남은 구간은 연하게 칠해서 현재 위치가 한눈에 보이게 한다.
- 아직 오지 않은 단계는 빈 동그라미와 회색 글자로 표시하되, 연결선은 유지한다.
- 점과 선을 떼어 놓지 않는다.

**AI 지시문**: "단계 표시를 점과 선으로 이어서 진행 상황이 한눈에 보이게 해줘. 완료 구간은 진하게, 남은 구간은 연하게."

### 05 연속성 (Continuity): 눈은 선과 줄을 따라 이어서 본다

**위반 신호**
- 가로 스크롤 목록인데 카드가 화면 끝에 딱 맞게 끝나서 더 있다는 걸 모른다.
- 사진 한 장이 화면을 꽉 채우고, 넘김 단서(작은 점)가 너무 작아 놓치기 쉽다.
- 글자나 카드의 왼쪽 끝이 들쑥날쑥하다.

**개선 규칙**
- 줄을 맞춘다. 글자와 카드의 왼쪽 끝을 하나의 기준선에 정렬한다.
- 옆으로 넘기는 목록은 마지막 카드가 화면 끝에서 살짝 잘려 보이게 한다 (폐쇄성과 함께 작동).
- 한 줄에는 한 카테고리만 둔다. 줄이 이어지는 동안은 같은 주제로 읽힌다.

**AI 지시문**: "가로 스크롤 목록은 마지막 카드가 살짝 잘리게 보여줘."

### 06 폐쇄성 (Closure): 빈틈이 있어도 뇌가 채워서 완성한다

**위반 신호**
- 빈칸이 회색 네모로 꽉 차 있어서 '빈자리'인지 '로딩 중'인지 구분되지 않는다.
- 업로드 영역에 경계(점선이나 테두리)가 없어서 어디에 놓아야 할지 보이지 않는다.
- 업로드 버튼만 있고 결과가 들어갈 자리 모양이 없다.

**개선 규칙**
- 다 그리지 않아도 된다. 점선, 반만 보이는 카드, 단순한 아이콘이면 충분하다.
- 빈자리는 **점선 테두리 + 가운데 + 아이콘**으로 "여기 채우세요"를 표시한다.
- 단서가 하나도 없으면 뇌도 채우지 못한다. 최소한의 경계는 남긴다.

**AI 지시문**: "업로드 자리는 점선 테두리로 비워두고 가운데에 + 아이콘을 넣어줘."

### 07 전경과 배경 (Figure–Ground): 앞에 있는 것과 뒤에 깔린 것

**위반 신호**
- 팝업이나 바텀시트를 띄우면서 뒤 화면을 그대로 밝게 둔다.
- 사진 위 글씨가 복잡한 배경에 묻힌다.
- 시트와 뒤 화면이 같은 색이라 같은 층처럼 보인다.

**개선 규칙**
- 팝업이 뜨면 뒤 화면을 어둡게 깐다. 밝은 테마에서는 회색으로 덮거나 흐리게 처리한다.
- 사진 위 글씨에는 받침을 깐다 (사진 아래쪽을 어둡게, 또는 글씨 뒤에 상자).
- 시트는 둥근 위 모서리와 손잡이 바로 '위에 떠 있는 층'임을 표시한다.
- 주인공은 한 번에 하나만 둔다. 지금 해야 할 일은 전경에만 둔다.

**AI 지시문**: "팝업 뜰 때 뒤 배경은 어둡게 깔아서 팝업만 눈에 띄게 해줘."

### 08 공동 운명 (Common Fate): 같이 움직이거나 같이 변하면 한 그룹

**위반 신호**
- 선택해도 작은 체크박스 하나만 바뀌어서 뭘 골랐는지 다시 찾아야 한다.
- 체크 표시가 작고 흐려서 사진 위에 묻힌다.
- 관련 요소들이 서로 다른 타이밍에 움직인다.

**개선 규칙**
- 같이 고른 항목은 같이 변하게 한다. 색·크기·체크를 함께 바꾼다 (예: 살짝 작아지면서 체크가 붙음).
- 선택된 항목과 선택되지 않은 항목이 한눈에 구분되게 한다.
- 선택에 맞춰 관련 액션 바(공유·삭제)와 개수 표시가 함께 나타나게 한다.
- 움직이는 타이밍을 맞춘다. 관련 요소는 같은 순간에, 같은 속도로 움직인다.
- 정적인 시안에서는 **선택 상태 스타일**로 대신 표현하고, 애니메이션은 따로 명시한다.

**AI 지시문**: "여러 개 선택하면 선택된 항목들이 같이 살짝 작아지면서 체크가 붙게 해줘."

## 3. 코드로 고칠 때 대응 수단

| 원칙 | 주로 바꿀 것 (CSS 기준) |
|------|------------------------|
| 근접성 | `gap`, `margin`, `padding`: 그룹 안 간격과 그룹 사이 간격을 다른 값으로 |
| 유사성 | 공통 클래스·디자인 토큰으로 색·모양 통일, 주요 버튼만 별도 variant |
| 공동 영역 | 그룹 래퍼에 `background` + `border-radius`, 중첩 카드 제거 |
| 연결성 | 단계 사이 연결선(`border-left`나 의사 요소), 완료·미완료 색 분리 |
| 연속성 | 공통 정렬 기준선, 가로 목록은 `overflow-x: auto` + 카드 폭을 화면보다 약간 좁게 |
| 폐쇄성 | `border: dashed` + 가운데 + 아이콘 |
| 전경과 배경 | 오버레이(반투명 어둡게 또는 `backdrop-filter: blur`), 이미지 위 그라데이션 받침 |
| 공동 운명 | 선택 상태 클래스 하나로 색·크기·체크를 동시에 변경, `transition` 값 통일 |

## 4. 최종 점검

**필수 3문항** (원본 기준)
1. 덩어리가 몇 개로 보이나? 의도한 그룹 수와 같은가? (근접성·공동 영역)
2. 같은 일을 하는 것들이 같은 모양인가? 제일 중요한 하나만 튀나? (유사성)
3. 지금 볼 것과 나중에 볼 것이 구분되나? (전경과 배경)

**해당 요소가 있을 때만**
- [ ] 순서가 있는 정보가 선으로 이어져 있나? (연결성)
- [ ] 가로 목록에 '더 있음' 단서가 있나? 왼쪽 끝이 정렬돼 있나? (연속성)
- [ ] 빈자리가 빈자리로 보이나? (폐쇄성)
- [ ] 선택한 항목이 함께 바뀌어 한눈에 보이나? (공동 운명)
- [ ] 고치면서 박스·선·색이 늘어나지 않았나? (단순성)

---

## 5. 금지 사항

- 간격을 정리하지 않고 박스·선부터 추가하기
- 콘텐츠(문구·데이터·순서)를 임의로 삭제하거나 바꾸기
- 근거 없이 "더 세련되게" 식으로 바꾸기
- 지정된 브랜드 색·폰트 무시하기
- 한 화면에 주인공을 둘 이상 두기

```
| ... | ... | ... |

[개선된 결과물]
```
