# PRD 먼저 정하기

> 한눈에: 프로킷은 PRD(만들 서비스를 적은 기획 문서)를 바탕으로 그 프로젝트에 맞는 스킬 구성을 추천하고 개발 환경을 만들어요. **그래서 새 프로젝트는 PRD를 정하는 일부터 시작해요.** 길게 쓰지 않아도 돼요. 누가 쓰는지와 무엇을 할 수 있는지만 있으면 돼요.

## 왜 PRD가 먼저인가요

에이전트는 프로젝트를 만들기 전에 PRD를 읽고 아래를 정해요. 두뇌와 스킬의 차이를 모르는 사용자는 목록만 보고 고르기 어려워요. 그래서 새 프로젝트는 PRD가 없으면 만들지 않아요. 이미 진행하던 프로젝트는 예외예요(아래 "기존 프로젝트라면").

| PRD에서 보는 것 | 정하는 것 |
|---|---|
| 로그인과 저장이 필요한지, 화면만 먼저 볼지 | 템플릿과 화면만 프로젝트 여부. PRD에 DB가 드러나지 않으면 물어봐요 |
| 요구가 얼마나 분명한지, 데이터 정확성·운영 품질·작업 범위 같은 성격 | 진행을 이끄는 두뇌와 mattpocock 추가 스킬 |
| 주 화면이 랜딩·소개처럼 읽고 스크롤하는 공개 페이지인지 | 화면 디자인 보조(taste-skill) |

추천마다 근거로 삼은 PRD 문장이 붙고, 고르는 것은 사용자예요. 묻는 화면과 선택지는 [두뇌와 선택 스킬](../skills/brains.md)에 있어요.

## 무엇을 적나요

꼭 필요한 것은 두 가지예요.

- **누가 쓰나요**: 예: 같이 사는 사람들, 동네 꽃집의 손님과 사장님
- **무엇을 할 수 있나요(핵심 기능)**: 예: 함께 쓴 돈을 적고 월말에 정산할 금액을 본다

아래를 더 적으면 추천이 정확해져요.

- 로그인과 저장이 필요한지, 화면만 먼저 만들지
- 주 화면의 종류: 공개 페이지(랜딩, 소개, 포트폴리오)인지, 일하는 화면(대시보드, 관리, 목록)인지
- 특히 중요한 것: 돈이나 예약처럼 틀리면 안 되는 데이터, 보안·성능 기준, 여러 세션에 걸친 큰 범위
- 이번에 만들지 않을 것

"todo 앱 만들어줘"처럼 이름만 있으면 PRD로 보지 않아요. 누가 쓰고 무엇을 하는지 한두 문장을 더하면 돼요.

빈칸을 채우는 틀이에요. `[ ]` 안만 바꿔요.

```text
[서비스 이름]. [누가 쓰는지]는 [무엇을 할 수 있는지]. [로그인과 저장이 필요해요 / 화면만 먼저 만들어요]. [이번에 만들지 않을 것]은 만들지 않아요.
```

예를 들면 이래요.

```text
동네 꽃집 예약 서비스. 손님은 꽃다발을 고르고 받을 날짜와 시간을 예약해요. 사장님은 날짜별 예약을 보고 준비 완료를 표시해요. 로그인과 저장이 필요해요. 결제는 이번에 만들지 않아요.
```

## 어떻게 주나요

- **요청에 함께 적기**: 프로젝트를 만들어 달라는 요청에 서비스 설명을 붙여요. 화면만 만들기 프롬프트에서는 서비스를 설명한 문장이 PRD예요([빠른 시작: 화면만 만들기](quickstart-screens.md)).
- **파일 경로 주기**: 기획 문서가 있으면 "PRD는 [파일 경로]에 있어"처럼 경로를 적어요([빠른 시작: 서비스 만들기](quickstart-service.md)).
- **스킬로 바로 부르기**: pro-kit 폴더에서 연 Claude Code는 `/prokit-init <PRD 파일 경로나 내용>`, Codex는 `$prokit-init <PRD 파일 경로나 내용>`이에요.
- **프리셋 팩**: 프리셋 팩(<!-- v:gloss.presetPack -->만들 서비스의 화면 구성, 디자인, 예시 데이터, 그림을 묶어 둔 폴더<!-- /v -->, [용어](../../tutorials/reference/glossary.md#만들기))도 PRD로 줄 수 있어요. 튜토리얼의 프리셋이 이 방식이에요. 팩을 받고 쓰는 법은 [프리셋 팩으로 시작하기](quickstart-pack.md)에 있어요.

## PRD가 없으면

새 프로젝트라면 에이전트가 다른 질문보다 먼저 PRD를 달라고 해요. 그래도 주지 않으면 이유를 알리고 프로젝트를 만들지 않은 채 끝나요. PRD를 준비해 다시 요청하면 돼요.

## 기존 프로젝트라면

이미 진행하던 프로젝트(초기 프로젝트, 운영 중인 Next.js, 다른 언어에서 전환)는 PRD가 꼭 있지 않아도 돼요. PRD가 있으면 함께 주세요. 에이전트가 프로젝트를 읽어 분석한 내용과 PRD로 설정을 추천해요. 자세한 흐름은 [기존 프로젝트에 도입하기](adopt.md)에 있어요.

## 만든 뒤에는

받은 PRD는 새 프로젝트의 `docs/prd.md`에 남아 첫 커밋에 들어가요. 작업 폴더에서 시작해 요청에 서비스 설명을 적었다면 `docs/first-request.md`가 그 역할을 해요. 나중에 두뇌를 바꿀 때도 에이전트가 이 파일로 다시 추천해요.
