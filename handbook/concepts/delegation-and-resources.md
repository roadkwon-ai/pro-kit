# 위임과 자원 관리

> 한눈에: 전문 스킬이나 수행자를 쓸 때는 이름만 보고 고르지 않아요. 실제 출처와 내용, 가능한 부작용을 확인하고 승인한 범위 안에서만 맡겨요. **로컬 자원도 현재 작업에 연결한 프로젝트·워크트리·관리 임시 폴더에서만 재고, 확인한 소유권 없이 지우지 않아요.**

## 위임할 때 남기는 근거

`skills.manifest.json`은 설치할 항목의 정본이에요. 실제 수행자를 고르는 허용 목록은 아니에요. 사용자가 명시한 출처, 프로젝트 정본, 실제로 접근 가능한 외부 출처, 검증한 기본 대안을 차례로 확인해요.

선택하기 전에는 실제 내용의 출처, canonical location, 내용 해시, 범위, 의존성, capability, side effect를 확인해요. 같은 이름의 스킬이 여러 곳에 있거나 매니페스트에 적혀 있어도 이 확인을 건너뛰지 않아요. 사용자가 현재 쓸 수 있는 로컬 사용자 지정 스킬, 플러그인, 제공자 참조를 명시했으면 선택 사실을 기록하고 다시 허락을 묻지 않아요. 실행 권한은 늘어나지 않아요.

전문 제공자를 선택한 작업에서만 이 절차를 열어요. 제공자 메타데이터와 선택 기록은 사실을 다시 확인하기 위한 캐시이지 권위가 아니에요. 네이티브가 이름 있는 역할 파일 등록을 지원하는지 먼저 확인하고, 지원하면 정확한 역할을 써요. 지원하지 않으면 검증한 논리 역할과 읽기 전용 텍스트 생산자만 써서 결과를 받고, Main이 승인한 범위를 바이트 단위로 통합해요.

| 역할 | 하는 일 |
|---|---|
| 코디네이터 | 작업 단위, 허용 경로, 선택한 공급자, 완료 조건과 최종 통합을 정해요 |
| `prokit-implementer` | 검증한 전문 공급자를 연결해 승인한 파일만 고쳐요 |
| `specialist-reviewer` | 공급자에 내장 리뷰가 없을 때만 전문 산출물을 읽기 전용으로 확인해요 |
| `prokit-reviewer` | 전체 계약, 증거 해시, 통합 수용 여부를 매번 읽기 전용으로 확인해요 |

작업을 넘기기 전과 받은 뒤에는 변경 스냅샷을 잡아요. 패킷에는 작업 식별자, 상태, 공급자, 허용 경로, 제약, 환경 참조와 지문, 실제 변경, 증거, 리뷰 범위, 미해결 항목, 부작용, 다음 행동을 넣어요. 실제 산출물 해시와 명령 종료 코드가 없는 보고 문구는 증거가 아니에요.

실제 capture artifact는 `tasks/evidence/` 아래에 실행 전과 후를 각각 한 번만 남겨요. 환경·자원 helper 출력은 작업 산출물과 분리해 기록하고, 해시에는 경로·바이트 수·표준 출력 요약을 함께 남겨요. private guard token이나 owner receipt는 직접 읽거나 출력하지 않아요.

`dev-cycle delegation resolve <스킬 참조 또는 상대 경로>`는 실제 스킬 원본의 위치와 내용 해시를 관찰해요. 신뢰한 source inspection과 실제 host adapter가 계약을 현재 실행에 묶지 못하면 inspection-only로 보고하고 exit 1로 막아요. `dev-cycle delegation validate`와 `audit --packet --context`는 패킷의 구조와 증거 데이터를 검사해요. `--context` JSON은 자료이지 Main의 승인 증명이 아니에요. 이 inspection-only 결과가 현재 승인된 읽기 전용 텍스트 위임까지 금지하지는 않아요. 실제 원문에서 의존성·도구·부작용을 확인하고 같은 작업·실행·루트에 연결된 네이티브 수행자가 수락했으면 후보 텍스트를 받을 수 있어요. 확인하지 못한 권한이나 범위 밖 부작용은 계속 차단해요.

최종 게이트는 Main 런타임의 검증된 콜백이나 실제 host adapter가 현재 task·run·제품·증거·공급자·환경·리뷰어 식별자에 묶어서만 허용해요. 그 연결을 증명할 수 없으면 `unknown`이나 `blocked`로 남겨요. 이 경계를 우회하려고 별도 인증 서버나 등록 서비스를 더하지 않아요.

전문 공급자가 자체 리뷰를 제공하면 그 리뷰 범위만 재사용해요. 스킬의 출처·내용, 계약, 리뷰어, 환경 지문이 모두 같은 경우에만 이전 전문 리뷰를 재사용하고, 환경이 달라지거나 확인되지 않으면 새 환경의 검사로 인정하지 않아요. 보안, DB, 계약처럼 빠진 관점만 보완하고, 최종 `prokit-reviewer` 게이트는 재사용하지 않아요. 출처, 범위, 의존성, 부작용을 맞추지 못하면 검증한 대안을 찾고, 없으면 `blocked`로 남겨요. 미검사 작업을 PASS로 바꾸지 않아요. 수정은 원 수행자에게 모아 재지시하고 영향받은 검사만 다시 해요. 외부 워크플로우의 반복 한도를 지키며 추가 재지시는 최대 두 차례예요.

## 관리 범위 안 자원만 다루기

자원 정책의 실행 정본은 `.dev-cycle.json`의 `resources`예요. `roots`에 등록한 경로는 감시 대상일 뿐 자동 삭제 권한이 아니에요. 등록할 때는 `path`, `kind`, `lifetime`을 적고, kind는 `workspace`, `buildCache`, `nextOutput`, `nodeModules`, `pythonVenv`, `managedTemp` 중 하나를 써요. lifetime은 기본 `project`와 `temporary`예요.

측정기는 캐시, Next 출력, Node 의존성, Python 가상 환경, 관리한 임시 폴더를 나눠 봐요. 하드링크는 한 번만 합산하고, 심볼릭 링크는 따라가지 않아요. COW 공유 여부를 알 수 없으면 그 한계를 따로 적어요. `node_modules`와 Python 가상 환경은 정상일 때 다시 쓰며, 활성 개발 서버의 Next 출력과 영구 환경은 지우지 않아요.

| 상황 | 정책 |
|---|---|
| 영구 활성 환경 하나 | <!-- v:policy.resource.environmentWarn -->10GiB<!-- /v -->가 넘으면 정보 경고만 남겨요 |
| 캐시 | <!-- v:policy.resource.cacheWarn -->20GiB<!-- /v -->부터 경고하고 <!-- v:policy.resource.cacheBlock -->40GiB<!-- /v -->부터 실행을 막아요 |
| 관리 대상 합계 | <!-- v:policy.resource.totalWarn -->40GiB<!-- /v -->부터 경고하고, 새 무거운 작업은 <!-- v:policy.resource.totalBlock -->80GiB<!-- /v -->부터 막아요 |
| 파일 시스템 여유 공간 | <!-- v:policy.resource.freeWarn -->20GiB<!-- /v --> 이하면 경고하고 <!-- v:policy.resource.freeBlock -->10GiB<!-- /v --> 이하면 막아요 |
| 빠른 점검 | <!-- v:policy.resource.fastTimeout -->30초<!-- /v -->마다 확인하고, 별도 bounded worker 측정 예산은 <!-- v:policy.resource.fastWorkerTimeout -->10초<!-- /v -->예요 |
| 전체 inventory 점검 | <!-- v:policy.resource.fullTimeout -->5분<!-- /v -->마다 확인하고, 별도 bounded worker 측정 예산은 <!-- v:policy.resource.fullWorkerTimeout -->30초<!-- /v -->예요 |

이 보호는 관리 명령과 등록한 경로에 적용돼요. 직접 실행한 명령이나 다른 프로세스까지 디스크 사용량을 제한하지는 않아요.

환경 재사용은 같은 프로젝트 위치에서 파일 지문과 실제 환경 상태를 확인한 뒤 결정해요. 지문이 같다는 이유만으로 정상이라고 판단하지 않고, Python 가상 환경을 다른 위치로 복사하지 않아요. 재설치 전후 증가도 기록해 필요 없는 중복 설치를 찾아요.

측정한 크기는 삭제 후 확보될 공간이 아니에요. 실행과 임시 출력이 놓이는 파일 시스템의 실제 여유 공간을 별도로 확인해요. HTML 내보내기는 인식한 가상 환경·Python bytecode·등록한 환경과 캐시 경로를 임시 사본에서 제외해요.

정리는 먼저 대상과 이유만 보여 줘요. 실제로 만든 임시 폴더는 생성 핸들, 루트 inode, 실행 수명 종료, 자식 프로세스 종료, 결과 전달을 모두 증명한 경우에만 지울 수 있어요. 작업 범위 밖 경로, 전역 캐시, 영구 환경은 정리하지 않아요.

## 확인과 기록

자원 확인은 측정이 끝까지 되지 않았거나 시간이 끝나면 `unknown`으로 남겨요. 무거운 명령은 실행 전후 상태와 종료 코드를 기록해요. 실패한 측정이나 막힌 실행은 통과로 바꾸지 않고 원인과 다음 행동을 남겨요.

위임은 공급자 내용과 패킷을 검증한 뒤에만 시작해요. 완료 패킷은 허용 경로 밖 실제 변경, 남은 미해결 항목, 허용하지 않은 부작용, 다른 환경 지문, 없는 명령 종료 코드, 다른 산출물 해시를 거부해요. 상세 명령과 종료 코드는 [명령 모음](../reference/commands.md)에서 확인해요.
