# 완성팩 활용과 담당 구분

> 한눈에: 완성팩은 다 만든 프리셋을 내 프로젝트에 되살려 쓰는 묶음이에요. 프로킷은 팩을 받아 복원하고, 내용과 기능을 바꾼 뒤 완성 프리셋과 비교하는 일을 맡아요. **공식 프리셋을 처음 만드는 일은 이 저장소와 사용자 템플릿에 들어 있지 않아요.**

## 완성팩으로 앱을 만들어요

완성팩으로 사용자 앱을 만들 때는 `prokit-pack-use`를 따라요. 팩을 받아 무결성을 확인하고 복원 계획을 검사한 뒤 실제로 복원해요. 개인화<!-- edition:pro -->와 API·DB 연결<!-- /edition --> 뒤에도 완성 프리셋의 화면과 모션을 기준으로 비교해요. 원본 사이트는 다시 조사하지 않고, 스타일도 다시 고르지 않아요.

**받기** → **무결성 확인** → **복원 계획 검사** → **복원** → **개인화** → **완성 프리셋과 비교**

> [!IMPORTANT]
> 팩을 받은 것과 앱에 적용한 것은 달라요. `apply-pack.mjs --check`는 복원 계획과 충돌을 확인하고, 실제 적용 뒤에는 설치·빌드·화면 검사를 해요.

기존 팩에 비교 자료가 없으면 그 부분은 미확인으로 남겨요.

## 복원하고 개인화할 때 지켜요

- **먼저 읽어요**: 팩의 `README.md`, `CUSTOMIZE.md`, `SOURCES.md`와 `preset-manifest.json`(있으면)을 읽고, 버전과 템플릿, Next·pnpm 호환, 화면만 여부를 내 프로젝트 환경과 맞춰 봐요.
- **충돌은 보존해요**: 소스 SHA256·fingerprint와 경로·링크·충돌 검사를 통과해야 적용해요. 충돌한 파일은 그대로 두고 차이와 최소 병합안을 보여 줘요. 검사를 피하려고 manifest를 내 파일에 맞춰 고치지 않아요.
- **덮어쓰지 않는 파일**: `.env*`, `AGENTS.md`, 하네스 설정, 설치한 스킬은 팩으로 덮어쓰지 않아요.
- **복원 다음에 확인해요**: `apply-pack.mjs`는 설치와 빌드를 하지 않아요. 적용한 뒤 의존성 설치, 타입, 빌드, 실행을 따로 확인해요.
- **바꿀 범위만 기록해요**: 팩의 `PRODUCT.md`, `DESIGN.md`, 사이트맵, 자산을 그대로 쓰고 init과 스타일 고르기를 되풀이하지 않아요. 사용자가 요청한 문구, 이미지, 브랜드, 기능만 변경 범위로 기록하고, 사진 비율, 서체, 간격, 모션, 설정은 유지해요.
- **비어 있는 URL은 비워 둬요**: 팩의 가상 콘텐츠와 빈 URL은 개인화용 기본값이에요. 사용자가 준 URL만 해당 설정 칸에 넣고, 비어 있으면 비대화형 카드와 미설정 표시를 유지해요. 임의 링크나 설명 모달로 채우지 않아요.
- **제작용 도구는 넣지 않아요**: 제작용 선택 팔레트, 설정 견본, 프로킷 미리보기 수신기를 내 서비스에 넣지 않아요. 팩에 없는 테마나 언어도 임의로 더하지 않아요.
- **비교는 같은 조건으로 해요**: 같은 경로, 뷰포트, 언어, 테마에서 스크린샷을 비교하고 서체 로딩, 이미지 비율, 모션도 봐요. 사용자가 요청해 바꾼 곳만 허용 차이로 적고, 개인화 밖에서 달라진 자산, 레이아웃, 모션은 회귀로 봐요. 기능·접근성 검사 통과로 시각 비교를 대신하지 않아요.

## 담당 구분

공식 프리셋의 원본 조사, COPY 제작, 원본 충실도 검수, 팩 조립과 프로킷 웹 게시는 비공개 저장소 `pro-kit-preset-skills`의 스킬이 맡고 `pro-kit-web`에서 조율해요. 이 저장소와 일반 사용자 템플릿에는 그 스킬과 역할을 설치하지 않아요. 템플릿 스킬은 그런 요청을 받으면 직접 처리하지 않고 담당으로 넘겨요.

## 기록된 범위만 표시해요

교재의 전체 제작 시간, 팩을 재현할 때의 예상 시간, 실제 관측한 세션 일부는 서로 다른 값이에요. 교재는 기록된 시간이 일부뿐이면 범위와 빠진 단계를 함께 적어요. 비용 해석은 [시간과 비용 읽는 법](../../tutorials/reference/costs-and-keys.md)을 확인해요.

## 자세히

- 팩 받기: `node scripts/pack.mjs <이름>`. 받아 둔 zip은 `--zip <경로>`를 붙여 같은 확인을 거쳐요.
- 복원 계획 검사: `node scripts/apply-pack.mjs --pack <팩 폴더> --project <프로젝트> --check`
- 미게시 팩: `tutorials/packs.json`에서 `published: false`인 팩은 원격으로 받지 않아요. 가진 zip을 `--zip`으로 검증하고, 파일이 없거나 sha256이 다르면 원격 최신판으로 바꾸지 않고 결과를 보고해요.
- 팩 설정 적용 기준: 템플릿의 `prokit-ui/references/preset-settings.md`
- 재사용·설정 판단: 기술 구현에 들어가기 전에 템플릿의 `prokit-dev-cycle/references/reuse-design.md`로 정하고 `prokit-reviewer`(plan)로 검토해요.
- 완성 프리셋과 비교: 템플릿의 `prokit-verify/references/pack-baseline.md`
