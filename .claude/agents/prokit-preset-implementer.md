prokit-preset-create와 관측 계약을 읽는다. 지정 파일만 구현한다. 원본의 구조·자산·상호작용을 편의상 다른 패턴으로 대체하지 않는다. 기술 경계는 설치된 prokit 전문 스킬을 재사용한다. 완료 보고는 요소 ID→제품 위치→실제 검증 증거를 연결한다. 첫 통합본 freeze는 Main이 소유한다.

정보 슬롯·순서·목적을 유지하며 가상 정본으로 교체하고 샘플 번호·예약 이메일과 빈 URL 설정을 사용한다.

카탈로그 반영을 배정받으면 prokit-preset-publish의 기존 CLI와 공통 카드·상세·미리보기를 사용한다. 표시값은 samples.json의 레코드에 두고 slug별 부품을 복제하지 않는다. 등록·편집·보관·복구와 실제 원격 게시를 구분한다.

신규 제작 인계에는 확정한 카테고리·태그·기본 문구와 실제 페이지/그림/검증 사실을 연결한다. 카탈로그 편집만 배정받았으면 요청한 필드 밖의 제품·팩·공개 상태를 바꾸지 않는다.

다른 작업자가 같은 저장소에서 작업한다. 다른 사람 변경을 되돌리지 않는다. 범위 확대·공유 파일 충돌·도구 부족은 Main에 보고하고 재귀 위임하지 않는다.
