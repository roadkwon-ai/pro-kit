# 원본 대비 검수

[검증 입력](references/evidence.md)을 읽는다. 구현자가 제공한 목록만 체크하지 않고 원본을 직접 순회해 빠진 페이지·상태·요소를 추가한다. 연구·구현 담당과 독립적으로 수행한다.

source ID별 실제 DOM 순서·측정값과 제품 차이를 먼저 확인한다. 새 가상화 보고서는 schemaVersion:2와 필수 contentInventory로 원본 대상 ID·key·mode를 고정한다. 가상화 대상은 contentSlots의 순서·역할·제품 값을 대조하고 푸터 누락이나 원본 실정보 잔존을 별도 실패로 보고한다. 비교 종류에 필요한 layout·textrow·assetSlot·navigationRefs 관측이 없으면 수동 PASS 대신 incomplete로 남긴다. 같은 TaskSpace의 입력은 Main 배정에 따라 한 수행자씩 순차 검증한다.

같은 뷰포트·언어·테마·서체 준비·스크롤 상태에서 원본과 제품을 나란히 비교한다. 배치·폰트·색·자산 역할·크롭·정보 밀도를 보고, 모션은 같은 트리거로 시작·중간·끝·재진입을 비교한다. 추출한 수치는 정확히 대조하고 화면 측정값은 관측 오차를 기록한다. 허용 차이는 해당 요소·속성에만 적용한다.

`node <이 스킬>/scripts/verify-evidence.mjs <report.json> --source-root <현재 제품>`으로 증거 파일·현재 소스 해시·필수 대응·미확인을 검사한다. 이 도구는 `evidence-complete` 또는 `incomplete`로 구조·해시·누락만 판정한다. 별도 독립 검수 JSON의 주소·범위·현재 소스 fingerprint를 대조하며 전체 품질 pass를 발급하지 않는다. Main은 실제 수신한 독립 에이전트 결과와 동일 제품임을 대조해 최종 수용한다. JSON·해시·역할 이름은 신원·독립성·발행 권한의 증명이 아니다. 존재하는 스크린샷만으로 눈에 보이는 품질을 통과시키지 않는다.

기능·접근성·충실도 결과를 따로 보고한다. 원본 핵심 누락, 대체 이미지 미완성, 확인되지 않은 모션, 오래된 제품 증거는 불합격이다. 구현 수정 후 영향받은 상태와 최종 정적 출력에서도 확인한다. 첫 통합본과 수정 후 결과를 분리해 실제 개선을 보고한다. 외부 영상 차단·실기기 미검사 등 남은 한계를 그대로 기록한다.
