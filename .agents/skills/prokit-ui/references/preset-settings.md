# 완성팩의 설정 적용

완성팩을 활용한 화면·실전 개발의 기준이다. 원본 조사·COPY와 공식 프리셋 기본 기능은 `pro-kit-preset-skills`의 `prokit-preset-create`가 소유한다. 팩 적용은 `prokit-pack-use`에서 시작한다.

## 기준 읽기

팩의 `preset-manifest.json`, `DESIGN.md`, `docs/preset-design.json`과 실제 구현을 함께 읽는다. 지원하는 경로·서체·색·언어·테마를 확인하고 사용자 요청으로 바꿀 항목만 기록한다. manifest가 없는 기존 팩은 있는 구현을 조사하고 없는 품질 기준은 미확인으로 남긴다.

- 사용자가 지정한 본문·제목 서체와 색은 기존 토큰에 적용한다. 지정하지 않은 값은 팩을 유지하며 스타일 카탈로그를 다시 고르지 않는다.
- 폰트 원본·굵기·한글 폴백·라이선스와 이미지 크롭·비율을 보존한다. 새 자산은 사용 권한과 실제 화면 표시를 확인한다.
- 테마·언어 메뉴의 구성·접근성 이름·키보드 조작을 보존한다. 시스템·라이트·다크와 한국어·영어는 팩이 지원하거나 사용자가 요청한 범위에서 검사한다. 팩이 단일 테마·언어라면 임의로 기능을 추가하지 않는다.
- 지원되는 설정을 바꾸면 페이지·입력·선택 상태가 유지되어야 한다. 선택값은 번역된 표시 문구 대신 언어와 무관한 ID로 보관하고, 언어 왕복 전환 후 선택과 제출·복사되는 현재 언어 문구를 확인한다. 시스템 설정 변화, 저장소 차단, 초기 깜박임과 수화 오류를 확인한다.
- 번역 체계와 키를 재사용하고 `html.lang`·Intl·긴 영문·오류·빈 상태·접근성 이름을 확인한다. 언어 변경으로 원본 데이터·통화·시간대를 바꾸지 않는다.

## 실전 서비스로 연결

제작용 폰트·색 팔레트와 설정 견본을 서비스에 더하지 않는다. 팩에 관리 미리보기용 adapter가 있으면 사용자 서비스에 필요한지 구분하고 기존 shared message schema를 복제·확장하지 않는다. 제거가 필요하면 실제 소비자를 확인하고 공개 UI의 설정 전환은 유지한다.

API·DB 연결은 `prokit-web`·`prokit-api`·`prokit-db`가 맡는다. loading·empty·error·비인가·긴 실제 콘텐츠에도 팩의 카드 비율·간격·모션·반응형 구조가 유지되는지 검사한다. 데이터 변화로 생긴 배치 변경을 디자인 재선택의 근거로 삼지 않는다.

## 실제 적용 증거

개발 화면과 요청된 정적 HTML에서 `document.fonts`, computed style의 서체·굵기·토큰을 비교한다. 본문·버튼 4.5:1, 큰 글자·아이콘·조작부 3:1 대비와 키보드 동작을 확인한다. `export:html` 성공은 실제 설정·시각 품질의 증거가 아니다.

전체 페이지의 비교 방법은 `prokit-verify`의 [팩 기준 비교](../../prokit-verify/references/pack-baseline.md)를 따른다. 사용자 변경 항목과 개인화 밖 회귀를 구분해 기록한다.
