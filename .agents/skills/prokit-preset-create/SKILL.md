# 공식 프리셋 제작

가상 사업자·연락 정보는 예시임이 명확한 무효 번호·가상 지역명·예약 도메인 `example.com`으로 구성하고 실제일 수 있는 주소·전화·새 운영 도메인을 만들어 넣지 않는다. SOURCES·provenance의 원본 출처 URL은 이 가상화와 구분해 보존한다.

원본→프리셋의 결과를 소유한다. 프로젝트 기술 구현에는 prokit-web·api·db를 재사용하되 원본 관측과 COPY 합격 판단을 prokit-ui에 넘기지 않는다.

1. 지정된 원본·제품·설치 경로와 기존 변경을 확인한다. 설치된 `prokit-preset-research`로 페이지·상태·자산·모션을 조사하고 독립 원본 순회에서 목록 밖 누락을 보완한다. 원본을 볼 수 없으면 해당 범위를 미확인으로 남긴다.
2. 유지할 구조와 교체할 콘텐츠를 구분한다. 새 가상화 결과는 검증 입력 v2의 contentInventory로 조사 목록을 고정한다. 푸터를 포함한 원본 정보 슬롯을 빠짐없이 가상 정본에 대응하고 슬롯별 변경과 미설정 URL을 기록한다. 원본과 다른 점은 요소·속성별로 승인된 범위와 이유를 기록한다. 승인된 이름·브랜드·문구 교체는 DOM 구조·사진 슬롯·순서·내비게이션 목적·제목 행수 변경의 허가가 아니다. [자산 제작](references/assets.md)에 따라 필요한 사진·표지·모션을 확보한다.
3. 기존 dev-cycle 기록을 사용해 구현한다. 역할은 [배정·설치](references/agents.md)를 따른다. 관측된 카드·슬라이더·프로필을 간단한 텍스트나 다른 패턴으로 대체하지 않는다.
4. 구현자는 개발자 자체 검사에서 원본 DOM 자식 순서와 실제 스타일, 글자 행수·사진 슬롯·내비게이션 목적을 제품에서 다시 관측한다. source ID별 실제 관측과 차이를 첫 통합본에 포함한다. 수동 pass만으로 측정을 대신하지 않는다.
5. 독립 리뷰 피드백 전 첫 통합본의 코드·입력·스킬·환경 해시와 실패 상태를 보존한다. 개발 중 자기 검사는 허용하되 독립 리뷰 후 결과를 첫 결과로 바꾸지 않는다.
6. 설치된 `prokit-preset-verify`로 원본 충실도와 기능·접근성을 각각 검수한다. 필수 요소 누락은 평균 점수로 상쇄하지 않는다. 실패한 항목과 변경 영향을 수정·재검사한다.
7. [팩 계약과 카탈로그 인계](references/pack-contract.md)에 따라 완성 프리셋 기준과 웹 등록에 필요한 사실을 준비한다. 제품 검수 증거를 prokit-docs·prokit-writing에 넘겨 문서를 완성한 뒤 ZIP을 조립·복원 검증한다. prokit-preset-publish에 검수된 팩·문서·카탈로그 입력·로컬 상태를 넘긴다.

## 공식 프리셋 설정

테마는 현재 테마를 나타내는 아이콘 버튼 하나에서 시스템·라이트·다크 메뉴를 연다. 언어는 `🇰🇷 한국어`, `🇺🇸 English`를 선택하는 메뉴다. 국기에만 의미를 맡기지 않고 접근 가능한 언어 이름을 제공한다. 기본은 시스템·한국어다. 모바일·모든 페이지·정적 내보내기·부모 미리보기에서 같은 설정과 저장키를 쓴다. 키보드 선택, Escape, 초점 복귀와 저장소 차단을 검증한다. 기본 UI·본문·폼·메뉴·alt/aria의 번역 키 범위를 대조하고 실제 언어 전환 뒤 본문 KO/EN 문구와 입력·선택 유지도 확인한다. 고정 브랜드명을 제외한 본문 번역을 관측하며 국기·document.lang·저장값만 바뀌는 구현을 번역 완료로 보고하지 않는다.

원본의 설정과 다른 이 공식 프리셋 요구는 허용 차이에 명시한다. 콘텐츠·자산 교체와 접근성 보완도 좁은 허용 차이로 기록한다. 실제 결제·외부 전송·배포는 사용자 범위에 따르며 데모를 실서비스로 보고하지 않는다.

같은 Ego TaskSpace의 브라우저 입력은 한 수행자만 맡는다. Main이 페이지와 검증 단계를 배정하고 완료 후 다음 수행자에게 순차 인계한다. 코드·파일 작업은 소유권을 나누어 병렬 실행할 수 있다. 별도 잠금 데몬이나 권한 영수증을 만들지 않는다.

후속 UI 수정은 보존한 첫 통합본을 유지한 채 수정 코드·현재 스킬 해시로 별도 결과를 만든다. 스킬 성능 평가에서는 각 old/new 쌍의 입력·환경·뷰포트·실행 조건을 맞추고 사용한 스킬 해시를 기록한다. 중간 스킬 판이 달라진 평가 A·B를 같은 조건의 개선율로 합치지 않는다.

관측한 typography·spacing 값을 첫 자체 측정의 기준으로 고정한다. 요청하지 않은 미학 보정으로 글자 크기·굵기·행간·자간·간격을 바꾸지 않는다. 필요한 변경은 기존 source ID의 명시된 허용 차이로 검토하고, 평가 때 사용한 스킬 revision을 그대로 기록한다.

공유 스타일을 삭제·정리하기 전에는 src뿐 아니라 packages/ui·공통 props·portal 소비처까지 기존 검색/파일 관계 도구로 확인한다. 모달 같은 대표 portal을 개발·정적 출력에서 직접 측정해 누락 CSS를 검증한다. 새 위젯도 공유 props와 전역 스타일 소비 범위를 포함한다.

선택 값은 번역된 label 대신 locale에 독립적인 key로 유지한다. 언어 전환 전→다른 언어→원래 언어→복사 결과에서 입력·선택이 유지되는지 확인한다.
