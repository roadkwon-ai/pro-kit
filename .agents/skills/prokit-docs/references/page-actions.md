# 문서 메뉴와 쪽만 읽어도 통하는 글

홈페이지는 `/docs`와 `/tutorials` 아래 모든 문서 쪽(목록 쪽 포함)에 세 가지를 붙인다. `<쪽>.md` 주소, 오른쪽 위 메뉴(마크다운 복사, ChatGPT에서 열기, Claude에서 열기), 도식 내려받기(SVG, PNG, 마크다운)다. 이 파일은 그 규칙을 다시 쓰지 않는다. 화면 모양, 보내는 글, 링크 꼴, 로고를 쓰지 않는 규칙은 아래 정본에서 읽는다.

## 정본

- pro-kit `AGENTS.md` "템플릿 수정 규칙"의 문서 원본 항목, `CONTRIBUTING.md` 문서 절
- pro-kit-web `AGENTS.md` "프로젝트 규칙", `docs/briefs/doc-actions.md`(R3, pro-kit-web dbe8b54)
- 검사로 지키는 곳: pro-kit-web의 `pnpm handbook:check`, `pnpm tutorials:check`와 빌드가 쪽마다 `.md`가 있는지, 문서 쪽이 메뉴 부품을 쓰는지, 도식이 내려받기 부품을 쓰는지 본다. `.md`는 `pnpm docs:md`가 만들고, 두 sync 명령이 마지막에 그 명령을 부른다. 받은 pro-kit-web 판에 이 기능이나 검사 항목이 없으면 그렇다고 보고하고 pro-kit-web의 일로 넘긴다.

## 원본을 쓸 때 지킬 것

AI로 보내기를 누르면 AI는 앞뒤 쪽 없이 그 쪽의 `.md` 하나만 읽는다. 마크다운 복사도 같다. 그래서 쪽 하나만 읽어도 뜻이 통하게 쓴다.

1. **다른 쪽을 가리키는 말에는 링크를 단다.** "앞 장에서 만든", "4장의", "6장에서 만든 DB", "가이드의"처럼 다른 쪽에 기대는 말은 그 쪽(필요하면 앵커)으로 링크한다. 같은 쪽 안의 절이면 앵커 링크를 단다.
   - 나쁜 예: `4장에서는 예시 데이터에서 찾았는데, 이제 6장에서 만든 DB에서 찾아요.`
   - 좋은 예: `[4장](04-screens.md)에서는 예시 데이터에서 찾았는데, 이제 [6장](06-catalog-db.md)에서 만든 DB에서 찾아요.`
2. **링크 글만으로 무엇인지 알게 쓴다.** `여기`, `이 문서` 대신 쪽 제목이나 내용을 링크 글로 쓴다.
3. **도식은 Mermaid 코드 블록으로 쓴다.** 내려받기는 그려진 Mermaid 도식에만 붙는다. 그림 파일로 넣은 도식에는 붙지 않는다.
4. **그림이 전하는 내용은 글에도 쓴다.** `.md`에서 그림은 주소로만 남는다. 대체 글에 무엇을 보여 주는지 쓴다.

## 새 문서 종류를 더할 때

새 handbook 묶음, 새 튜토리얼 과정, 새 가이드 쪽을 더하거나 쪽을 옮기면 다음을 확인한다.

1. pro-kit 검사(`node --test scripts/handbook.test.mjs scripts/doc-values.test.mjs`)가 통과한다.
2. pro-kit-web에서 sync 뒤 두 검사가 통과해 새 쪽에도 메뉴, `.md`, 내려받기가 붙는다(명령은 `SKILL.md`의 검사 명령 표). 새 경로가 검사 대상에 없으면 pro-kit-web의 일로 넘기고 보고한다.
3. 쪽을 옮기거나 지우면 홈페이지 주소와 `.md` 주소가 바뀐다. 바뀐 주소와 그 주소를 가리키던 링크를 보고한다.

pro-kit-web 코드는 이 스킬로 고치지 않는다. 그 저장소의 세션에서 한다.
