# 검수 절차

프로킷 글을 korean-skills로 검수하는 순서와 프로킷 예외다. 릴리스 노트도 이 절차를 쓴다.

## 순서

1. **humanizer**: AI 티(번역투, 명사 나열, 과장, 관용구, 쉼표 과다)를 고친다.
2. **style-guide**: 어조, 용어, 숫자, 목록, 따옴표의 일관성을 맞춘다.
3. **grammar-checker**: 맞춤법, 띄어쓰기, 문법, 구두점을 고친다.
4. **프로킷 최종 점검**: 아래 점검표를 하나씩 확인한다.
5. **저장소 검사**: `SKILL.md`의 "저장소 검사" 표대로 실행한다.

이 순서는 pro-kit `AGENTS.md`의 "버전과 릴리스" 2단계가 정했다. korean-skills README의 권장 순서와 달라도 이 순서를 쓴다. 프로킷 점검을 세 스킬 뒤에 두는 이유는 앞 단계가 값 표시나 링크를 건드리거나 문체를 섞을 수 있어서다.

## 스킬 찾기

각 스킬의 `SKILL.md`를 읽고 그 절차를 따른다. 설치 위치는 에이전트마다 다르다. 프로젝트의 `.claude/skills/`나 `.agents/skills/`, 사용자 전역의 `~/.agents/skills/`, `~/.claude/skills/`, `~/.gemini/antigravity-cli/skills/` 등을 찾아본다. 세 스킬 중 하나라도 없으면 아래 명령을 알려 주고 멈춘다. Antigravity CLI는 `~/.agents/skills/`를 읽지 않으므로 둘째 줄로 링크를 건다.

```bash
npx skills add DaleSeo/korean-skills -g -a claude-code -a codex -y
for s in humanizer style-guide grammar-checker; do ln -s ~/.agents/skills/$s ~/.gemini/antigravity-cli/skills/$s; done
```

## 프로킷 예외

세 스킬의 지적 가운데 아래는 프로킷 문서에서 따르지 않거나 바꿔 따른다. 따르지 않은 지적은 보고의 "일부러 고치지 않은 것"에 적는다.

| 스킬 | 지적 | 프로킷에서 |
|---|---|---|
| humanizer | 패턴 24: 글 전체가 같은 어미면 AI 신호로 보고 다른 어미를 섞으라고 한다 | 적용하지 않는다. 문서마다 문체 표의 문체 하나를 지킨다 |
| humanizer | 변경률 가드(30% 경고, 50% 중단), 의미 보존 검사 | 그대로 지킨다 |
| style-guide | 용어를 많이 쓴 말로 통일한다 | 다수결 대신 정본(용어집, `GLOSSARY.md`, 화면 이름 표)을 따른다 |
| style-guide | 숫자, 날짜, 범위 꼴 | 값 표시, `\~`, 요약 시간 꼴이 우선이다 |
| grammar-checker | 대안 나열의 가운뎃점을 쉼표로 바꾸라고 한다 | 짧은 대안 나열(`neon·supabase`, `Claude Code·Codex`)은 그대로 둔다. 문장 속 긴 나열은 지적을 따른다 |
| 세 스킬 모두 | 보존 목록 안의 글을 고치라는 지적 | 고치지 않고 보고한다 |

## 보존 목록 세기

보존 목록의 정본은 `SKILL.md`의 "보존 목록"이다. 그 가운데 아래 항목은 검수 전후로 개수와 글자를 세어 맞춰 본다.

- 코드 블록, 인라인 코드
- 값 표시(`<!-- v:`), 묶음 표시(`<!-- b:`, `<!-- /b -->`)와 묶음 안의 글
- 링크 주소. 제목을 바꿨으면 그 앵커를 쓰는 링크도 같은 수만큼 바뀌었는지 본다.
- 프롬프트 안의 `[ ]`
- 릴리스 노트의 첫 줄, 메타 줄 세 개, 절 제목, 커밋 해시, `**BREAKING**`
- CASES로 지키는 줄(`scripts/doc-values.cases.mjs`에서 그 파일 경로를 찾는다)

원본과 결과에서 `<!--`, `](`, 백틱, 커밋 해시의 개수를 세어 맞춰 보거나 `git diff`로 그 줄만 골라 본다.

## 릴리스 노트 검수

그 저장소 릴리스 절차의 2단계다. pro-kit은 `AGENTS.md`의 "버전과 릴리스"(1단계 `node scripts/release.mjs --title "<제목>"`), pro-kit-web과 템플릿으로 만든 프로젝트는 `prokit-deploy` 스킬의 릴리스 절차(1단계 `pnpm release --title "<제목>"`)를 따른다. 1단계가 쓴 `release/<날짜>-<제목>.md` 하나가 대상이다.

1. 노트 파일만 고친다. 다른 파일과 이미 발행한 노트는 고치지 않는다.
2. 위 순서로 검수하고 보존 목록을 지킨다. 첫 줄의 엠대시는 스크립트가 넣은 것이라 그대로 둔다.
3. 항목 글은 `~다`나 명사형으로 끝낸다. 뜻은 바꾸지 않는다. 항목을 더하거나 빼지 않는다.
4. 커밋하지 않고 발행하지 않는다. 사용자가 발행을 청하면 그 저장소의 발행 절차를 따른다(pro-kit-web과 템플릿 프로젝트는 발행 전에 버전과 노트를 보여 주고 동의를 받는다).
5. 보고에 검수에서 고친 내용을 요약한다.

## 프로킷 최종 점검표

- [ ] 문서 전체가 문체 표의 문체 하나다(문장으로 끝나는 표 칸과 목록 포함, 인용과 표에 적은 예외는 제외)
- [ ] 보존 목록의 개수와 글자가 검수 전과 같다
- [ ] 엠대시가 없다(스크립트가 만든 줄은 제외)
- [ ] 마크다운 문서에서 한 문단에 `~`가 둘 있지 않고, 범위는 `\~`다(코드 안 화면 글은 `~` 그대로)
- [ ] 굵은 글씨는 핵심 문장과 구절에만 있다(이름표 제외, 양은 voice.md가 가리키는 정본)
- [ ] 출처 없는 숫자가 없다
- [ ] 같은 대상을 정본의 같은 말로 부른다
- [ ] 짧은 가운뎃점 나열과 문서 문체가 korean-skills 때문에 바뀌지 않았다
