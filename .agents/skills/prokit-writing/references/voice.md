# 문체와 표기

`prokit-writing` 본문 규칙을 자세히 적은 파일이다. 어느 문서가 어느 문체인지는 `SKILL.md`의 문체 표가 정본이고, 여기에는 그 표에 없는 끝맺음 예와 표기만 둔다. 필요한 절만 읽는다.

## 끝맺음 예

| 문체 | 끝맺음 예 | 독자에게 시킬 때 |
|---|---|---|
| `~습니다` | 설치합니다, 있습니다 | 실행합니다, 확인하세요 |
| `~요` | 설치해요, 있어요, 거예요 | 보내세요, 확인해요 |
| `~다` | 설치한다, 있다 | 실행한다, 확인한다 |

- 인용은 원문 문체 그대로다. 튜토리얼의 프롬프트(`검색을 실제로 동작하게 해줘.`), 에이전트가 하는 질문, 커밋 제목은 문서 문체에 맞추지 않는다.
- 브리프와 설계 안에 따옴표로 적은 화면 문구는 화면 글이다. 설명 문장은 `~다`로, 화면 문구는 해요체로 쓴다.
  - 나쁜 예: `누르면 "복사 완료되었습니다"를 띄워요.`
  - 좋은 예: `누르면 "복사했어요"를 띄운다.`
- 같은 값이 문체별로 따로 있으면(`policy.agentBrowser.da`, `.yo`, `.cell`) 문서 문체에 맞는 키를 쓴다. `.cell`은 표 칸용 명사구다.
- 릴리스 노트 항목은 커밋 제목과 본문에서 온다. `~다`나 명사형(`고침`, `더함`)으로 끝내고 `~요`와 `~습니다`를 섞지 않는다.

## 이름 표기

- 서비스 이름은 "프로킷"이다. 영문이 필요하면 ProKit이고, 화면에서는 한글 "프로킷"을 앞에 둔다.
- 저장소 이름은 `pro-kit`, `pro-kit-web`, `pro-kit-samples`, `pro-kit-packs`, `pro-kit-docs-skills`처럼 코드 꼴로 쓴다. 스킬 이름은 `prokit-*`다.
- 템플릿은 소문자 `neon`, `supabase`로 부르고(`neon 템플릿`), 서비스는 제품 표기(Neon, Supabase, Vercel, GitHub)를 쓴다.
- 에이전트 이름은 Claude Code, Codex, Antigravity, Grok Build로 쓴다.
- 다른 회사 이름은 글자로만 쓴다. 로고나 상표 그림을 문서에 넣지 않는다.

## 맞춤법 결정

pro-kit(커밋 `de01de6`)과 같게 쓴다.

- 사이시옷: `최솟값`, `최댓값`. 앞말에 받침이 있는 `계산값`, `어림값`, `입력값`은 그대로다.
- `맨값`, `맨글`, `맨시간`, `맨숫자`처럼 접두사 `맨-`은 붙여 쓴다. `맨 위`, `맨 앞`처럼 '가장'을 뜻하는 관형사 `맨`은 띄어 쓴다.

## 이름 뒤 조사

영문 이름 뒤 조사는 읽는 소리의 받침을 따른다.

| 이름 | 읽기 | 조사 |
|---|---|---|
| neon | 네온 | `neon은`, `neon을`, `neon이` |
| supabase | 수파베이스 | `supabase는`, `supabase를`, `supabase가` |
| Codex | 코덱스 | `Codex는`, `Codex를` |
| Claude Code | 클로드 코드 | `Claude Code는`, `Claude Code로` |
| GitHub | 깃허브 | `GitHub에서`, `GitHub로` |

이름이 값이나 인자로 바뀌는 글(묶음 안의 `{{v:preset.{{name}}.title}}`)은 조사를 글에 박지 않고 인자 `neun`(는/은), `reul`(를/을), `ga`(가/이)로 받는다. 이런 글을 고칠 때는 `prokit-docs`를 따른다.

## 숫자, 날짜, 시간, 범위

- 날짜는 `2026-10-08`, 시각은 `09:57 (KST)`처럼 쓴다.
- 단위는 `5분`, `2배`, `8개`처럼 숫자에 붙여 쓴다. 네 자리 이상인 수는 `3,460번`처럼 쉼표를 찍는다.
- 토큰은 `190만`, `2.2억`처럼 만과 억 단위, 유효숫자 두 자리로 쓴다. 최솟값이면 "최소 약 N 토큰"처럼 최소임을 밝힌다.
- 어림값에는 "약"을 붙이고, 잰 값은 잰 그대로 쓴다. 잰 날짜나 판이 있으면 함께 적는다.
- 마크다운 문서의 범위는 `1\~3`처럼 `\~`로 쓴다. 한 문단에 `~`가 둘이면 GitHub와 홈페이지가 그 사이를 취소선으로 그린다. 인라인 코드 안의 `~`는 괜찮다. 코드(TSX, TS, JSON) 안의 화면 글은 `~`를 그대로 쓴다.
- pro-kit에서는 두 곳 이상에 쓰거나 자주 바뀌는 시간과 숫자를 값 표시로 쓴다. 표시 밖 맨시간은 테스트가 잡는다. 판단은 `prokit-docs`가 맡는다.

## 굵은 글씨, 알림, 바꿀 곳

- 굵은 글씨는 "이것만 읽어도 되는" 핵심 문장과 구절에만 쓴다. 문단이나 항목 맨 앞의 이름표(`**macOS**:`, `**이렇게 되면 성공**`)는 굵은 글씨 수에 넣지 않는다.
- 목록 항목 머리를 짧은 문장으로 굵게 쓸 때(질문 목록, 요령 목록)는 마침표와 물음표를 굵은 글씨 밖에 둔다(`**작은 범위로 시작해요**.`, `**얼마나 걸리나요**?`). 이름표로 보여 형광 띠 없이 굵기만 그려진다. 검수할 때 부호를 다시 안으로 넣지 않는다.
- 표 칸을 읽는 법(칸이 무엇인지 알리는 문장), 문단 맨 앞 이름표, 바로 뒤에 "확인하지 않았다"는 단서가 붙는 문장에는 굵은 글씨를 더하지 않는다.
- 홈페이지는 굵은 핵심 문장에 형광 띠를 달고, 굵은 글씨만으로 ` → `를 이은 문단을 흐름 띠로 그린다. 흐름 띠는 흐름을 보일 때만 쓴다.
- 프롬프트 안에서 독자가 바꿀 곳은 `[ ]`로 감싼다.
- 굵은 글씨의 양, 형광 띠 수, 흐름 띠 조건, `[ ]`를 칠하는 조건은 pro-kit-web `DESIGN.md`의 "본문 굵은 글씨", "흐름 띠 flow-chip", "바꿀 곳 prompt-placeholder" 항목이 정본이다.
- 알림은 GitHub 알림 문법(`> [!TIP]`, `> [!NOTE]`, `> [!WARNING]`)으로 쓴다.

## 화면 글 (pro-kit-web)

- 코드를 모르는 사람도 읽는 쉬운 해요체로 쓴다.
- 도구와 스킬 이름(critique, impeccable 등), 개발 용어(모달, 토스트, 404, 콘솔 오류)는 화면에 쓰지 않는다. `PRODUCT.md` "화면에 쓰는 이름" 표의 말로 바꾸고, 꼭 필요하면 설명 툴팁의 괄호 안에만 둔다.
  - 나쁜 예: `모달과 토스트까지 콘솔 오류 0으로 검사했어요.`
  - 좋은 예: `열린 창과 잠깐 뜬 알림까지 브라우저 오류 없이 검사했어요.`
- 화면 글은 TSX 안 문자열이다. 범위 물결표는 `~` 그대로 쓰고, JSX 태그, 중괄호, 따옴표는 건드리지 않는다.
- 점수나 평가는 무엇을 어떤 기준으로 쟀는지 풀어 쓴다.
- 서비스 이름, 헤드라인 후보, 화면 모양은 `prokit-ui`가 맡는다.
