# 프로킷 프리셋 관리 계약 갱신

실제 시스템 코드의 변경을 확인하고, 달라진 계약과 영향받은 스킬·검사만 갱신한다. 기준선 파일과 검사 JSON은 일치성 자료이며 발행 권한이나 Main 인수 콜백이 아니다.

## 점검

프리셋 제작·반영 시작마다, 공통 시스템을 바꾼 뒤, 관리자가 주기 점검을 요청했을 때 아래 명령을 실행한다. 날짜만으로 최신을 판단하거나 변경이 없는데 전체 검사를 반복하지 않는다. 별도 예약 작업·감시 데몬은 만들지 않는다.

```bash
node <이 스킬>/scripts/check-contract.mjs --web <pro-kit-web> --kit <pro-kit> [--slug <이름>]
```

이 명령은 기존 `preset-contract.mjs`를 호출한다. `ok`는 현재 등록 검사와 검증한 시스템 기준선이 일치한다는 뜻이다. `review-required`는 달라진 정본 파일 목록을, `blocked`는 누락·불완전한 등록이나 기준선 등 원인을 남긴다. 새 프리셋 미등록과 공통 시스템 변경은 별도로 처리한다.

## 갱신

[change-review.md](references/change-review.md)를 읽고 바뀐 파일의 실제 소비자와 검사 범위를 정한다. 구현은 해당 파일을 맡은 전문 수행자, 스킬 수정은 `skill-creator`를 적용하는 수행자, 문서 정본·한국어 검수는 문서 전문 스킬에 배정한다.

카탈로그 변경은 데이터 정본·검증/변경 함수·공통 화면 소비자·게시 검사까지 함께 대조한다. 카테고리나 태그를 바꾸려고 slug별 화면 분기를 늘리거나 DB 도입 전에 별도 저장 엔진을 만들지 않는다.

공통 코드 결함이면 시스템을 먼저 고친다. 스킬만 고쳐 동작하는 것처럼 만들지 않는다. 일반 사용자 프로젝트 지침을 관리 스킬로 가져오거나 반대로 프로킷 웹의 게시 관리 계약을 사용자 템플릿에 넣지 않는다. 이 작업에 필요하지 않은 외부 스킬 업그레이드·기존 프로젝트 H·팩 재발행을 덧붙이지 않는다.

변경한 동작의 검사와 독립 검수 뒤에만 `references/contract-baseline.json`을 현재 `contractFiles`·`contractFingerprint`로 갱신한다. 지적과 수정 영향을 재검사하고, 통과한 비교는 반복하지 않는다. 추가 보완은 두 차례로 제한한다. 기준선 수정 자체를 검수로 간주하지 않는다.

검증한 원본을 사용하는 관리 프로젝트에만 다시 설치하고 내용 해시를 대조한다. 사용자 템플릿 manifest나 전역 설치는 바꾸지 않는다. sourceFingerprint는 프리셋 입력, contractFingerprint는 관리 시스템의 정본 판이다. 환경이 다르거나 unknown이면 예전 실행 증거를 성공으로 재사용하지 않는다.

변경이 없으면 무변경 결과로 종료한다. 변경이 있으면 파일·원인·보완·실제/재사용 검사·기준선·설치본·미해결 항목을 보고한다. 예약 실행이나 외부 발행은 별도 사용자 요청의 범위로 다룬다.

## 제작 체계 변경

create·research·verify의 관측 계약, 독립 검수, 첫 통합본 보존, 팩 인계 계약을 함께 대조한다. 제작 역할은 create의 지정 역할 설치 helper로만 해당 작업공간에 적용하고 설치 해시와 실제 native 역할 노출을 별도로 기록한다. 소비자 pro-kit에는 완성팩 활용 계약만, pro-kit-docs-skills에는 문서 사실 인계만 전달한다. 설치 성공과 행동 품질을 구분하고 라우팅·실제 첫 산출물·결함 변형본의 독립 평가 결과를 보존한다.
