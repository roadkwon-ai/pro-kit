# 제작 기록과 시간 표시

완료한 작업 이력의 존재와 전체 시간의 측정 완료는 다르다. 기록이 있으면 먼저 실제 타이머·시작/끝·대상·내용 해시를 찾아 관측 가능한 구간을 회수한다. 이력이 있는데 모두 `미측정`으로 숨기지 않는다.

## 무엇을 기록할지

준비·설계·구현·검증·리뷰·로컬 반영 중 이번 요청에 해당하는 단계의 시작과 끝, 실행 대상, 실제 종료 코드·실패·중단과 guard 판정을 기존 증거 폴더에 둔다. 작은 단계마다 새 에이전트를 띄우지 않는다.

명령을 계측할 때는 `scripts/record-command.mjs --out <새 증거.json> --phase <단계> -- <명령> <인자>`를 쓸 수 있다. 명령 문자열을 셸로 재해석하지 않고 실제 자식 프로세스가 끝날 때까지 기다린다. 기록은 실행 관측이며 작업 권한이나 제품 인수의 증명이 아니다. 원시 명령·인증값은 기록에 넣지 않는다.

## 시간의 종류

| 값 | 표시 기준 |
|---|---|
| 전체 제작 경과시간 | 제작 범위의 시작/완료와 누락·대기 포함 여부가 확인된 경우에만 사용한다 |
| 일부 제작 세션 관측 | 현재 `presets.<slug>.observed`의 `coverage:partial`, 범위·제외 단계·상대 출처·원시 SHA-256·시각·wallMs·exitCode로 기록한다 |
| 명령·QA 시간 | 기존 타이머·QA sidecar의 조건과 종료 코드를 따른다. 부모 세션 시간에 다시 더하지 않는다 |
| 팩 재현 예상 | 실제 제작 세션과 섞지 않는다. 기존 pack/scratch/screen/full 예상치 정본과 출처가 있어야 표시한다 |
| 토큰·비용 | 실제 자료와 수행자·캐시·과금 범위가 확인된 것만 쓴다. 시간이나 구독 요금으로 역산하지 않는다 |

같은 실행의 중복 영수증은 거부한다. 병렬·내부 구간은 기존 `summarizeObservations`의 구간 합집합으로 중복을 제거한다. 빠진 단계나 세션 사이의 대기를 합산하지 않는다. 파일 수정 시각이나 두 번의 대화 시각을 전체 제작 시간으로 바꾸지 않는다.

외부 세션 관측은 큐·오케스트레이션·검사·증거 정리 시간을 포함할 수 있으며 순수 모델 계산 시간과 다르다. 실패·중단한 세션 시간도 관측으로 보존하지만 성공 검사로 취급하지 않는다. 준비 시간·사용자 대기와 검사 시간의 분해가 불가능하면 그 항목은 unknown으로 남긴다.

웹은 일부 관측 시간을 점수·공개 여부·토큰과 독립적으로 표시한다. 값은 pro-kit 공통 값 공급자를 사용하고 상세 설명을 해당 교재의 기록 범위에 연결한다. 누락된 팩 예상·토큰·구독 키를 0으로 만들거나 strict 값 조회로 렌더 실패시키지 않는다.

한 제작의 관측 누계를 구판 대비 개선율이나 과거 장시간 작업의 단축률로 표현하지 않는다. 개선율은 동일 범위·입력·품질 조건으로 실제 비교했을 때만 보고한다.
