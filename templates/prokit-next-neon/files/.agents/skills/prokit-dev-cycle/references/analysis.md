# 정밀 분석 점검표

`prokit-analyzer`가 기존 프로젝트를 들일 때 쓰는 점검표와 보고서 틀이다. 유형(`.dev-cycle.json`의 `projectType`)은 `early`(기획 자료와 프로토타입만 있음), `operating`(운영 중인 Next.js), `migration`(다른 언어·프레임워크에서 Next.js로 전환)이다. 분석은 읽기 전용이고, 결과는 `docs/prokit/analysis.md`에 남긴다.

## 공통 점검표
| 항목 | 볼 것 |
|---|---|
| 스택과 구조 | 언어·프레임워크와 판, 패키지 관리자, 모노레포 여부, 진입점, 폴더 구조, 규모(파일 수, 주요 모듈) |
| 문서와 기획 자료 | PRD, 화면 정의서, 디자인 시스템 문서, ADR, README, 도메인 용어. 서로 어긋나는 곳 |
| 기능과 화면 | 화면·라우트 목록, 주요 사용자 흐름, 권한(누가 무엇을) |
| 데이터 | DB 종류, 스키마·마이그레이션 도구, 주요 테이블, 시드·백업 |
| 인증과 보안 | 인증 방식, 세션, 권한 검사 위치, 비밀값 관리(`.env*` 추적 여부), 알려진 취약 지점 |
| 외부 연동 | 결제, 메일, 지도, AI API 등. 키와 웹훅 위치 |
| 테스트와 검사 | 테스트 러너와 범위, 린트·타입 검사, CI. 지금 통과하는지는 "확인하지 못한 것"으로 둔다 |
| 빌드·배포 | 빌드 명령, 배포 대상과 방법, 환경별 설정, 도메인 |
| 디자인 자산 | 디자인 토큰·테마, 컴포넌트 라이브러리, 서체, 아이콘, `DESIGN.md` 유무(없으면 만들 근거가 되는 파일) |
| 위험 | 되돌리기 어려운 것, 데이터 손실 가능성, 운영 중단 가능성, 모르는 부분 |

## 유형별 점검표
### early
- 자료 대응표: PRD의 기능 → 화면 정의서의 화면 → 프로토타입의 화면 파일. 빠지거나 어긋난 것
- 프로토타입 화면 목록과 Next.js로 옮길 방식(그대로 옮김, 다시 만듦, 버림)
- 디자인 시스템 문서를 `DESIGN.md` 명세로 옮길 때 필요한 값(색, 서체, 간격, 반경, 컴포넌트)
- 첫 Task 후보: 데이터 모델, 인증, 화면 순서

### operating
- 프로킷 규칙과의 차이: dev-cycle 경로 규칙 후보(화면·API·DB·인증 경로), 테스트 러너, 린트·포맷 도구, 커밋·브랜치·배포 방식
- 위험 순위: 테스트 없는 핵심 흐름, 운영 데이터에 닿는 코드, 배포 자동화
- 첫 H Task 후보: `.dev-cycle.json`의 `rules`(위에서 처음 맞는 규칙을 쓴다)·`authPaths`, `docs/dev-workflow.md`의 행, 계층 규칙을 이 프로젝트에 맞추기. 기본 브랜치 push가 배포를 부르는지(CI, Vercel Git 연결)와 배포를 `prokit-deploy`에 맞출지도 적는다. 맞추기 전까지 라운드 끝은 커밋까지만 한다(`prokit-dev-cycle` 5절). `pnpm dev-cycle secrets`는 루트·`apps/web`·`packages/db`의 로컬 `.env` 값만 대조하므로, 다른 폴더에 `.env`가 있으면 패턴 검사만 받는다고 위험에 적는다
- Better-T-Stack 구조로 옮길지는 제안만 한다. 운영 중인 구조를 바꾸는 Task는 이득과 위험을 함께 적는다

### migration
- 기능 대응표: 기존 기능·라우트·API → Next.js의 화면·라우트·API(새 프로젝트의 `apps/web`, `packages/api`)
- 데이터 대응표: 기존 스키마 → Drizzle 스키마, 데이터 이전 방법과 검증 방법
- 전환 순서 후보: 의존이 적고 위험이 낮은 것부터. 인증과 데이터는 이른 Task로
- 병행 운영 방식: 기존 서비스를 켜 둔 채 기능 단위로 옮기는 방법(예: Next.js `rewrites`의 fallback으로 아직 옮기지 않은 경로를 기존 서비스로 보냄), 전환 시점과 되돌리기 방법. 병행 운영에 쓰는 설정 파일(`apps/web/next.config.ts` 등)은 H(빌드·배포 설정)로 판정되어 빌드 행이 붙는다
- 기존 코드(`legacy.path`)는 읽기만 한다

## 보고서 틀
`docs/prokit/analysis.md`의 절 순서다.
1. 요약(다섯 줄 이내): 지금 상태, 가장 큰 위험, 권하는 첫 Task
2. 스택과 구조
3. 기능·화면·데이터 대응표(유형별)
4. 테스트·검사·배포
5. 보안과 비밀값
6. 디자인 자산과 `DESIGN.md` 근거
7. 위험 목록(심각도 순)
8. 진행 계획 후보
9. 먼저 확인할 질문
10. 확인하지 못한 것
