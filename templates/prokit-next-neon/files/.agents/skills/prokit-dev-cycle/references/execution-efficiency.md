# 실행 효율과 재검증

위임의 출처·권한·패킷 계약은 [delegation.md](delegation.md), 증거의 형식은 `prokit-verify`가 정한다. 이 문서는 같은 계약을 반복하지 않고 작업 분할과 검사 재사용만 정한다.

## 적용 대상과 범위

- 읽기 전용 분석, 템플릿 하네스 보완<!-- edition:pro -->, 기존 프로젝트 이행<!-- /edition -->은 별도 작업이다. 사용자가 완성 사이트에 H 반영·build·수정 작업을 명시하지 않으면 그 사이트에는 하지 않는다. 대상 프로젝트의 하네스 수정을 명시했다면 그 프로젝트의 H 라운드는 그대로 쓴다.

## 작업 분할

- 독립 작업은 의존성, 소유 파일, 완료 조건, 산출물과 검사를 배정한다. 작은 관련 작업은 같은 수행자에게 묶고, 같은 파일·생성 산출물·소비자를 건드리면 순서대로 처리한다. Main은 조정·통합·최종 게이트만 맡고 전문 구현을 대신 쓰지 않는다.
- 구현자는 자신이 바꾼 동작의 배정된 회귀 검사만 한다. `.dev-cycle.json`의 `commands`에 등록된 전역 검사를 각 수행자가 자동으로 반복하지 않는다. 프로젝트 전체 typecheck·lint·build는 통합 뒤 한 번의 통합 lane에서 한다. UI 스킬의 리뷰·감사(impeccable `critique`·`audit`, hallmark 마감 리뷰)는 메인 세션에서만 실행한다.
- provider가 실제로 지원하는 capability만 쓴다. 내장 review coverage는 재사용하고 빈 계약만 보완한 뒤, `prokit-reviewer`의 fresh final gate를 항상 거친다. 읽기 전용 artifact는 write authority가 아니다.
- 병렬 작업은 서로 겹치지 않는 쓰기 범위만 쓴다. CI의 QA worker는 기본 하나로 두고, browser 4, agent 2, build 1을 한 작업의 상한으로 잡으며 중첩 worker도 센다. 이 상한은 host 전체 용량을 보장하지 않는다. guard나 worker 지원이 없으면 독립 읽기 browser만 하나로 제한하고 `unsupported`로 기록한다. 실제 자원 측정이 `unknown` 또는 `block`이면 새 batch를 시작하지 않는다. authority나 실행 권한이 unknown이면 병렬 수를 낮춰도 실행하지 않는다.
- 같은 frozen artifact를 읽는 독립 review와 QA는 병렬로 할 수 있다. batch의 planned·executed·missing coverage와 receipt를 구분해 남긴다. 일반 런타임 확인은 ego-browser를 우선하고 agent-browser를 기록한 대안으로만 쓴다. Playwright는 이미 승인한 batch에만 쓰며 일반 대안으로 넓히지 않는다.

## 검사와 증거

- 같은 artifact·도구·조건·환경·baseline·trusted receipt가 모두 알려져 같을 때만 그 검증을 재사용한다. 하나라도 unknown이면 관련 범위를 다시 검사한다. 최초 baseline은 유효한 초기 검사가 있을 때만 생략하며, 새 사이트·layout·token·route는 관련 전체를 검사한다. dev 런타임 증거와 정적 build 증거는 서로 대신하지 않는다.
- 재검사는 이전 검사가 실패했거나, 해당 검사 입력이 바뀌었거나, 바뀐 공유 의존성의 소비자가 있을 때 한다. stale `.next/types` 오류는 먼저 원인을 확인하고 필요한 생성물만 새로 고치며, 무관한 전체 build로 덮지 않는다.
- 첫 실패의 raw output은 보관한다. flaky 가능성은 진단 목적의 재시도 한 번만 허용하고, 재시도가 성공해도 첫 실패를 PASS로 바꾸지 않는다. 추가 재지시는 provider를 바꿔도 기존 추가 재지시 횟수를 합쳐 총 두 번을 넘기지 않으며, provider의 더 낮은 상한이 있으면 그것을 따른다. 그 뒤에는 `blocked`로 남긴다.

## 검증 증거 묶음

화면 라운드(B, F의 화면)는 같은 화면을 런타임 확인·디자인 리뷰·감사가 따로 찍고 재지 않는다. 런타임 확인이 묶음을 한 번 만들고 나머지는 그 묶음을 읽는다.

- 만들기: `prokit-runtime-checker`가 `pnpm dev-cycle packet capture <http://localhost:3001/경로> tasks/evidence/<라운드>/packet-<n>`을 실행한다. 표준 뷰포트(1440·1024·768·390·320)와 라이트·다크마다 첫 화면·전체 쪽 스크린샷, 가로 넘침과 원인 요소, 터치 영역(24px 미만 목록, 44px 미만 수), 글자 대비(실패 목록, 잴 수 없는 수), 콘솔·잡히지 않은 오류를 재고, 쪽마다 Tab 순서(1440·390)와 `/_next/mcp` `get_errors`를 남긴다. 로그인이 필요한 화면은 같은 agent-browser 세션에서 먼저 로그인하고 `--session <이름>`을 붙인다. 다른 도구로 찍었으면 같은 꼴의 `measure.json`을 쓰고 `pnpm dev-cycle packet seal <폴더>`로 봉인한다. 재지 못한 검사는 `{"skipped": "사유"}`로 적어야 봉인된다. `next start`로 띄운 빌드 서버에는 `/_next/mcp`가 없어 `get_errors`가 404를 받아 `해당 없음:`으로 남고 봉인 출력의 "해당 없는 검사"에 나온다. 그때 서버 오류는 `next start` 출력으로 확인한다.
- 봉인: 측정 칸, 파일 hash, 화면 소스 지문(apps·packages·의존성 잠금)을 `packet.json`에 남긴다. 출력 `packet: <경로> sha256=<값>`을 위임 보고와 대조표 증거에 그대로 옮긴다. 대조표·증거·문서를 고쳐도 지문은 그대로다.
- 읽기: 디자인 리뷰(impeccable critique의 Assessment A, hallmark 마감 리뷰, 기본 AI의 게슈탈트 점검), 디자인 감사, `prokit-reviewer(ui)`, 재확인 위임 지시에 묶음 경로와 hash를 넣는다. 평가자는 먼저 `pnpm dev-cycle packet check <경로>`가 `fresh`인지 보고 묶음의 스크린샷과 측정을 그대로 쓴다. 브라우저는 묶음에 없는 것(hover·메뉴·모달·폼 입력·애니메이션 진행, 묶음에서 빠진 뷰포트, 로그인 뒤 상태)에만 직접 연다. `stale`이면 그 묶음을 쓰지 않고 Main에 다시 찍게 한다. 이 규칙은 위 "검사와 증거"의 재사용 조건(같은 artifact일 때만)을 지문으로 확인하는 것이다.
- 격리: 묶음에는 측정값만 둔다. 의견·점수·detector 결과를 넣지 않으므로 critique A·B 격리가 그대로다. critique B의 detector는 묶음과 별개로 페이지에 주입해 돌린다(impeccable 절차). 개발 전용 요소(Next 개발 표시, TanStack Query devtools)가 Tab 순서·터치 영역에 섞여 나오면 결함으로 세지 않고 그렇다고 적는다.
- audit: 증거에 적은 묶음의 hash와 라운드, 봉인한 파일마다의 hash를 대조한다. 편집 도구로 묶음 폴더를 고친 기록이 있거나, 찍기 시작한 뒤 그 행을 마지막으로 채우기 전에 화면 소스를 고친 기록이 있으면 받지 않는다. 그래서 묶음을 쓴 행은 마감 위임 전에 채우고, 마감 뒤 재확인은 새로 찍은 묶음을 쓴다. 다크로 찍었는데 라이트로 그려진 뷰포트는 봉인할 때 빠진 뷰포트로 남는다.

## 병렬 행 묶음

`table --write`와 `status`가 함께 시작할 수 있는 행을 알린다. 서로의 결과가 필요 없는 행이다. 화면 라운드는 이렇게 묶인다.

| 시작할 때 | 함께 시작하는 행 |
|---|---|
| 구현 행을 채운 뒤 | 타입·린트·빌드, 런타임 확인(묶음 만들기와 오류 예산). `prokit-reviewer(ui)`의 web-design-guidelines 코드 검사는 브라우저를 쓰지 않아 여기서 시작해도 된다 |
| 묶음을 봉인한 뒤 | 휴대폰 스크롤 측정(같은 `prokit-runtime-checker`를 이어 쓴다), 디자인 리뷰, 디자인 감사 |
| 마감 행을 채운 뒤 | 재확인(같은 `prokit-runtime-checker`가 새 묶음을 찍고, 리뷰·감사한 평가자를 이어 써서 그 묶음으로 본다), `prokit-reviewer(code)` |

- 함께 시작해도 보증은 그대로다. critique A와 B는 서로의 결과를 보지 않고, 구현하거나 마감한 수행자는 리뷰·재확인을 맡지 않으며, `[confirm]`은 모든 행 뒤에 사용자에게 받는다.
- 런타임 확인 위임은 묶음을 봉인하고 오류 예산을 적으면 보고를 끝낸다. 휴대폰 스크롤 측정은 같은 수행자를 이어 써서 리뷰·감사와 겹쳐 돈다.
- audit은 채운 순서가 아니라 표 순서와 위임 기록으로 본다. 묶음 안의 행은 어느 순서로 채워도 받는다. 위임 행의 일은 같은 에이전트에 맡긴 앞 행 뒤의 다른 행을 채운 뒤의 기록만 세므로, 다음 묶음을 위임하기 전에 앞 묶음의 행을 모두 채운다(마감 위임 전에 디자인 감사까지, 코드 리뷰 위임 전에 마감 행).
- 재확인에서 고칠 것이 나오면 다시 마감 행을 채우고, 바뀐 diff로 코드 리뷰를 다시 받는다. 병렬로 받은 코드 리뷰를 바뀐 diff의 리뷰로 쓰지 않는다.
- 리뷰·감사·런타임 확인은 파일을 쓰지 않는다. 함께 시작할 때도 `delegation capture`를 한 번 남기고, 모두 끝난 뒤 `--scope` 없이 한 번 대조한다(위임 프로토콜 "관측과 수행 범위"). 행마다(작업 단위마다) 위 "작업 분할"의 상한을 지키고, `pnpm dev-cycle resource check`가 unknown이거나 block이면 묶음의 행을 동시에 시작하지 않고 차례로 한다.

## 문구만 바꾼 화면 라운드

화면 글자(JSX 텍스트, 문자열 상수, `messages/`·`locales/` 같은 문구 폴더의 JSON)만 바꾸고 구조·클래스·컴포넌트·스타일·로직은 그대로인 B 라운드는 리뷰를 줄인다.

- 그대로 하는 행: 타입·린트·빌드, 런타임 확인과 검증 증거 묶음(글자 길이가 바뀌면 넘침과 줄바꿈이 바뀐다), 디자인 리뷰의 critique A(묶음을 읽는다), `prokit-reviewer(code)`.
- 줄이는 것: 디자인 감사 행과 휴대폰 스크롤 측정은 `N/A: 문구만(<바꾼 글자 요약>)`으로 둔다. 디자인 리뷰에서 critique B(detector)는 돌리지 않고 증거에 `critique B: N/A: 문구만`을 덧붙인다.
- 판정: `prokit-reviewer(code)` 위임 지시에 "diff가 화면 글자만 바꿨는지 판정해 `문구만: 확인` 또는 `문구만: 아님`을 결과의 `actual_contract`에 넣는다"를 넣는다. audit은 `N/A: 문구만` 행을 이 판정이 `확인`일 때만 받는다. `아님`이면 줄인 행을 모두 한다. diff에 스타일·의존성·설정 파일(`.css`, `package.json`, 잠금 파일, 문구 폴더 밖의 JSON, `*.config.*` 등)이 있으면 러너가 문구만으로 보지 않는다.
- `N/A: 문구만`은 디자인 감사와 휴대폰 스크롤 행에만 받는다. 다른 행에 쓰면 audit이 받지 않는다.

## 핵심만 진행

Main은 감독하면서 결과를 바꾸지 않는 일을 줄인다. 생략은 근거를 남긴 판정이고 통과가 아니다. 대조표에는 `N/A: 사유`(해당 없음)나 줄인 범위를 적고, 실행하지 않은 검사를 통과로 적지 않는다.

| 일 | 줄이거나 생략할 때 | 증거 |
|---|---|---|
| 화면 브리프 | 좁은 개선(구성은 그대로, 간격·문구·부품 하나) | `N/A: 좁은 개선(…)` |
| 디자인 감사, critique B | 화면 글자만 바꿈(위 "문구만 바꾼 화면 라운드", 코드 리뷰의 판정이 있어야 받는다) | `N/A: 문구만(…)` |
| 휴대폰 스크롤 측정 | 스크롤 모션·긴 쪽·반복해서 다시 그리는 요소를 바꾸지 않음 | `N/A: 스크롤 모션·긴 쪽 변경 없음` |
| 마감에 넣을 지적 | 통과 기준을 막는 것(P0·P1, high 이상, 기준 미달 점수), 바닥선 위반, 한 파일 몇 줄로 끝나는 지적만 넣는다. 나머지(P2·P3, low)는 백로그로 보낸다 | 반영 내역과 `백로그 N건` |
| 재확인 범위 | 마감 diff가 바꾼 경로만 새 묶음으로 다시 찍고, 나머지 경로는 다시 보지 않았다고 적는다 | `재확인: /pricing(마감이 바꾼 경로), 나머지 미실행: 마감 diff에 없음` |
| 코드 리뷰 다시 받기 | high 이상 지적을 고쳤을 때만 같은 focus로 다시 받는다 | 반영·기각 내역 |
| `DESIGN.md` 갱신 | 토큰·컴포넌트 변화 없음 | `N/A: 토큰 변화 없음` |
| 같은 오류 반복 | 같은 명령이 같은 오류로 두 번 실패하면 세 번째 대신 원인을 본다(위 "검사와 증거"의 재시도 한도) | 첫 실패 원문과 `blocked: 사유` |
| 하위 에이전트의 진행 | `supervise` 신호에 따라 다시 읽기·묶음 밖 촬영·배정 밖 편집·같은 명령 반복을 끊고, 예산을 넘으면 멈춰 남은 일을 다시 나눈다 | 위임 보고의 `진행 보고:` |

줄이지 않는 것: `[confirm]` 사용자 확인, `prokit-reviewer`의 독립 리뷰 행, critique A·B와 그 격리, 구현 행의 위임과 위임 범위 대조, 증거에 적는 실행 결과. 사용자가 더 꼼꼼히 하라고 하거나 고위험 변경(인증<!-- edition:pro -->, 마이그레이션<!-- /edition -->, 결제)이면 생략 판정을 하지 않고 표 그대로 한다.
