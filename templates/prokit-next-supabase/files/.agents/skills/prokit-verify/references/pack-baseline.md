# 완성 프리셋과 복원 앱 비교

팩의 `preset-manifest.json`과 `source-manifest.json`을 읽는다. 다운로드 캐시 표식은 프로젝트 복원 증거가 아니다. 실제 소스 해시와 실행 화면을 확인한다.

## 재현 조건

각 baseline의 route, viewport, locale, theme, prepare 순서를 동일하게 적용한 뒤 screenshot과 checks를 비교한다. 서체 로딩·레이아웃 안정·스크롤 위치·모달·hover·모션 시점을 맞춘다. baseline을 못 열거나 필요한 상태가 없으면 해당 비교를 미확인으로 남긴다. 없는 자료를 임의 캡처로 원래 합격 기준처럼 만들지 않는다.

- 모든 routes의 직접 접근·새로고침·메뉴 이동과 지원 설정 전환을 검사한다. 링크는 팩의 목적·도착 주소·새 창 여부까지 대조한다. 빈 URL 상태는 실제 이동이 없는 비대화형 샘플인지, URL을 채운 상태는 허용된 http(s) 목적지로 이동하는지 각각 확인한다. 외부 판매 링크를 설명 모달로 바꾸면 동작 회귀다.
- 언어 변경 전 선택한 항목이 왕복 전환 후 유지되고 제출·복사 내용도 현재 언어에 맞는지 확인한다. 문구만 번역되고 선택이 사라지는 경우를 통과로 처리하지 않는다.
- 전역 CSS나 팝업 스타일을 바꾸면 앱뿐 아니라 `packages/ui` 등 공유 패키지의 실제 소비자를 검색한다. 관련 portal을 직접 열어 배경막·위치·크기·본문·초점·닫기를 확인한다. 정적 내보내기가 납품 범위라면 내보낸 화면에서도 같은 창을 열어 시각 확인한다. DOM의 열림 상태나 빌드 통과만으로 스타일 보존을 판정하지 않는다.
- 폰트의 실제 로딩과 computed style, 이미지 비율·크롭, 섹션 순서·폭·간격·반응형을 비교한다.
- 스크롤·sticky·반복·hover·열림·선택 동작은 prepare와 실제 이벤트를 재현한다. 스크린샷 한 장으로 모션 합격을 판정하지 않는다.
- 사용자 요청으로 바꾼 경로·필드만 허용 차이로 기록한다. 개인화 밖 영역의 자산·레이아웃·모션 변화는 회귀다. 전체 페이지를 예외로 제외하지 않는다.
- 실전 API 연결 뒤 loading·empty·error·비인가·동적 목록 길이·긴 텍스트·지연 응답에서도 배치와 상호작용을 확인한다. 로컬 테스트 API를 이용하고 운영 데이터는 사용하지 않는다.
- 최소 desktop·mobile과 팩이 지정한 추가 뷰포트를 검사하고 긴 영문·키보드·초점·reduced-motion을 포함한다.

## 결과

소스 fingerprint, 실제 검사한 페이지·상태·뷰포트, 사용자 허용 차이, 남은 회귀와 미확인 항목을 연결한다. 기능·접근성 검사와 팩 대비 시각·모션 보존 판정을 분리한다. legacy 팩은 기준 없는 항목만 미확인으로 두고 파일 무결성·설치·실행과 제공된 화면 비교는 수행한다. metadata가 있다고 시각 검증이 끝난 것은 아니다.

팩을 다시 받거나 source·자산이 달라졌다면 이전 fingerprint의 증거를 재사용하지 않는다. 동일 입력의 통과 검사는 반복하지 않으며 변경된 소비자와 상태만 다시 검증한다.
