# 프리셋 기본 설정

프로킷 사이트에 싣는 공식 프리셋을 제작할 때 적용하는 계약이다. 실전 서비스에서는 프롬프트로 정한 폰트·색상만 디자인 토큰에 고정한다. 서비스에 선택 팔레트·설정 견본·프로킷 미리보기 수신기를 넣지 않으며, 모드·언어는 그 프로젝트의 요구를 따른다. 이미 공개한 프리셋은 실제로 전환하고 검증한 기능만 지원한다고 표시한다.

## 디자인

- 시스템·라이트·다크를 모두 제공하고 초기 모드는 시스템으로 두되, 제작 프롬프트에 선택값이 있으면 그 값을 따른다. 강제 테마 설정으로 전환을 막지 않는다. 시스템 설정이 바뀌면 화면도 바뀐다.
- DESIGN.md에 light/dark의 배경·표면·글자·보조 글자·대표 색·대표 색 위 글자·테두리를 정의한다. 색을 기계적으로 반전하지 않고 대비를 확인한다. 성공·경고·오류·차트 의미 색은 별도로 유지한다.
- 제작할 폰트·색상은 원래 디자인을 기본으로 하고, 프리셋 제작자가 선택하면 그 값으로 구현한다. 선택값이 원본 스크린샷 지시와 충돌하면 선택값을 우선하고 비교 기준도 갱신한다. 선택 팔레트는 제작 도구에만 두며 실전 서비스에는 선택값을 바꾸는 기능을 추가하지 않는다.
- 제목·본문 서체를 나누고 한글이 없는 영문 서체에는 한글 폴백을 지정한다. 참고 사이트 서체의 상업 이용·웹 배포·재배포를 공식 출처로 확인한다. 원본 파일과 라이선스를 자체 호스팅하고 필요한 굵기만 불러온다. 견본 글자만 있는 서브셋을 일반 화면에 쓰지 않는다.

## 한국어·영어

- 모든 사이트맵 페이지에 한국어·영어를 제공한다. 초기 언어는 한국어로 두되, 제작 프롬프트에 선택값이 있으면 그 값을 따른다. 공통 언어 메뉴에는 국기와 언어 이름을 함께 표시하고, 테마는 현재 모드 아이콘을 눌러 시스템·라이트·다크를 고르는 메뉴로 제공한다. 접근성 이름과 키보드 선택을 지원한다. 고유명·사용자 입력·콘텐츠 원문은 번역할 화면 문구와 구분한다.
- 설치된 국제화 체계가 있으면 재사용한다. 서비스의 라우팅·서버 렌더링·정적 내보내기 요구에 맞춰 국제화 방식을 정한다. 화면만 프로젝트에는 같은 키를 갖는 `messages/ko`·`messages/en` 사전과 작은 조회 함수로 충분하다. 번역 문구를 컴포넌트마다 중복하지 않는다.
- 탐색·버튼·폼·오류·빈 상태·툴팁·접근성 이름을 번역하고 두 사전의 키 일치를 검사한다. DOM 문자열 치환이나 외부 번역 API로 화면을 번역하지 않는다.
- `html.lang`과 날짜·숫자·금액의 Intl 표시를 언어에 맞춘다. 언어만 바꿀 때 통화·환율·시간대와 원본 데이터는 바꾸지 않는다.
- 모드·언어를 바꿔도 현재 페이지, 입력, 선택 상태를 유지한다. 선택을 기억하되 저장이 막혀도 동작한다. 초기 깜박임과 수화 오류를 검사한다.

## 선택값 구현과 완료 검사

디자인 설정이 붙은 제작 프롬프트에서는 자동 블록의 선택값을 구현 기준으로 삼는다. 본문·제목 서체, 실제 파일·굵기·라이선스, 라이트·다크 의미 토큰, 초기 모드·언어를 `docs/preset-design.json`과 `DESIGN.md`에 기록한다. 기존 팩이나 스크린샷과 충돌하는 디자인 값은 선택값으로 갱신하며, 사용자 요청 본문은 그대로 보존한다.

개발 화면과 내보낸 HTML에서 `document.fonts` 로딩, `getComputedStyle`의 실제 서체와 토큰을 기록한 선택값과 대조한다. 본문·버튼 문구는 4.5:1 이상, 큰 글자·아이콘·조작부는 3:1 이상 대비를 검사한다. 모든 페이지의 언어·모드 전환과 폼·모달의 입력·상태 유지도 확인한다.

불일치는 고친 뒤 다시 검사하고, 결과에 검증 증거와 미확인 항목을 남긴다. `pnpm export:html`의 성공만으로 선택 디자인 적용을 판정하지 않는다. 그 명령은 정적 빌드·경로·비밀값 검사이며 선택값 대조는 실제 브라우저 검사로 증명한다. 이 기준은 선택 디자인을 고정하는 실전 서비스에도 적용하지만 프로킷 전용 팔레트·수신기는 추가하지 않는다.

## 프로킷 미리보기

프로킷 전용 팔레트는 프로킷 부모 사이트 안에만 둔다. 공식 프리셋에는 자기 서비스의 모드·언어 전환기와 프로킷 미리보기용 수신기를 둔다. 실전 서비스에는 이 수신기를 설치하거나 생성 프롬프트에 요구하지 않는다. 공식 프리셋의 설정만 iframe 내부의 의미 토큰과 번역 사전에 연결하며, 프리셋별 화면과 앱 로직을 공통화하지 않는다.

메시지 계약은 `prokit:preview:hello → prokit:preview:ready → prokit:preview:apply → prokit:preview:applied`이며 버전은 `1`이다. 모든 메시지에 프리셋 `slug`, 적용 요청에는 `requestId`를 넣는다. 지원 기능은 `font`, `palette`, `theme`, `locale`로 알린다. 옵션은 `bodyFont`, `headingFont`, `palette`, `theme(system|light|dark)`, `locale(ko|en)`다. 폰트·팔레트의 `original`은 프리셋 정본을 따른다.

부모 사이트의 실제 URL에서 확인한 정확한 origin만 허용한다. 수신 때 `event.source === window.parent`, origin, 버전, slug와 옵션 허용 목록을 확인한다. 응답 targetOrigin에도 확인한 origin을 쓰며 `*`를 쓰지 않는다. 외부에서 보낸 CSS·HTML·파일 URL을 실행하지 않는다.

`ready`에는 검증한 지원 기능만 반환한다. `applied`는 요청 식별자와 실제 적용한 옵션, `unsupported` 목록을 반환한다. 폰트·번역·토큰 적용이 끝나기 전에 성공을 회신하지 않는다. 부모도 iframe/source/origin/slug/version/requestId와 실제 옵션을 대조해야 적용 완료를 표시할 수 있다. 페이지 이동 뒤 연결을 다시 시작한다. 프리셋 헤더에서 직접 바꾼 모드·언어는 같은 버전의 `prokit:preview:settings` 알림으로 부모 설정과 동기화한다. 부모는 iframe 창·출처·프리셋과 모드·언어 허용 값을 확인한 뒤 현재 설정에 결합한다.

비동기 폰트·번역 준비와 실제 화면 적용을 분리한다. `prepareApply(options)`는 DOM을 바꾸지 않고 준비한 뒤 적용 함수를 반환한다. React 상태 적용이 비동기이면 실제 렌더가 끝날 때까지 기다린다. 적용 전과 응답 전에 요청이 최신이고 연결이 살아 있는지 확인한다. 모드 설정 함수의 참조가 바뀌어도 수신 연결을 다시 만들거나 이전 상태를 적용 결과로 반환하지 않는다. 이전 요청과 연결 종료 뒤의 준비 결과가 새 화면을 덮어쓰지 않아야 한다.

## 검증과 팩

- 모든 사이트맵 페이지를 라이트·다크·시스템과 한국어·영어로 확인한다. 시스템 테마는 운영체제 설정 변경까지 검사한다.
- 두 번역 사전 키, 작은 화면의 긴 영문, 글자 굵기·한글 폴백·대비, 입력/페이지 유지, 키보드와 접근성 이름을 검사한다.
- HTML 내보내기 후 같은 전환과 미리보기 연결을 확인한다. 잘못된 origin/source/slug/version/options와 이전 요청 응답은 거부해야 한다.
- 팩의 DESIGN.md·CUSTOMIZE.md·번역 자료·폰트 라이선스를 실제 결과에 맞춘다. 검증 전 지원이라고 선언하거나 원본 팩을 자동 재발행하지 않는다.
