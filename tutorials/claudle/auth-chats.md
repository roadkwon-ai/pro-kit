# 5장. 로그인과 대화 저장
https://prokit-web.vercel.app/tutorials/claudle/auth-chats/

## 이번 장에서 할 일

가입과 [로그인](https://prokit-web.vercel.app/tutorials/reference/glossary/#만들기)(회원이 누구인지 확인하는 기능)을 실제로 동작하게 하고, 대화와 답을 DB에 저장해요. 4장에서는 새 대화가 내 브라우저에만 남았지만, 이제 어느 브라우저로 로그인해도 내 대화가 보여요.

답은 아직 [모의 응답](https://prokit-web.vercel.app/tutorials/reference/glossary/#만들기)(미리 써 둔 답을 질문의 낱말로 골라 흘려 보내는 것)이에요. 다만 이번에는 서버가 답을 만들어 흘리고, 다 흐르면 저장해요. 실제 AI는 [7장](https://prokit-web.vercel.app/tutorials/claudle/ai-reply/)에서 붙여요.

> [!NOTE]
> 5장부터는 기능을 하나씩 만들어요. 에이전트는 4장처럼 [라운드](https://prokit-web.vercel.app/tutorials/reference/glossary/#만들기)(기능 하나를 만들거나 요청한 것을 고치고 확인까지 마치는 작업 묶음)로 일하고, 기능 하나가 라운드 하나예요. **라운드마다 끝에서 내가 직접 써 보고 확인해야 그 라운드가 닫히고, 마지막 라운드까지 닫아야 다음 장으로 갈 수 있어요.**

## 1. 프로젝트 폴더에서 에이전트 열기

4장 대화창을 그대로 써도 돼요. 대화가 길어졌거나 에이전트를 닫았다면 터미널에 입력하세요.

```bash
cd ~/projects/claudle
claude --dangerously-skip-permissions   # Codex는 codex --yolo
```

하던 일은 프로젝트에 기록돼 있어서 새로 열어도 이어 갈 수 있어요. DB는 Docker Desktop(또는 Podman)이 켜져 있어야 동작해요. 컴퓨터를 다시 켰다면 앱부터 켜 두세요.

## 2. 로그인하고 대화 저장하기

에이전트에 붙여 넣으세요.

```prompt
이제 실제로 가입하고 로그인하게 만들어줘. 로그인하면 새 대화 화면으로 가.
대화와 메시지는 프리셋 팩 features.md "대화 저장과 모의 응답"대로 사용자마다 DB에 저장해줘.
답은 아직 같은 절의 모의 응답으로 서버에서 흘리고, 다 흐르면 저장해줘. 실제 AI는 다음에 붙일 거야.
고정, 이름 바꾸기, 삭제도 다음에 할 거야. 지금은 저장, 목록, 이어 쓰기, 자동 제목까지만 해줘.
```

에이전트는 이런 순서로 일해요.

1. [프리셋 팩](https://prokit-web.vercel.app/tutorials/reference/glossary/#만들기)(만들 서비스의 화면 구성, 기능 규칙, 디자인 노트, 예시 데이터, 그림을 묶어 둔 폴더)의 규칙을 읽고, 무엇을 만들지 정리한 [스펙](https://prokit-web.vercel.app/tutorials/reference/glossary/#만들기)(기능의 범위와 동작을 적은 문서)을 보여 주며 확인을 받아요.
2. 대화와 메시지 표를 만드는 [마이그레이션](https://prokit-web.vercel.app/tutorials/reference/glossary/#만들기)(DB의 표를 만들거나 바꾸는 기록)을 만들어 내 컴퓨터의 DB에 적용해요.
3. 로그인 화면과 대화 저장, 답을 흘리는 서버 기능을 만들어요. 처음 한 번은 자동 테스트 도구를 설치하고 테스트용 DB를 따로 만들어요.
4. 두 계정을 만들어 서로의 대화를 보거나 이어 쓸 수 없는지 자동 테스트로 확인해요.
5. 리뷰를 받아요. 로그인 정보를 읽는 파일을 고치면 [보안 리뷰](https://prokit-web.vercel.app/tutorials/reference/glossary/#만들기)(전문 에이전트가 로그인과 권한에 빈틈이 없는지 보는 단계)가 저절로 붙어요.
6. 검사를 마치면 개발 서버를 켜 두고, 내가 써 볼 순서를 알려 줘요.

## 3. 직접 써 보고 확인하기

에이전트가 알려 준 주소(보통 `http://localhost:3001`)를 브라우저로 열고 가입해 보세요. 다른 계정은 사용자 메뉴에서 로그아웃한 뒤 연습용 이메일 주소(예: `test2@example.com`)로 하나 더 만들면 돼요.

**이렇게 되면 성공**
- 질문을 보내면 답이 흐르고, 새로고침해도 대화가 남아요.
- 사이드바 "이전" 맨 위에 대화가 생기고, 제목은 첫 질문의 앞부분이에요.
- 답 아래에 "모의 응답" 표시가 있어요.
- 다른 계정으로 로그인하면 내 대화가 안 보이고, 내 대화 주소로 열면 찾을 수 없다고 나와요.

괜찮으면 `확인했어`라고 보내세요. 고칠 곳이 있으면 이렇게 말하세요.

```prompt
새로고침하면 대화 제목이 첫 질문이 아니라 "새 대화"로만 나와. 고쳐줘.
```

확인하면 에이전트가 라운드를 닫고 이번 작업을 기록(커밋)해요.

## 에이전트가 물어보면

이 장부터는 프로젝트 폴더에서 연 에이전트가 기능마다 라운드 하나로 진행해요. 라운드 끝에는 늘 직접 써 보고 확인해 달라고 해요. 선택지 창이 뜨면 아래 답과 같은 선택지를 고르고, 없으면 직접 입력하는 칸에 붙여 넣으세요([질문에 답하는 법](https://prokit-web.vercel.app/tutorials/reference/claude-code-and-codex/#질문에-답하는-법)).

| 질문 | 답 |
|---|---|
| 외부 스킬의 새 판이 있다며 업데이트할지(하루에 한 번까지) | `나중에`. `지금 업데이트`를 고르면 업데이트 라운드를 먼저 따로 열어 확인과 커밋까지 마친 뒤 이 장으로 돌아와요. 장을 마친 뒤 `스킬 업데이트해줘`라고 보내면 그때 따로 해요 |
| 스펙을 정하기 전에 고를 것 | 모르겠으면 `추천대로 해줘` |
| 스펙을 확인해 달라 | 읽어 보고 `좋아, 진행해줘` 또는 고칠 곳 |
| 계획을 확인하고 구현 방식을 골라 달라 | `추천대로 해줘` |
| 보안 리뷰에서 나온 지적을 어떻게 할지 | `추천대로 해줘` |
| 직접 써 보고 확인해 달라 | 알려 준 순서대로 써 본 뒤 `확인했어` 또는 고칠 곳 |

화면을 고치는 라운드에서는 [4장 표](https://prokit-web.vercel.app/tutorials/claudle/screens/#에이전트가-물어보면)의 디자인 점수 질문도 나올 수 있어요.
