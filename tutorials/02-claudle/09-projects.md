# 9장. 프로젝트

## 이번 장에서 할 일

프로젝트를 실제로 저장해요. 프로젝트에는 지침(답할 때 늘 따를 말)과 지식 파일(참고할 글)을 둘 수 있고, **그 프로젝트 안의 대화는 지침과 파일을 보고 답해요.** 4장의 예시 프로젝트 대신 내가 만든 프로젝트가 나와요.

## 1. 프로젝트 저장하기

8장의 확인을 마친 에이전트에 보내요.

```prompt
프로젝트를 프리셋 팩 features.md "프로젝트"대로 실제로 저장되게 해줘. 지침과 텍스트 지식 파일, 개수와 길이 제한도 같은 절대로.
프로젝트 안의 대화는 지침과 파일을 붙여서 답하게 해줘.
프로젝트를 지우면 안의 대화도 함께 지워줘.
```

에이전트는 이런 순서로 일해요.

1. [스펙](../reference/glossary.md#만들기)(<!-- v:gloss.spec -->기능의 범위와 동작을 적은 문서<!-- /v -->)을 보여 주며 확인을 받아요.
2. 프로젝트와 지식 파일 표를 만드는 [마이그레이션](../reference/glossary.md#만들기)(<!-- v:gloss.migration -->DB의 표를 만들거나 바꾸는 기록<!-- /v -->)을 적용해요.
3. 프로젝트 목록과 상세, 지침 편집, 파일 추가를 서버 기능과 이어요.
4. 대화를 보낼 때 그 프로젝트의 지침과 파일을 [시스템 지침](../reference/glossary.md#만들기)(AI에게 늘 함께 보내는 지시문)에 붙여요. 다른 계정의 프로젝트에 대화를 넣을 수 없는지 자동 테스트로 확인해요.
5. 리뷰를 마치면 개발 서버를 켜 두고 확인을 요청해요.

**이렇게 되면 성공**
- 프로젝트를 만들고 지침을 저장하면 새로고침해도 남아요.
- 프로젝트가 5개일 때 6번째를 만들면 더 만들 수 없다는 안내가 나와요.
- 지침에 "답은 세 줄로"라고 적으면, 그 프로젝트 대화의 답이 지침을 따라요. 키 없이 모의 응답일 때는 지침이 붙는 것만 확인하면 돼요.

괜찮으면 `확인했어`라고 보내세요.

<details>
<summary>막히면</summary>

- **지침이 답에 반영되지 않아요**: 키가 없으면 모의 응답이라 지침을 따르지 않아요. 키가 있는데도 그러면 `프로젝트 대화에서 지침과 파일이 시스템 지침에 붙는지 확인해줘`라고 보내세요.
- **큰 파일을 올리니 오류가 나요**: 지식 파일은 텍스트만, 크기 제한이 있어요. `파일이 크면 무엇을 줄여야 하는지 안내하게 해줘`라고 보내세요.
- **프리셋 팩을 못 찾거나, 앞 장 작업을 이어서 하려 하거나, 중간에 멈췄어요**: [5장의 막히면](05-auth-chats.md#3-직접-써-보고-확인하기)과 같아요.
- 그 밖의 문제는 [막혔을 때](../reference/troubleshooting.md)를 보세요.

</details>

## 에이전트가 물어보면

5장처럼 [라운드](../reference/glossary.md#만들기)(기능 하나를 만들거나 요청한 것을 고치고 확인까지 마치는 작업 묶음) 하나로 진행되고, 끝에 직접 써 보고 확인해 달라고 해요. [4장](04-screens.md#에이전트가-물어보면)과 [5장](05-auth-chats.md#에이전트가-물어보면) 표의 질문(디자인 점수, 스킬 업데이트 등)도 나올 수 있어요. 선택지 창에서 답하는 법은 [질문에 답하는 법](../reference/claude-code-and-codex.md#질문에-답하는-법)에 있어요.
<!-- /b -->

| 질문 | 답 |
|---|---|
| 지식 파일로 PDF나 그림도 받을지 | `텍스트 파일만 받아줘` |
| 스펙을 확인해 달라 | 읽어 보고 `좋아, 진행해줘` 또는 고칠 곳 |
| 직접 써 보고 확인해 달라 | 프로젝트를 하나 만들어 대화해 본 뒤 `확인했어` 또는 고칠 곳 |
