# 스피커 포트폴리오
https://prokit-web.vercel.app/tutorials/samples/speaker-portfolio/

강연자·작가·크리에이터의 소개와 활동을 담는 홈·클래스·결제 체험·정책 샘플 프리셋이에요. 가상 인물 서윤의 활동·책·과정과 가상 영상 썸네일을 살펴볼 수 있어요. 외부 주소는 비어 있는 예시예요. 문의와 신청은 내용을 작성해 복사하는 데모예요. 프리미엄 팩으로 제공하며, 아래 안내에서 다운로드하고 복원할 수 있어요.

| 항목 | 내용 |
|---|---|
| 페이지 | 6개, 홈·클래스·결제 체험·정책 샘플을 제공해요 |
| 디자인 참고 | [yjkim.kr](https://yjkim.kr/)과 [클래스 페이지](https://class.yjkim.kr/)의 구성·서체·자산 배치·모션을 참고해요. 인물·책·영상·과정은 가상 예시로 제공해요 |
| 대표 색 | 화이트·잉크·코랄, 강조색은 `#ff4b35`예요 |
| 서체 | Pretendard Variable을 자체 호스팅하며 OFL 이용 조건을 팩에 포함해요 |
| 생성 이미지 | 18개, 사진·책 표지·가상 영상 썸네일을 사용해요 |
| 설정 | 국기 언어 메뉴와 테마 버튼 하나의 시스템·라이트·다크 메뉴를 제공해요 |
| 검사 상태 | 지적 사항 수정 뒤 여섯 정적 경로의 독립 검수와 별도 환경 복원·빌드·화면 비교를 확인했어요. 실결제·운영 DB·배포는 포함하지 않아요 |

## 프리셋 팩으로 만들어 보기

작업 폴더 `~/projects`에서 연 에이전트에 이 프롬프트를 보내면 스피커 포트폴리오 프리셋과 같은 서비스를 만들어요. [프리셋 팩](https://github.com/roadkwon-ai/pro-kit-premium-packs/releases/tag/pack-speaker-portfolio)의 화면 구성, 디자인, 예시 데이터, 그림을 그대로 써서 AI 그림을 새로 그리지 않아요. `[ ]` 안의 이름을 바꿔 같은 구성의 서비스를 만들어요. 팩을 써도 AI가 만들기 때문에 100% 똑같지는 않을 수 있어요.

```prompt
https://github.com/roadkwon-ai/pro-kit 을 이 폴더에 받고, 그 안의 AGENTS.md대로 화면만 만들 프로젝트를 pro-kit 옆에 [speaker-portfolio] 폴더로 만들어줘.
DB는 쓰지 않아. 없는 준비물은 설치해줘.
옆 폴더 pro-kit의 packs/speaker-portfolio에 프리셋 팩을 받아줘.
그 팩대로 스피커 포트폴리오 프리셋과 똑같은 서비스를 만들 거야. 이름은 [스피커 포트폴리오].
팩의 README.md 순서대로 하고, 팩은 고치지 마. 이름을 바꿨으면 팩의 이름 대신 내가 정한 이름을 써.
디자인, 화면 구성, 그림은 팩에 있는 것을 써. 스타일 추천, 시안, 새 그림은 만들지 마.
모든 페이지의 기본 디자인은 팩의 스크린샷과 같게 만들어줘.
시스템·라이트·다크 모드 전환과 한국어·영어 전환을 모든 페이지의 기본 기능으로 넣어줘. 화면 문구는 같은 키를 가진 두 언어의 번역 사전에서 관리하고, 전환해도 현재 페이지와 입력을 유지해줘. 개발 화면과 HTML로 내보낸 결과에서 모든 페이지의 전환과 상태 유지를 실제로 확인해줘.
다 만들면 HTML 파일로 내보내줘.
```

> [!IMPORTANT]
> **프롬프트만 보내면 에이전트가 이 프리셋 팩을 자동으로 받아 설치해요. 따로 받지 않아도 돼요.**
>
> 직접 받으려면 [speaker-portfolio-pack.zip](https://github.com/roadkwon-ai/pro-kit-premium-packs/releases/download/pack-speaker-portfolio/speaker-portfolio-pack.zip)(11.2MB, [릴리스](https://github.com/roadkwon-ai/pro-kit-premium-packs/releases/tag/pack-speaker-portfolio))을 받고, 프롬프트 끝에 `프리셋 팩 zip은 [~/Downloads/speaker-portfolio-pack.zip]에 받아 뒀어.` 한 줄을 더하세요. 에이전트가 그 zip이 최신 판인지 확인하고, 옛 판이면 새로 받아요.

### 직접 받은 ZIP으로 자세히 복원하기

ZIP을 미리 받았다면 아래 절차로 파일을 검증하고 복원해요.

pro-kit의 `tutorials/packs.json`에 등록된 판과 같은 ZIP을 받은 뒤 pro-kit 폴더의 터미널에 입력해요. `[팩 ZIP 경로]`는 실제 파일 경로로 바꿔요.

```bash
node scripts/pack.mjs speaker-portfolio --zip "[팩 ZIP 경로]"
```

이 명령은 등록된 SHA-256을 대조해 `packs/speaker-portfolio/`에 풀어요. 파일이 없거나 해시가 다르면 다운로드한 파일과 등록 정보를 확인해요.

팩이 준비되면 작업 폴더에서 연 에이전트에 아래 프롬프트를 보내요. [처음부터 만들기](https://prokit-web.vercel.app/tutorials/samples/speaker-portfolio/#이-컨셉으로-처음부터-만들기)의 프로젝트 생성 절차처럼 에이전트가 템플릿 초기 구성을 먼저 처리해요. `[ ]` 안은 원하는 폴더와 서비스 이름으로 바꿔요.

```prompt
pro-kit의 AGENTS.md대로 pro-kit 옆 [speaker-portfolio] 폴더에 새 화면만 프로젝트를 만들어줘.
검증해 풀어 둔 pro-kit/packs/speaker-portfolio의 README와 manifest를 읽고 prokit-pack-use로 복원해줘. 이름은 [스피커 포트폴리오].
apply-pack.mjs --check로 충돌을 확인한 뒤 실제 적용하고, 환경·하네스를 보존한 채 설치·타입·빌드·실행을 확인해줘.
DB는 쓰지 않아. 없는 준비물은 설치해줘.
팩은 고치지 말고 소스, 디자인, 그림, 폰트와 이용 조건을 재사용해줘. 스타일 추천이나 새 그림은 필요 없어.
홈 문의와 클래스 신청은 입력 검사·내용 복사 데모로 유지해줘. 실제 전송·결제·DB 저장은 하지 마.
한국어·영어와 시스템·라이트·다크 전환 후에도 입력 내용과 현재 위치를 유지해줘.
전체 화면과 정적 출력의 메뉴·외부 판매 링크·영상 썸네일·스크롤 모션·문의·신청을 확인하고 manifest의 화면 기준과 비교해줘.
다 만들면 HTML 파일로 내보내줘.
```

팩에는 환경값·환경 schema·하네스·제작 스킬이 들어 있지 않아요. 템플릿으로 초기 구성한 프로젝트의 로컬 설정을 보존하고, 필요한 환경 선언은 실제 소스와 대조해 별도로 확인해요. 받기 성공과 프로젝트 복원 완료는 달라요.

**이렇게 되면 성공**

- 홈과 클래스에 직접 접근하고 새로고침·왕복할 수 있어요.
- 설정 메뉴를 닫으면 열었던 버튼으로 초점이 돌아와요.
- 국기 언어 메뉴·테마 단일 메뉴·이미지·스크롤 효과가 완성 프리셋과 같은 조건에서 유지돼요.
- 문의 내용이 복사되고 실제 발송으로 오해할 안내가 나오지 않아요.

<details>

- **복사가 안 돼요**: 화면에 나온 문의 내용을 직접 선택해 복사해요.

## 프리셋 팩으로 나만의 서비스 만들기

복원한 프로젝트에서 이름·역할·소개·활동 주제부터 바꿔요. 팩의 `CUSTOMIZE.md`는 바꿀 항목과 다시 확인할 동작을 안내해요.

```prompt
복원한 스피커 포트폴리오를 [내 이름]의 소개 사이트로 바꿔줘.
주제는 [내 전문 분야]이고 소개할 활동은 [강연·책·콘텐츠]야.
팩의 CUSTOMIZE.md를 보고 바꾸는 부분만 수정해줘. 원본 팩은 고치지 마.
사진은 내가 제공한 사용 가능한 사진으로 교체하고, 확인되지 않은 이력이나 성과는 추가하지 마.
전체 화면·두 언어의 문구와 모바일 배치를 맞추고 문의·신청은 내용 복사 방식으로 유지해줘.
나머지 이미지·서체·모션·설정 메뉴는 유지하고 완성 프리셋과 비교해줘.
```

새 사진이 필요하면 [이미지 그리기 안내](https://prokit-web.vercel.app/tutorials/reference/costs-and-keys/#이미지-그리기)를 확인해요. 사진을 바꿀 때 비율·크롭·대체 설명도 맞춰요. 소셜·영상·책 판매 주소는 비어 있어요. 확인된 본인 계정·영상·판매 주소를 등록하면 직접 외부 링크로 연결해요.

주소는 `apps/web/src/lib/portfolio-content.ts`의 `portfolioUrls` 한 곳에서 바꿔요. `socials`에는 YouTube·Instagram·Threads·LinkedIn의 이름별 키가 있어요. `books`의 네 칸과 `videos`의 여섯 칸은 화면에 표시된 제목·이미지 순서대로 채우며, 정확한 대응은 팩의 `CUSTOMIZE.md`에서 확인해요. 두 언어가 같은 주소를 읽으므로 번역 사전이나 `map` 안에 따로 넣지 않아요. 연결하지 않을 칸은 빈 문자열로 두어요.

푸터의 상호·대표자·등록번호·주소·연락처·저작권은 같은 파일의 `portfolioBusiness`에서 바꿔요. 가상 예시를 확인한 본인 정보로 교체하고, `ko`·`en` 값이 있는 항목은 두 언어를 함께 맞춰요. 홈·클래스·결제·정책 화면이 같은 설정을 읽으며, 각 항목의 정확한 키와 확인 순서는 팩의 `CUSTOMIZE.md`에 있어요.

## 이 컨셉으로 처음부터 만들기

작업 폴더 `~/projects`에서 연 에이전트에 이 프롬프트를 그대로 보내면 **바로** 시작돼요. [가장 쉬운 방법](https://prokit-web.vercel.app/tutorials/samples/#가장-쉬운-방법)의 프롬프트와 같고, `[ ]` 안만 이 프리셋의 폴더 이름과 컨셉이에요. 원하는 대로 바꿔도 돼요.

```prompt
https://github.com/roadkwon-ai/pro-kit 을 이 폴더에 받고, 그 안의 AGENTS.md대로 화면만 만들 프로젝트를 pro-kit 옆에 [speaker-portfolio] 폴더로 만들어줘.
DB는 쓰지 않아. 없는 준비물은 설치해줘.
[강연자·작가·크리에이터의 소개와 클래스 과정을 읽고 문의·신청 내용을 복사하는 사이트]를 만들고 싶어.
필요한 화면을 모두 예시 데이터로 만들어줘. 로그인이나 저장 같은 기능은 빼고 화면만 만들어.
시스템·라이트·다크 모드 전환과 한국어·영어 전환을 모든 페이지의 기본 기능으로 넣어줘. 화면 문구는 같은 키를 가진 두 언어의 번역 사전에서 관리하고, 전환해도 현재 페이지와 입력을 유지해줘. 개발 화면과 HTML로 내보낸 결과에서 모든 페이지의 전환과 상태 유지를 실제로 확인해줘.
디자인 스타일은 서비스에 어울리는 걸로 추천해주고, 다 만들면 HTML 파일로 내보내줘.
```

**같은 컨셉이라도 이름, 스타일, 화면은 매번 다르게 나와요.** 프리셋에 가깝게 만들려면 [프리셋 팩으로 만들어 보기](https://prokit-web.vercel.app/tutorials/samples/speaker-portfolio/#프리셋-팩으로-만들어-보기)를 쓰세요.

에이전트를 아직 열지 않았으면 [1. 작업 폴더에서 에이전트 열기](https://prokit-web.vercel.app/tutorials/samples/#1-작업-폴더에서-에이전트-열기)부터 하세요. 프롬프트를 보낸 다음에는 [3. 알려 준 한 줄로 이어 가기](https://prokit-web.vercel.app/tutorials/samples/#3-알려-준-한-줄로-이어-가기)와 [4. 답하며 요청을 자세히 채우기](https://prokit-web.vercel.app/tutorials/samples/#4-답하며-요청을-자세히-채우기)를 따라가면 돼요.

## 실제 서비스로 만들 때

예시 이름·이력·책·과정·가격을 확인된 본인 자료로 바꿔요. 실제 문의를 받으려면 수신 방법과 개인정보 처리 범위를 정하고 `prokit-api`·`prokit-db` 등 프로젝트 스킬로 서버 기능을 연결해요. 연락처 입력과 과정 선택이 있다는 이유로 전송·결제가 연결된 것으로 판단하지 않아요.

```prompt
복원한 프로젝트에서 [필요한 실전 기능]을 연결해줘.
먼저 데이터·수신 방법·권한·개인정보 처리 범위를 확인하고 프로젝트 기술 스킬을 따라 구현해줘.
완성팩의 배치·서체·이미지·모션·설정 메뉴를 유지해줘.
로딩·빈 목록·오류·긴 내용·권한 없음 상태와 원래 화면을 함께 검사해줘.
실행한 검사와 미확인 항목을 나눠 보고해줘.
```

복원 검사와 실전 기능 검사는 별개예요. 등록한 영상·판매·소셜 링크의 이동은 실제 운영 환경에서도 확인해요. 기본값이 비어 있으면 활성 링크나 재생 버튼처럼 보이지 않아야 해요.

## 시간과 비용

프리셋 팩으로 다시 만들 때는 한 번에 완성하면 약 1시간\~2시간(여러 번 고쳐 달라고 하면 약 3시간까지)이고, 토큰은 최소 약 122.4만(캐시 포함 약 6118.8만)으로 예상해요. 처음부터 화면을 만들 때는 한 번에 완성하면 약 1시간 36분\~3시간 10분(여러 번 고쳐 달라고 하면 약 4시간 50분까지)과 최소 약 226.4만 토큰으로 예상해요.

시간은 공통 단계별 계획의 합이고, 토큰은 같은 정책의 기준 단위에서 환산한 예상값이에요. 검사 예상은 이 프리셋의 화면 범위를 기준으로 정했어요. [예상 계산 근거](https://github.com/roadkwon-ai/pro-kit/blob/main/docs/reports/2026-10-13-preset-measurements.json)를 확인해요.

실제 제작 기록이나 현재 제공자의 청구 요금을 뜻하지 않으며, API·DB·실결제 개발은 포함하지 않았어요. 고쳐 달라는 횟수와 사용하는 모델에 따라 늘어날 수 있어요. [시간과 비용 읽는 법](https://prokit-web.vercel.app/tutorials/reference/costs-and-keys/#시간과-비용-읽는-법)을 참고해요.

기존 제작·보완 이력의 활성 작업 합계는 10시간 56분이고 루트 토큰은 캐시 제외 약 380만(캐시 포함 약 2.1억)이에요. 관련 스킬 개선도 포함하며 사용자 대기와 별도 자식 에이전트·이미지 생성 사용량은 제외한 기록이에요. 순수 제품만의 전체 비용으로 읽으면 안 돼요.

설치·빌드 등 짧은 명령 네 개의 합을 제작 시간으로 표시했던 값을 이 기록과 분리했어요.

디자인 평가는 닐슨의 열 가지 기준으로 29점이며, [기준별 점수와 감점 이유](https://prokit.highvalue.kr/process/?preset=speaker-portfolio#step-5)를 함께 확인해요.

## 결제 체험과 정책 화면

클래스에서 세 과정 중 하나를 골라 `/class/checkout/`로 이동해요. 로컬 카드 체험은 실제 결제나 수강 계약이 아니에요. `/class/terms/`, `/class/refund/`, `/class/privacy/`는 화면용 정책 샘플이며 운영자의 실정책으로 사용하지 않아요.

이전 두 페이지 범위의 검사 횟수·캡처·팩 기록은 보존하되 새 여섯 화면의 합격으로 합치지 않아요. 새 범위의 정적 경로·독립 검수와 별도 환경 설치·타입·단위 검사·빌드를 확인했어요. 한국어·라이트에서 여섯 경로를 두 화면 크기로 비교해 지정한 배치·서체·줄 수의 차이와 가로 넘침이 없었어요. 네이티브 기타 카드 목록의 키보드 탐색 전체, 실기기·Safari와 실결제는 확인하지 않았어요.
