# 6장. 검사하고 다듬기

## 이번 장에서 할 일

에이전트가 만든 화면을 스스로 검사하고 고쳐요. 마지막으로 내가 직접 둘러보고 마음에 안 드는 곳을 말해요.

## 1. 에이전트가 하는 검사

화면을 다 만들면 에이전트가 알아서 아래 검사를 하고 결과를 보고해요.

| 검사 | 하는 일 |
|---|---|
| 링크와 버튼 | 모든 페이지의 링크와 버튼을 눌러 없는 페이지(404)나 반응 없는 버튼이 없는지 봐요 |
| 디자인 리뷰 | 쓰기 편한지 점수를 매기고 큰 문제(P0, P1)를 찾아요 |
| 접근성 검사 | 글자 대비, 키보드 이동, 화면 읽기 프로그램을 확인해요 |
| 다듬기 | 찾은 문제를 한 번에 고치고 다시 확인해요 |

검사를 다시 하고 싶으면 이렇게 보내세요.

```prompt
지금까지 만든 거 검증해줘
```

```prompt
디자인 리뷰해서 큰 문제부터 고쳐줘
```

## 2. 직접 둘러보고 고치기

개발 서버를 켜고 모든 페이지를 눌러 보세요. 마음에 안 드는 곳은 "어디가 어떻게"를 적어 보내면 돼요.

```prompt
홈의 금액 글자는 더 크게, 그 아래 설명은 더 연하게 해줘.
```

```prompt
휴대폰에서 지출 목록이 너무 빽빽해. 줄 사이를 넓혀줘.
```

스타일, 이름, 사진을 바꾸는 프롬프트는 [다듬기](refine.md)에 모아 두었어요.

**이렇게 되면 성공**
- 보고에 없는 페이지(404) 0, 반응 없는 버튼 0이 나와요.
- 디자인 리뷰의 큰 문제(P0, P1)가 모두 고쳐졌거나 이유가 적혀 있어요.

<details>
<summary>막히면</summary>

- **기준에 못 미친다며 어떻게 할지 물어요**: `한 번 더 다듬어줘`라고 하거나, 괜찮으면 `이대로 둬`라고 답하세요.
- **결과를 직접 보고 확인해 달래요**: 화면을 둘러본 뒤 `확인했어`라고 답하세요. 고칠 곳이 있으면 함께 적으세요.

</details>

## 에이전트가 물어보면

| 질문 | 답 |
|---|---|
| 점수가 기준에 못 미칠 때 더 다듬을지 | `한 번 더 다듬어줘` 또는 `이대로 둬` |
| 결과를 직접 보고 확인했는지 | 둘러본 뒤 `확인했어` |
