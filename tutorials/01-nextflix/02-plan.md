# 2장. 서비스 기획

## 이번 장에서 할 일

<!-- b:clone-plan-intro -->
[프리셋 팩](../reference/glossary.md#만들기)(만들 서비스의 화면 구성, 기능 규칙, 디자인 노트, 예시 데이터, 그림을 묶어 둔 폴더)을 에이전트에게 읽혀 서비스의 기획 문서를 채워요. 서비스 소개는 [`PRODUCT.md`](../reference/glossary.md#디자인), 서비스에서 쓰는 말은 `GLOSSARY.md`, 모든 페이지 목록은 사이트맵에 들어가요. 이 문서가 앞으로 모든 화면과 기능의 기준이 돼요.
<!-- /b -->

## 1. 프리셋 팩으로 기획 채우기

<!-- b:clone-plan-start name=nextflix neun=는 -->
**여기서부터는 1장에서 새 프로젝트 폴더(`~/projects/nextflix`)에 연 에이전트에 보내요.** `[Nextflix]`는 서비스 이름이에요. 마음에 드는 이름으로 바꿔도 돼요.
<!-- /b -->

```prompt
넷플릭스 같은 영상 구독 서비스를 만들 거야. 이름은 [Nextflix].
옆 폴더 pro-kit의 packs/nextflix에 있는 screens.md와 features.md를 읽고(없으면 pro-kit 폴더에서 node scripts/pack.mjs nextflix로 받아서) 서비스 소개, 용어, 사이트맵을 채워줘.
팩은 고치지 말고, 팩 데이터의 서비스 이름은 내가 정한 이름으로 바꿔 써.
디자인 스타일은 다음에 프리셋 팩대로 정할 거라 지금은 후보를 찾지 마.
```

<!-- b:clone-plan-reads -->
에이전트는 프리셋 팩의 화면 구성(`screens.md`)과 기능 규칙(`features.md`)을 읽어요. 문서는 바로 쓰지 않고 서비스 질문과 첫 화면 문구 후보, 사이트맵과 페이지별 설계 메모([브리프](../reference/glossary.md#디자인))를 한 번에 보내요. 디자인은 3장에서 프리셋 팩대로 정하니 지금은 스타일을 찾지 않아요.
<!-- /b -->

> [!TIP]
> 이름을 바꾸려면 이 장 프롬프트의 `[Nextflix]` 한 곳만 고치면 돼요. 8·9장 프롬프트의 `[Nextflix]`도 같은 이름으로 바꿔요.
>
> 팩 파일은 고치지 않아요. 에이전트가 팩의 이름 대신 내가 정한 이름을 화면, 제목, 문서에 써요.

## 2. 질문에 답하고 확정하기

<!-- b:clone-plan-confirm -->
서비스 질문의 답은 대부분 프리셋 팩에 있어요. 아래 프롬프트 하나로 질문에 답하고, 사이트맵을 확인해 확정해요. 선택지 창이 뜨면 직접 입력하는 칸을 고르고 붙여 넣으세요([질문에 답하는 법](../reference/claude-code-and-codex.md#질문에-답하는-법)).

```prompt
질문의 답은 프리셋 팩에서 채우고, 없는 건 추천대로 해줘.
사이트맵이 screens.md와 같은지 확인하고, 빠진 화면이 없으면 사이트맵과 브리프는 이대로 확정해줘.
```
<!-- /b -->

프리셋 팩의 화면은 랜딩, 로그인, 가입·요금제, 프로필 고르기, 프로필 관리, 홈, 시리즈, 영화, 요즘 대세, 나의 Nextflix, 검색, 상세 창, 작품 쪽, 재생, 계정이에요. "나의 Nextflix"에는 내가 정한 이름이 들어가요. 사이트맵(`docs/briefs/site-map.md`)을 직접 보고 싶으면 `사이트맵을 표로 보여줘`라고 보내세요.

**이렇게 되면 성공**
- `PRODUCT.md`에 서비스 소개가 생겨요.
- `GLOSSARY.md`에 프로필, 찜, 이어 보기 같은 말이 생겨요.
- 에이전트가 사이트맵에 프리셋 팩의 화면이 모두 들어 있다고 알려 주고, 사이트맵과 브리프를 확정했다고 해요.

<details>
<summary>막히면</summary>

- **프리셋 팩을 못 찾는대요**: `~/projects` 안에 `pro-kit`과 `nextflix`가 나란히 있는지 보세요. 있으면 `프리셋 팩은 옆 폴더 pro-kit의 packs/nextflix에 있어. 없으면 pro-kit 폴더에서 node scripts/pack.mjs nextflix 명령으로 받아줘`라고 보내세요. pro-kit 폴더가 2026-10-08 전에 받은 것이라 팩 받기가 멈추면 `그 폴더 이름을 pro-kit-old로 바꾸고 새로 받아줘`라고 보내세요.
- **에이전트가 질문 없이 바로 화면을 만들어요**: `먼저 기획만 해줘. 화면은 디자인을 정한 뒤에 만들어`라고 보내세요.
- **디자인 스타일 후보를 찾기 시작했어요**: `디자인은 3장에서 프리셋 팩대로 정할 거야. 후보 찾기는 멈춰줘`라고 보내세요.
- **문서에 Nextflix가 남았어요(이름을 바꿨을 때)**: `팩은 고치지 말고, 프로젝트 문서에 남은 팩의 서비스 이름을 내가 정한 이름으로 바꿔줘`라고 보내세요.
- **사이트맵에 화면이 빠졌대요**: `사이트맵에 계정 쪽을 더하고 확정해줘`처럼 빠진 화면을 말하세요.
- **답을 잘못 보냈어요**: `PRODUCT.md에서 쓰는 사람 부분을 고쳐줘`처럼 고칠 곳을 말하세요.

</details>

## 에이전트가 물어보면

| 질문 | 답 |
|---|---|
| 누가 쓰는지, 무엇이 좋아지는지(서비스 질문) | 2단계 프롬프트로 한 번에 답해요 |
| 첫 화면 문구 후보 | 2단계 프롬프트가 추천대로 정해요. 따로 물으면 마음에 드는 번호나 `추천대로 해줘` |
| 서비스 이름 후보 | `이름은 내가 정한 대로 둘게` |
| 디자인 스타일을 고를지 | `3장에서 프리셋 팩대로 정할게` |
| 사이트맵과 브리프를 확인해 달라 | 2단계 프롬프트로 확정해요. 빠진 화면이 있으면 그 화면을 말하기 |
| 결과를 확인해 달라 | 문서를 훑어보고 `확인했어` |
